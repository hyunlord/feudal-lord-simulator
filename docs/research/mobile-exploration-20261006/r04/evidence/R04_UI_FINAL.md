# R04 UI 후속 구현과 실제 브라우저 검수

이 기록은 R04_FIRST_PLAY.md의 독립 첫 플레이 이후 수행한 구현·회귀 확인이다. 새 블라인드 평가나 사람 사용자 시험이 아니다. 첫 플레이의 재미 판정은 바꾸지 않았다.

## 변경 범위

- `prototype/ui/contract-copy.ts`: 계약 사건명, 영수증 이유와 화면 상태의 계약 응답을 한국어로 변환한다. 합의 예상 이익, 위반 보증금·배상금은 원본 값을 보존한다.
- `prototype/ui/encounters.ts`: 위 표시 변환을 실제 계약 영수증에 적용했다.
- `prototype/ui/app.ts`: 상태 메시지 표시 변환 및 무료 지도 색감 기본/저녁 토글. 비교 화면에는 색감을 적용하지 않는다.
- `prototype/style.css`: 지도에만 `sepia(.25) brightness(.85)`를 적용한다. 텍스트와 버튼은 기존 토큰을 유지한다.
- 모델·리그·계약 규칙 변경 없음, 새 의존성 없음. 기존 번역 규칙은 작은 표시 모듈로 모았다. 실제 이동 경로 없는 주민 이동 장식은 만들지 않았다.

## 검증 결과

`../../node_modules/.bin/tsc -p tsconfig.json` 최종 exit0. 동시 작업 중 최초 컴파일은 미완성 league/analysis 관련 오류로 실패했으나 파일 완성 후 같은 명령이 통과했다. 계약 문구 함수 직접 검증6개도 통과했다.

실제 설치 Chrome을 Playwright로 실행했다. 375×693,390×693,768×693,1280×693 각각 다음 흐름을 실제 버튼으로 수행했다.

1. 교역50/해상50 적용 →12일 성장→건축 이유 펼치기.
2. 이웃→북쪽 한정 약탈→경로와 노출 기록. 식량12 운반, 출정6명, 공격손실0/방어손실2.
3. 기록 저장→지도 색감 변경→재저장→새로고침→기록 이어하기→재저장.
4. 교역 조건을 못 찾는 경우의 한국어 메시지 확인.
5. 이름 가린 세 영지 비교를144일까지 기다려 확인.

각 화면 체크포인트에서 `document.scrollWidth === innerWidth`, 네 너비 모두 console error0/pageerror0. 768·1280에서는 세 패널 y좌표가 같아3열 배치 확인. 모바일은1열 스크롤. 시설 tooltip에서 농업/제작/군사 축 이름이 나오지 않는 것도 확인했다.

별도 농업48일 실행에서 교역 제안→합의(상대 예상 이익9.748)→50일 교환 완료를 실제 조작했다. 영수증과 상태 문구가 한국어로 보였다. 정책 총200 입력은 적용을 거절하고 이유를 표시했다. 키보드 왼쪽 화살표로 농업100→99 변경 가능했다. reduced-motion 설정에서도 조작했다.

## 외형이 결과를 바꾸지 않는 범위의 증거

- 같은 세션에서 색감 토글 전후 저장 JSON 문자열 전체 동일. 따라서 명령 목록·입력 hash·결과 hash 동일.
- 전투 DOM의 전체 내용도 동일(접힌 details의 표시 상태는 비교에서 제외하고 textContent를 비교).
- 새로고침과 기록 재현 후 저장 문자열 및 전투 내용 동일.
- 별도의 새 세션 두 개에서 처음부터 기본/저녁을 각각 선택하고 같은 정책·12일·전투 명령을 실행했다. 최종 저장 문자열 전체 동일.
- 저녁 색감이 켜진 상태에서 비교 진입 시 `.city-map`의 computed filter는 `none`.

이는 무료 시제품 색감 토글의 비인과성 검증이다. 구매·유료 외형·서버 결제 구현을 검증하거나 과금 의사를 측정한 것이 아니다. 색감은 새로고침 후 기본값으로 돌아가며 게임 기록에 저장하지 않는다.

## 시각 확인

직접 이미지 확인: policy-375/390, growth-reason-390, battle-375, compare-768/1280, cosmetic-evening-390, contract-receipts-390, compare-1280x1100, policy-budget-error-390. 기준은 첫 플레이 캡처와 DESIGN.md. 기존 종이색·풀빛·녹색 주행동을 유지하고 한글 잘림이나 가로 넘침은 확인되지 않았다. 세 도시 차이는 넓게 퍼진 농지, 길 주변 작업장, 북쪽 길을 따라 선 군사시설로 보인다.

최종 비교 캡처는 실제 viewport1280×1100에서 세 도시·재고·하단 조작을 한 번에 읽을 수 있도록 추가했다. 693높이 전체 페이지 캡처에서는 sticky 내비가 캡처 중간에 나타날 수 있으며 실제 화면은 스크롤로 아래 항목에 접근한다.

- 판정: PASS94/100, 직접 수행한 범위의 시각 회귀 판정.
- 상태: `.omx/state/r04-ui-final/ralph-progress.json`.
- 전체 증거: `records/r04-ui-final/verification.json`, `additional.json`, `layout.json`.
- 대표 이미지: `records/r04-ui-final/compare-1280x1100.png`, `contract-receipts-390.png`, `battle-375.png`, `cosmetic-evening-390.png`.
- 재현 스크립트: 동일 폴더의 `verify.mjs`, `additional.mjs`, `layout.mjs`. 기존 설치 Playwright 경로를 사용한다.

## 남은 경계

Lighthouse, 사람 첫 사용성, 실제 휴대폰/Safari, 전체200% 브라우저 확대는 검증하지 않았다. root font-size200% 설정은 px 기반 본문 확대를 증명하지 않으므로 확대 접근성 통과로 계산하지 않았다. Bun 실행기가 없어 스킬 bundled pixel-diff는 실행하지 못했다. 상위의 재귀 위임 금지에 따라 별도 시각검수 에이전트는 생성하지 않았다. 향후 모델이 새로운 영문 사건·이유 코드를 추가하면 표시 사전을 함께 갱신해야 한다.
