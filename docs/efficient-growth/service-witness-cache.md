# 공동 서비스 공간 증명의 재사용

**실측 원인.** 실제 기본 도시 실행을 277,920틱에 중단해 보존한 상태에서 곡창 운송 후보 검사가 첫 호출 2,696.8ms, 반복 호출 2,365.1ms였다. 전체 조언자도 2,330.3/2,352.3ms였다. 모두 결과는 `none`이다. 배송 후보의 여러 가상 도로마다 공동 서비스 계획을 다시 푸는 비용이 컸다. 별도 관련 상태의 CPU 표본에서도 서비스 공동 계획이 후보 검사 표본의 약77%를 차지했다. 단순 재고·인구 변경은 구조 캐시를 무효화하지 않았으며, 이를 원인으로 설명하지 않는다.

**수정.** 공동 계획은 참/거짓뿐 아니라 선택한 시설 점유와 실제로 확인한 자재·서비스 연결 경로를 반환한다. 주택·시설 배분이 같고 변경이 증명에 필요한 점유·경로를 훼손하지 않으면 이 증명을 이어 쓴다. 도로 추가는 필요한 경로를 끊지 않지만 시설 자리 위에 놓는 도로는 재검사한다. 주택·시장·교회 변경, 상한/배분, 벽·지형·공급 출발점 변경과 관련 경로 제거는 그대로 재검사한다. 수용량보다 많은 필지는 기존처럼 재계산한다. WeakMap에서 조회한 구조도 LRU 사용 순서를 갱신해 살아 있는 도시가 투영 후보 때문에 불필요하게 밀려나지 않게 한다. 실패 결과는 성공 증명처럼 전파하지 않는다.

**동일 상태 비교.** 수정 후 같은 277,920틱 원시 상태·같은 호출 순서에서 운송 후보는 380.0/369.9ms, 전체 조언자는 360.1/362.8ms였다. 각각 첫 호출/반복 호출이며 행동은 모두 같은 `none`이다. 이 표본에서 약84~86% 감소했으나 전체 게임 FPS, GPU 시간, 도시 성장 성공률을 뜻하지 않는다. 원본 상태는 덮어쓰지 않았다. 전후 로그는 `/tmp/efficient-service-slowstate-separated-before.log`, `/tmp/efficient-service-slowstate-reuse-after.log`다.

**검증.** 기존 서비스·성벽·주택·시설 상한 검사와 새 물 위 다리 회귀를 합쳐 **34개 통과**, typecheck·diff 검사 통과. 증명에 실제 공급/주민 경로의 다리와 시설 점유가 들어가는지 확인하고, 다리 제거 후 주택 거부·복구 허용·순서 반전/복원 결과를 검사한다. 이전 마지막 시설 자리 보호, 계획 공사 및 성벽 변경 검사도 유지한다.

**남은 검증.** 600,000틱 기본 도시 안정성과 5개 seed 효율 검증은 아직 완료가 아니다. 식량 담당자의 별도 수정과 합친 뒤 동일 검토자·실행 검증자가 확인한다. 비싼 최초 계획 탐색과 후보 도로 계산 자체는 남으며, 이번 최적화가 불가능한 도시를 통과시키지는 않는다.
