# 목책·석벽 공사 운반 계약 (A⁵ F1)

공사 부지는 기존처럼 자재 공급 건물에서 인접 도로 칸까지 실제 길이 이어지면 정박한다. 같은 닫힌 성벽의 구간은 끝점 순서로 이어지며 성문이 이 운반 연결을 끊지 않는다. 한 구간에 정박하면 나머지는 성벽 **안쪽**의 통행 가능한 칸을 따라 접근한다. 안쪽 칸은 지면·점유·성벽 경계 판정을 통과해야 하며, 이 예외는 목책·석벽 공사 배송에만 적용한다. 주민·배급·일반 건물 배송은 계속 도로 경로를 쓴다.

대각선으로 이웃한 두 안쪽 칸 사이는 직교 중간 칸 하나를 경유할 수 있을 때만 통과한다. 두 중간 칸 모두 물·점유·성벽에 막히면 모서리를 비집고 지나가지 않는다. 운반 중 만난 도로 칸이 일반 도로망에서는 고립돼 있을 수 있으므로, 복귀할 때는 지나온 유효 경로를 거슬러 집까지 실제 길이 있는 첫 도로 칸을 찾는다.

각 후보는 `공급처 → 정박 도로`의 기존 도로 길이와 `정박 → 부지`의 실제 안쪽 이동 칸 수에 가중치 2.0을 곱한 합으로 비교한다. 같은 안쪽 칸에서 다음 벽 변으로 넘어가는 경우 이동 칸 수와 비용은 0이다. 대각 한 번은 맨해튼 거리 2칸으로 계산하고 운반인 이동 속도를 절반으로 해 실제 소요 틱과 비용을 맞춘다. 여러 정박 후보 중 총비용이 가장 낮은 경로를 선택한다. 완료된 부지로 향했던 운반인은 출발 경로의 안쪽 칸을 거슬러 도로로 돌아간다.

제안·초안의 자재 접근 검사는 가상 선포 상태에 실제 배송 판정을 적용한다. 예측에는 도로 직접 연결 수, 벽을 따라 운반하는 수, 연결이 필요한지를 구분한다. 정박 구간이 없으면 가장 짧은 합법 연결 길을 가진 한 구간을 지도에서 가리키고 한 곳의 길이 필요하다고 경고한다. 추천 생성기는 정박이 있는 후보를 먼저 고르며 실패하면 경고와 함께 기존 기하 후보를 초안으로 제시한다.

`wallCarryRoute`의 기하 그래프 캐시는 성벽 객체와 타일 배열의 참조가 모두 같을 때만 재사용한다. 도로·점유 변경은 새 타일 배열, 공사 완료·성벽 변경은 새 성벽 객체를 만들어 무효화한다. 지도 크기는 한 성벽과 타일 배열 사이에서 바뀌지 않는다. 재고·일꾼은 그래프가 아니라 매 요청의 시작점과 배송 후보에 반영된다. 자연 12구간 상태에서 동일 경로 200회 지역 측정은 벽 객체를 매번 새로 만든 경우 14.3ms, 그래프 재사용은 8.9ms였다. 이는 경로 호출 미시 측정이며 전체 틱 성능 결과는 아니다.

검증 상태는 `tests/fixtures/wall/README.md`에 출처를 기록한 자연 화면 플레이 스냅샷이다. 25분 선포 전 상태는 정박 0/12, 도로 도구로 새 칸 1개를 이으면 접근 12/12가 된다. 35분 선포 후 상태는 정박이 없어 길 추가 없이 12,000틱 진행해도 완공 0/12다. 원래 60분 화면 기록은 플레이어가 길을 추가해 10/12였으므로 두 결과를 동일 조건의 속도 비교로 보지 않는다.
