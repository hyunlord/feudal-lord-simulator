# UI-KIT-1b 후속 둘 — 보고서

관문: 통과 — ① 일시정지 설정의 색약 모드 설명 겹침 없음 · ② 연대 띠의 진입 안 한 시대 = 명목 연도 + "아직 오지 않음"(옅게) · 스킨 감사 0 / 726(19개 상태) · UX-3 회귀 세트 통과

## 1. 고친 것
- **① 일시정지 설정:** 설정 칸이 인라인 흐름이라 색약 모드의 설명 줄("배치 가능 칸 초록")이 다음 단추 밑으로 흘렀다.
  - 설정 칸을 줄바꿈되는 플렉스 줄로 바꿨다(`.pause-menu-settings`).
  - 색약 단추와 그 설명은 한 묶음(`.setting-pair`)이다.
  - 캡처: [pause-settings-after.jpg](pause-settings-after.jpg)
- **② 연대 띠:** `timelineSegments`는 진입 안 한 시대를 `max(명목 연도, 지금 + 1)`에서 시작시키고, 그 위치의 연도를 이름표로 썼다. 그래서 진입이 밀린 시대는 "지금 연도"로 읽혔다.
  - 이제 진입 안 한 시대의 `fromYear`는 명목 연도다(1337·1348·1380).
  - 이름표 아래 둘째 줄에 "아직 오지 않음"을 쓰고, 옅게(불투명도 0.6) 그린다. 띠 위의 자리는 그대로 "지금" 뒤다.
  - 이름표는 띠의 1/5 칸 안에 들어간다(길어진 이름표가 옆 칸과 겹쳤다).
  - 시험 `tests/chronicleScreen.test.ts`: 1469년에 둘만 진입한 도시는 `[1300 진입, 1302 진입, 1337·1348·1380 미진입]`이고, 미진입 시대는 지금 뒤에 선다.
  - 캡처: [실제 판 seed 2, 1323년](chronicle-strip-live-1323.jpg)

## 2. before-after 캡처의 저장 — 실제 판인가
**실제 봇 판이지만 옛 형식을 그대로 넣은 것이라, 연대 띠는 합성과 다를 바 없다. 엔진에 넘길 일은 아니다.**

- **어떤 저장인가:** 연대기·장부·전기 캡처의 `merchant-town`은 결정론 고정 저장 `fixtures/determinism/seed1/final-state.json`이다.
  - seed 1 자동 성장 봇 판이 틱 679,251(1469년, 석조 도시, 인구 768)에 닿은 끝 상태다.
  - 2026-09-24에 저장 형식 v12(시대·계절)보다 먼저 만든 것이다.
  - `historicalEras`·`seasons`·`persons`·`history` 필드가 없다.
  - `scripts/ui5States.ts`가 이것을 불러 사람 이름이 붙을 때까지 틱을 더 돌렸다. 캡처는 저장 이주 없이 스토어에 바로 넣었다.
- **왜 1469가 찍혔나:** 불러온 첫 틱에 `advanceHistoricalEras`가 시대 다섯을 한꺼번에 진입시켰다(모두 `enteredTick` 679,252). 캡처의 1469는 진입하지 않은 시대가 아니라 1469년에 한꺼번에 진입한 시대였다([캡처](chronicle-strip-fixture-1469.jpg)).
- **현재 형식의 실제 판은 제때 진입한다:** seed 2 1장(`scripts/ui5States.ts`)에서 포화 1300년, 기근과 취약 1320년(강제), 장 끝 1323년에 나머지 셋이 아직이다. 1307년 청원 상태는 포화만 진입이다.
- **그와 별개로 ②의 결함은 진짜였다:** 진입이 밀린 시대(명목 연도는 지났는데 조건이 안 됨)는 "지금 연도"로 찍혔다. 위에서 고쳤다.
