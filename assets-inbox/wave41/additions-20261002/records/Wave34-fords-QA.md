# Wave 34 여울 12장 자체 검수

- 상태: candidate. 게임 파일 수정/설치 없음.
- 6개 여름 여울은 폭 2/3/4칸과 NE/NW별 각각 독립 native image_gen 호출. 겨울 6개는 대응 여름 원본을 각각 편집 호출했다. 모델 이름은 도구에 노출되지 않았다.
- 12장 모두 512×256, 중심 피벗 (256,128), 반복 없음. 타일128×64. NE 중심축 기울기 -0.5, NW +0.5.
- 여울의 바닥 자갈/디딤돌, 양끝 수레 바퀴 자국 경사로가 읽힌다. 지면보다 솟은 다리/제방이나 널판은 없다.
- 폭별로 동일 그림을 단순 확대하지 않았다. 원본 구성이 다르고 물 부분의 실제 접합 거리는 폭별 2/3/4칸이다. 횡단 통행 폭은 약1칸으로 고정했다.
- 생성 원본의 물 표면이 불투명하여 청회색 물 색상 ROI만 알파를 약0.52배로 정리했다. 갈색/올리브색 강둑과 따뜻한 회색 디딤돌은 유지했다. 전체 그림을 반투명하게 만들지 않았다.
- waterROI에서는 각 이미지 3,392~9,922개 물 픽셀이 검출됐고 모두 alpha1~167 범위의 반투명이다. 희미한 가장자리 픽셀도 포함하므로 최소1은 내부 평균 불투명도를 뜻하지 않는다.
- 겨울은 기존 돌 배치와 양안 윤곽을 유지하며 얇은 가장자리 얼음/서리만 추가했다. 물 전체가 얼어 붙지 않는다. 원본을 새로 그린 생성 편집이므로 계절간 세부 픽셀 완전 일치는 보장하지 않는다.
- 최종 QA보드에서는 두 방향·3폭과 얇은 겨울 가장자리 차이를 확인했다. 줌0.6에서 미세한 자갈과 바퀴 자국은 작은 질감으로 줄지만, 디딤돌 줄/양안 진입부/열린 물이라는 큰 구조는 유지한다. 실제 게임 물 흐름과 런타임 정렬은 설치 후 검증 대상이다.

## 기계적 후처리

원본 알파 경계와 청회색 물 구간을 측정하여 등각 좌표 축으로 크기와 피벗을 맞춘다. 물 구간 양끝을 지정 접합점에 매핑하고 은행 둑 부분은 각각 반 칸 길이에 맞춘다. 이는 크기/정렬/알파 정리이며 새로운 그림 요소를 절차적으로 생성하지 않는다. 실제 좌표와 원본 크기는 `fords-sources.json`의 `mechanicalTransform`에 기록했다.

NE 접합점: w2=(192,160)/(320,96), w3=(160,176)/(352,80), w4=(128,192)/(384,64). NW는 y값 순서가 반대다.
