# Charter & Kin 콘텐츠 v4.1

2026-10-05 · Astra 콘텐츠 편집 · **게임 미설치 / 저장소 코드 변경·커밋·푸시 없음**

v4 200건에 **수정 1건(011), 추가 15건(201–215)**을 ID로 덧씌우는 판이다. 합친 정본은 215건이며 이번 `events-v4.1.json`은 변경분 16건만 담는다. 다른 기존 199건은 그대로 둔다.

## 함께 전달하는 이유

`events-v4.1.json`은 문구·효과 설명이다. 발동·대상·반복을 실행하는 `registry-v4.1.json`도 반드시 같은 ID로 병합해야 한다. 원고만 바꾸면 011의 차단과 반복 문제는 고쳐지지 않는다. 이 묶음은 v4 원고·등록기 **레코드 형식을 유지**한다. Delta Schema는 정확한 레코드 수 200→16, 신규 number 상한 200→215, 문서 메타데이터만 바꿨다. 기존 필수 필드·효과 enum·레코드 추가 필드 금지는 완화하지 않았다.

원격 정본: `d169d3faf8366c839861042596c2ec79b0a4c4c2`.
LM-E9b 검증 코드: 별도 로컬 작업 폴더의 `813b31f0d0e4eacb0e12c58d45cf4719e12dec94` 및 파일 해시 스냅샷. 원격에는 아직 해당 실행기가 없었다. 코드·분포 자료를 읽기 전용으로 사용했고 검사는 외부 복사본에서 했다. 원격 병합 완료나 게임 설치 완료로 표현하지 않는다.

## 011: 혼담에 되돌아온 조건

- 존재하지 않는 `COUNTER_MATERIAL_BURDEN_INCREASE_V1` 호출 제거. `_V1` 없는 명세도 expression/parameters가 없어 단순 이름 교체는 올바른 수정이 아니다.
- 금전만 늘고 다른 조건이 같다는 본문·선택 대가의 단정을 제거했다. 실제 유효 역제안·남은 기한·지급 능력은 유지했다.
- 기간 계산은 파생 이름 대신 지원 연산 `subtract`로 표시했다.
- 실제 바인딩에 없던 estate/person/steward/audit 키를 **bound.negotiation.id**로 바로잡았다. 같은 혼담에는 한 번, 새 혼담에는 재등장할 수 있다. 원래 3년 이상 간격은 보존했다.
- 기존 선택지와 ID는 보존했다. 역제안을 거절해도 없는 관계 벌점을 새로 붙이지 않는다.

## 반복과 선택의 계약

- 계절 번호는 실제 `floor(state.tick / 1000)`을 바인딩한 읽기 값이다. 저장 상태나 가상의 발생 ID가 아니다. 달력 외에 시장·노동·식량·공사 등 실제 조건을 함께 검사한다.
- 중복 키에는 `bound.*`만 쓴다. 같은 ID·같은 맥락은 답변 완료·보류 여부와 무관하게 재발동하지 않는다. 값 왕복만으로 새 맥락을 만들지 않는다.
- 최소 실효 선택 2개. 현재값과 같은 명령은 변화로 세지 않는다. 정책 세 안을 제시하면 현재 정책 하나가 숨겨져도 두 안이 남는다.
- 좌판세는 `state.agency.duesPermille`에서 상대 ±100‰를 계산하고 250–2000으로 제한한다. 이름이 비슷한 `stallFeePermille`(권리 할인 읽기)를 사용하지 않는다. 개별 가구 면제·통행세 변경이 아니다.
- 보류는 명확히 매핑되는 단일 보내는 세력에만 기존 R3 관계 −2를 사용한다. 임의 새 효과가 아니며 부과는 엔진 원장이 담당한다. 원정기 214는 실제 왕실 바인딩·보내는 쪽에 맞춰 왕실 관계 대가를 적용한다. 모든 신규 사건에 실효 대가가 있는 현행 유지 선택을 두었다.
- 우물 공고는 기존 공고 금액이 24d 미만일 때만 새 24d 약속으로 제시하며 실제 후보 자리와 예산을 추가 요구한다. 다른 정책·좌판세·주문 선택은 도시의 빈 건물 자리를 전제로 하지 않는다.
- 목재는 잔량 설정이다. 추가 지급·즉시 완공이 아니다. 정책은 도시 전체 사업 가중치로, 임금·고용·징병·구호금을 직접 바꾸지 않는다.

검증 수치와 범위는 `VALIDATION.md`, 분포 목표·가정은 `EXPECTED_DISTRIBUTION.md`, 미지원 소재는 `REMAINING.md`를 따른다.
