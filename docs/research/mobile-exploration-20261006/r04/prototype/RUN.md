# 로컬 시제품 실행

Node.js 22 이상이 필요하다. 사전 빌드한 `dist/`를 포함한 납품에서는 외부 의존성 설치 없이 실행할 수 있다.

```sh
node server.mjs
```

브라우저에서 http://127.0.0.1:4179 를 연다. 같은 포트가 사용 중이면 `PORT=4180 node server.mjs`. 서버는 내 컴퓨터(loopback)에만 열린다. 모바일 크기390×693 또는375×667로 확인할 수 있다. 휴대폰 실기기 네트워크 접근을 허용한 배포는 아니다.

1. 지원 비중을 총100 이하로 섞고 ‘이 방침 적용’을 누른다.
2. ‘영지로 가기’→‘성장 보기’ 또는 ‘12일 진행’. 주민의 시설과 이유 영수증을 읽는다.
3. ‘이웃과 교역·전투’에서 교역 제안 또는 출정/방어를 선택한다. 실제 경로·손실·재고를 확인한다.
4. ‘같은 시작, 세 방향 비교’에서144일 완료 뒤 도시 구조를 비교한다.
5. ‘기록 저장’은 이 브라우저의 localStorage에 명령 기록을 저장한다. 새로고침 뒤 ‘저장 기록 이어하기’는 재실행과 SHA256 확인 후 이어간다.

그림은 모델 격자를 그리는 자리 그림이다. 서버 오프라인 성장·다중 계정·알림·결제는 구현하지 않았다. 마지막으로 열린 동안 자동 정산하며, 닫힌 동안의 성장을 제품 서버처럼 주장하지 않는다. 계약·전투는 로컬 동일 규칙을 사용하는 가상 이웃과 실행한다.

## 소스 검증

원 저장소 전용 복제본 안의 현재 위치에서 기존 TypeScript 도구를 사용한다. 새 의존성은 설치하지 않았다.

```sh
../../node_modules/.bin/tsc -p tsconfig.json
node --test dist/tests/*.test.js
```

독립 추출본에서 소스를 바꾸려면 호환 TypeScript 컴파일러가 필요하다. 사전 빌드 게임 실행에는 필요 없다. 검증 명령은 원본 저장소의 전체테스트/DGX 작업을 실행하지 않는다.

저장 검사는 재현·우발적 변경 탐지다. 사용자가 입력과 결과 hash를 함께 다시 만든 위조를 막는 인증 서버가 아니며, 상용 중복 지급/동시성 보장을 제공하지 않는다.

전체 모델 소스를 수정했다면 컴파일 전에 `node scripts/build-identity.mjs`를 실행한다. `node scripts/build-identity.mjs --check`는 생성된 소스·규칙·콘텐츠 ID가 현재 파일과 같은지 검사한다. 다른 빌드에서 만든 기록은 자동 이행하지 않고 거부한다. 기존 실험 기록은 보존할 수 있지만 서로 다른 규칙판의 결과를 같은 판으로 비교하지 않는다.

실제 검증은 macOS ARM64의 Node25.8.2에서 수행했다. Node22는 API 기준 최소 요구 버전이며 별도 실행 검증하지 않았다.
