## 만든 것

1. **종류별 활성화(Z-11a)**: 집 규칙은 필지 구역이 하나라도 있을 때만 켜지고, 밀밭 규칙(성내 금지 포함)은 경작지 구역이 하나라도 있을 때만 켜진다(`zoneRuleActive`·`activeZoneRuleFor`). 불일치 진단도 켜진 규칙만 본다. 미리보기·원인은 판정 함수를 그대로 따른다.
2. **`zone_undo_stroke`(Z-17)**:
   - 마지막 `zone_paint`/`zone_erase` 하나를 되돌린다. 편집 직전 상태가 정확히 돌아온다. 병합됐던 구역은 흡수 전으로 나뉘고, 새 구역은 사라지며 서수도 되돌아간다.
   - 스택은 최근 20편집이다. 지시서의 "구역별 획 스택" 대신 편집 순서 하나의 스택으로 했다. 한 획이 여러 구역을 바꾸기 때문에(병합, 다른 구역의 칸 빼앗기), 구역별로 나누면 되돌린 결과가 편집 직전과 달라진다(결정 Z5).
   - `zone_remove`는 스택을 비운다.
3. **자동 성장 구역 인식(Z-15a)**:
   - 필지 구역이 있으면 직접 집 배치(`housingAction`)는 쉬고, 집은 ZoneFillAgent로만 놓는다. 에이전트는 정책의 필지 상한 아래에서만 부른다. 상한은 이번에 더했다.
   - 집·밀밭의 모든 자동 후보는 켜진 구역 규칙을 통과해야 한다(`autoplayCanPlace`: 건설 부지 탐색 2곳, 후반 식량 부지, 식량 입구).
   - 그래도 걸리는 후보가 나오면 그 결정 동안 제외 목록에 넣고 다시 고른다(최대 3번). 걸린 후보는 리듀서로 보내지 않고 수를 센다(`autoplayZoneRejections`). 결정론이다.
4. **달력**: `TICKS_PER_YEAR = 4000`(계절 1,000), 잠정값이다. 달력은 파생값이라 저장된 필드가 없어 저장 요약도 틱에서 다시 계산된다. 역사 시대 전이 연도는 그대로다.
5. **경작지 띠 상태 API(Z-18)**: `arableStripStates(zone, state) → { axis, strips: [{ id, cells, state, farmId }] }`.
   - 지시서 서명 `arableStripStates(zone)`에 밀밭을 읽을 `state`를 더했다.
   - 축은 경계 상자의 긴 변이다. 띠는 축 방향 한 줄의 연속 칸이다.
   - 상태는 띠를 덮는 밀밭(id 순 첫 번째)의 생산 진행을 투영한다: 1/3 미만 `ploughed`, 2/3 미만 `seedling`, 그 이상이거나 가득 차면 `growing`. 일꾼 부족·중지·미납이면 `fallow`, 공사 중이면 `ploughed`, 밀밭이 없으면 `fallow`. 결정론이다.
6. **목초지·건초지·과수원·숲**: 상태·배치 규칙 없이 종류만 유지한다(C5).
7. **성벽에 걸친 획(Z-9a)**: 성 밖 칸만 소속에 넣는다. 예측 줄은 `성 안 N칸 제외`(warn)이고, 칠하기 판정 결과에 `excludedInsideWall`을 더했다. 모든 칸이 성 안일 때만 `성내 경작지 금지`로 거부한다.

## C1c-2 두 안 비교 (사용자 결정 대기, 결정 Z8)

**안 A — 밀밭 건물을 유지하고, 경작지 구역은 입지 규칙과 띠 표시만 맡는다(지금 C1c).**
- 규칙: 밀밭 2×2가 생산 단위다. 경작지 구역은 "밀밭은 구역 안에만"과 성내 금지를 강제하고, 띠 상태는 건물 상태를 투영한 표시다. 밀밭이 없는 띠는 늘 휴경이다.
- 저장: 추가 없음(v9 그대로).
- 가드레일: 영향 없음. 구역 없는 seed는 바이트 단위로 같고, 자동 성장은 구역이 있을 때만 후보를 거른다.
- 약점: 방앗간/밀밭 밀도 문제(24필지 도시에 밀밭 25~28개)가 그대로다. 띠와 생산의 연결이 표시뿐이다.

**안 B — 밀밭 건물을 없애고 "경작지 구역 + 헛간"으로 바꾼다.**
- 규칙:
  - 경작지 칸이 생산 단위가 된다. 띠마다 밭갈이 → 파종 → 생장 → 수확 → 휴경 주기를 계절(1,000틱)에 맞춰 돌린다.
  - 헛간(작은 건물)은 일꾼 배치, 수확물 보관, 수레 출발점을 맡는다.
  - 생산량은 경작 칸 수 × 주기다. 휴경 비율은 삼포제 같은 선택이 된다.
- 저장: 띠 주기 상태를 저장해야 한다(v10). 옛 저장의 밀밭 건물은 경작지 구역 + 헛간으로 이주하거나, 옛 건물 호환 경로를 둬야 한다.
- 가드레일: 자동 성장 식량 사슬 전체가 밀밭 건물을 전제로 한다. 부지 선정, 방앗간 비율, 곡창 커버리지, 밀 재고 0 관측(`autoplayFood*`) 모두 다시 써야 하고, seed 1~5 가드레일을 새 기준선으로 다시 통과해야 한다. 가장 큰 작업이다.
- 이점: 열린 경지 띠가 실제 규칙이 되고, 계절이 의미를 가지며, 밀밭 밀도 문제가 "경작 면적" 문제로 다시 정의된다.

## 넘길 것

**렌더**
- **Z 키**: `canvasZoneBrushRuntime.ts`의 `KeyZ`에서 `{ type: "zone_undo_stroke" }`를 보내면 된다. 되돌릴 기록이 없으면 상태가 그대로이므로 버튼 비활성은 `state.zoneUndo === undefined`로 판단한다. C1e가 아니라 다음 렌더 작업에 통보한다.
- **띠 상태 API**: `arableStripStates(zone, state)`(`src/zones/arableStrips.ts`). 띠의 `id`는 칸 줄·첫 칸이 같으면 유지된다. 상태 네 가지와 `farmId`를 쓴다.
- **성벽 걸친 획**:
  - 칠하기 판정 결과에 `excludedInsideWall`(뺀 칸 수)이 생겼다. `zonePaintLines`가 `성 안 N칸 제외` warn 줄을 준다.
  - 지금 렌더 오버레이는 거부된 획에서만 성 안 칸을 붉게 칠한다. 성벽에 걸친 획은 이제 거부되지 않아, 뺀 칸이 미리보기에 따로 보이지 않는다. 뺀 칸을 회색으로 보여 주려면 원래 래스터 − `cells`를 그리면 된다.
- 경작지 도로 접근 예측(C1b 마찰 2)은 이번 범위 밖이라 넣지 않았다.

**C3(노동)**
- 띠 상태의 `fallow`에는 "밀밭 일꾼 부족"이 섞여 있다. 노동 모델이 생기면 원인을 띠 상태와 분리해 보여 줄 수 있다.
- ZoneFillAgent의 `labour` 진단(공사 중인데 쉬는 일꾼 0)은 C3 일용 노동 풀과 맞물린다.
- 안 B를 고르면 경작 주기의 계절 노동 수요(파종·수확 철)가 C3의 첫 계절 노동 사례가 된다.
