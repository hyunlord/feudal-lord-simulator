# FACTION-0 세력 기초 보고서

지시서: FACTION-0 세력 기초(사용자 지시 2026-09-27, 엔진 2장 작업 셋째, 6시간). 명세: [세력 기초](../../design/factions.md) FX-1~FX-8. 결정: FN1~FN9.
- 엔진 세션이다. 렌더·UI 0줄, 검증은 DGX에서 했다.
- 근거: 권리·정치 조사(행위자 최소 세트, 기억 세 종류), 기록·연대기 설계 2.3.

## 만든 것
- **세력 아홉(FX-1)**: 상위 영주(백작령 seed) · 왕실(그해의 국왕) · 이웃 영주 둘(젠트리 가문 seed, 서로 다르고 영주 가문과도 다름) · 주교(교구 seed) · 상인 가문 둘 · 도시 공동체 · 농민 공동체.
  - 세력마다 이름·수장·문장 seed·관계(−100~100)·기억·연표를 갖는다.
  - 요구(열린 청원)와 약속(준 권리·상인 전쟁 차입·양모 분할 납부)은 API가 상태에서 읽는다.
- **수장 = 인물(FX-2)**
  - 바깥 세력: 세력의 사람(`factions.people`, id `f-`, 젠트리·성직자 초상)이다. 해마다 죽음 굴림이 있고, 같은 성의 후계자가 잇는다.
  - 왕실: 에드워드 1세~헨리 6세를 역사대로 따른다.
  - 마을 세력: 가구주(상인 → 장인 → 촌장)이고, 떠나면 다음 계절에 다시 뽑는다.
  - `personById`가 세력 사람도 찾는다.
- **청원·사건의 귀속(FX-3)**: 청원자 → 세력(상인 → 첫째 상인 가문, 상위 영주, 왕실, 도시 공동체, 피란민 → 주교).
  - 바깥 세력 청원의 청원자 인물은 그 수장이다(국왕의 칙령, 백작의 복원 청원, 주교의 서한).
  - 청원 결정 기록과 전쟁 기록(전령·징집·면허 = 왕실, 봉화·습격 = 도시)에 세력이 `actors`로 붙는다.
- **관계와 기억(FX-4)**: 청원 답·왕실 칙령·대기근 대응·쇠퇴·되사기·가문 교체·습격이 관계를 움직인다(크기는 결정 FN8).
  - 움직일 때마다 원장 `faction.relation` 기록이 남고, 세력의 기억은 그 기록 id를 가리킨다.
  - 상인 게이지(FC-3)와는 따로 센다(FN4).
- **연표(FX-5)**: 세계 사건 19건(1307~1450, 고정)이 그 세력의 연표에 들어간다. 바깥 세력의 일(해마다 250 ‰, seed)과 수장의 죽음·후계도 들어간다.
- **API(FX-6)**: `factionsList`·`faction`·`factionChronicle`(세력 연대기 쪽: 그 세력의 원장 기록 + 연표)·`worldTimeline`·`factionOfPetitioner`.
- **저장 v21(FX-7)**: `GameState.factions`. v20은 다음 틱에 세력이 생긴다. 지문 `391cf4f5`, v21 저장 픽스처 9개.

## 렌더가 넘겨받을 API
- **세력 연대기(CHRON-2 화면)**: `factionChronicle(state, id)`(기록 = 원장 `HistoryRecord`, 문장은 `historySummary`), `factionsList`(관계·요구·약속), 연표 `timeline`.
  - 문구: `factionCopy.ko.ts`의 `factionDisplayName`·`WORLD_EVENT_LINES`·`FACTION_AFFAIR_LINES`·`FACTION_LEADER_LINES`.
- **문장**: `heraldrySeed`(세력마다). 영주 가문 문장과 같은 방식으로 그린다.
- **수장 초상**: `personById(state, leaderId)` → `personPortrait`(바깥 세력은 젠트리·성직자 풀).
- **청원 카드**: 바깥 세력의 청원자는 그 수장 한 사람이다(`petitionerIds`). "청원자: 상인 무리" 고정 문구를 세력 이름으로 바꿔야 한다.
