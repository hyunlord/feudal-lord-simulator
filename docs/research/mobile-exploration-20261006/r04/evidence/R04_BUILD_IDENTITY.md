# R04 replay build identity

Scope: session recording boundary, generated `prototype/model/build-identity.ts`, generator `prototype/scripts/build-identity.mjs`, session tests. No gameplay changes or heldout simulations.

Before compiling or releasing, run:

```sh
node prototype/scripts/build-identity.mjs
node prototype/scripts/build-identity.mjs --check
../node_modules/.bin/tsc -p prototype/tsconfig.json
```

Commands above run from mobile-study. The generator is dependency-free Node and uses its own file URL, so also works from the extracted prototype using `node scripts/build-identity.mjs`. `--check` compares exact generated content, reports stale sources, exits1 without rewriting. Regenerate **after** the final gameplay source freeze. Browser runtime imports only generated constants, never Node filesystem/crypto modules.

Identity format1:
- sourceHash: SHA256 over deterministic JSON of sorted relative paths plus SHA256 of exact bytes for **every model .ts file**, recursively, except session.ts and build-identity.ts. Current11 files includes economy, battle, contracts, pathfinding, RNG, terrain, rules, types and reexport module. New model source files automatically join the hash.
- rulesHash: same manifest scheme restricted to rules.ts.
- contentHash: same scheme restricted to terrain.ts, which contains the simulation's generated physical map content. Appearance-only UI/CSS/placeholders are excluded. Model rules embedded elsewhere remain covered by sourceHash.
- BUILD_SOURCES includes exact per-file digests for audit. Generated source does not hash itself; session is excluded as requested to keep recording/serialization changes independent from gameplay freeze.

Recordings now bind version label, full identity, initialStateHash, seed, terrain, ordered commands in inputHash. Initial state is generated under the actual current rules/seed and checked before replay. ResultHash covers both cities, diplomacy and battle. Existing no-identity recordings intentionally reject; there is no silent cross-build migration. Command changes, initial seed changes, claimed result changes, foreign source/rules/content identity and foreign initial state are rejected. Same recording replay and subsequent continuation remain equal.

These are **local reproducibility checks, not authentication**. Anyone who can edit a recording can recompute unsigned hashes or alter client code. Production authority still requires server-owned state, authentication, revision/idempotency checks and server recomputation. Generated static identity proves source correspondence only when `--check` is run before actual compilation; a stale compiled dist must also be rebuilt. No server attack-resistance claim follows from tests.

Verification: identity test failed before implementation (missing sourceHash), then session roundtrip/tamper tests and strict TypeScript passed. Final source identity should be regenerated by owner after other model edits stop; current digest is not a permanent release identifier.
