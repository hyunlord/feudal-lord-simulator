# Engine B 결정 무게 전수 정적 감사

관문: **정적 목록 검증 통과, 실행·사람 판정 대기**. 실행 가능한 56건을 빠짐없이 열거했으며, 이것을 56건 자연 발생·결과 표시·인과 검증 완료로 표현하지 않는다.

## 현재 실행 기록

- `engineB-weight-smoke-4b45924`: DGX 1년 시험 exit0, 4.5초. 0–4000틱 관측 간격 최대1·역행0, 후보 판정224건, 청지기 보고2/2. `smoke-1.json.gz`와 `smoke-provenance.json`에 원본 해시를 보존했다. 장기 관문 대체 자료가 아니다.
- `engineB-weight125-7ee76b9`: 종료 연도의 첫 틱이 전체 분모에 섞이는 검토 지적 때문에 자체 실행만 중단했다. 결과를 채택하지 않는다.
- `de3d9e224`: 결정·제시·후보 판정은 `[0,500000)`으로 제한하고, 이전 결정의 결과 확인에는 끝점 history를 보존하도록 수정했다. 경계 회귀 포함12시험과 독립 재검토 통과.
- `engineB-weight125-fixed-de3d9e2`: 수정 소스로 seed1→2→3을 한 실험에서 직렬 실행 중이다. 완료 전 수치·통과를 주장하지 않는다.

실행 원본은 `engineBWeightAuditRun.ts`, 세 원본의 동일 소스·구간·56 ID·관측 완전성을 검증하는 합산기는 `engineBWeightAuditReport.mjs`다. 연간 분모는 실제 `cameHeavyToLord` trace 사안이며 모든 명령 횟수나 전체 화면 도착 횟수와 구분한다. 후보 판정 기록은 실제 v4 평가를 관측하지만 외부 등록기 예산으로 평가 자체가 생략된 철까지 설명하지 않는다.

`layers.json`은 현재 `registryV4Support()`의 `runs=true` 집합과 정확히 같다. 각 ID마다 지원되는 선택과 실제 명령 인수, 기본 무게와 Engine B 예외, 지속세율 여부, 잠재 trace 대상, because 생산 경로, 처음 관측 가능한 조건과 남은 증거 공백을 담는다. 지원되지 않는 선택도 이유와 함께 별도로 보존한다. 명령 인수의 binding은 실제 세계 대상을 읽는 식이며 아직 실행해서 얻은 대상 ID가 아니다.

## 결과가 보이는 경로와 한계

명령 성공 뒤 occurrence와 decision trace, `decisionReads.ts`의 연간 결정·청지기 보고가 첫 모델 증거다. 후속 결과는 권리의 첫 수입, 소송 단계 변화, 혼인·약속 전이, 사업 채택 영수증, 목재 주문 감소, 감사 또는 철 요약의 기분 구간 변화처럼 실제 조건이 충족되어야 because 기록이 생긴다. 모든 사건에 “다음 철에 결과가 보인다”는 고정 기한을 붙일 수 없다. JSON의 각 명령 경로가 그 조건과 시기 불확실성을 명시한다. 화면 소비와 실제 첫 표시 시점은 검증하지 않았다.

영주 응답은 `decisionTrace.ts:193`에서 occurrence 무게를 이어받으며 청지기 처리는 `:268`에 기록된다. `decisionReads.ts:203`의 사건 보고는 도착 시각 기준이고, 이전 장기 관측 수집기는 해결·만료 trace 시각 기준이다. 둘을 같은 연간 도착 집계로 해석하지 않는다.

코어 넘김: `decisionTrace.ts:223`은 영주가 고른 답과 무관하게 사건 안에 좌판세 명령이 하나라도 있으면 `dues` target을 붙인다. 정적 목록은 083·144·150을 후보로 표시한다. 이 목록의 소스 대조와 아래 후속 실행 근거를 구분하며 코어는 수정하지 않았다.

후속 단위 대조에서 083의 실제 목재 답이 좌판세 target을 갖고 합성 좌판 수입에 because를 붙이는 현상을 재현했다. 자연 판 후속 수입 검증과 구분한 [엔진 요청서](../../requests/engine-B-weight-trace.md)를 남겼다. 위 정적 목록 자체는 실행 증거로 바꾸지 않는다.

소식 전환 후보는 **아직 없음**이다. 의미 없는 선택이 실제로 입증된 ID는 없으며 정본 콘텐츠 수정 넘김은 행동 감사 뒤에 결정한다. DTR-22·23의 소송·방어 규칙은 기존 엔진 계약으로 보존한다.

## 재생성과 검증

Mac에서 아래 두 명령을 실행했다. 생성기는 지원 API의 정확한 56 ID 집합, 누락·추가 0, HOLD 38 비활성, 예비 43/13, 편집표 9/18을 assert한다. `sourceFiles`는 의존성을 넉넉히 포함한 모든 `src` 파일과 생성기·HOLD 권고 파일의 실제 작업 바이트 SHA-256이다. 커밋되지 않은 수정과 추적되지 않은 소스도 포함한다. `sourceCommit`은 생성 당시 체크아웃 HEAD이며 그 커밋 트리와 작업 소스가 같다는 뜻이 아니다. `--check`는 이 생성 당시 커밋을 보존하면서 현재 파일 해시와 전체 의미 자료를 비교한다. 소스가 같은 이후 커밋이나 문서만 바뀐 HEAD 때문에 실패하지 않는다.

```sh
node --import tsx scripts/engineBLayerInventory.ts
node --import tsx scripts/engineBLayerInventory.ts --check
```

정적 검증은 단기·장기 실행을 하지 않는다. 다음 증거는 별도로 필요하다: 실제 occurrence별 활성 선택과 배정, 선택 실행 뒤 trace/history/보고의 같은 ID 연결, 후속 because 발생과 지연, 조용한 해의 실제 화면 결과 노출. `layers.json`의 상태는 이 증거가 생기기 전까지 `static_inventory_runtime_pending`이다.
