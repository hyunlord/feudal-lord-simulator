- 생성 입력: 프로젝트 소유 건물 그림을 화풍·카메라 참고로 사용하고, 각 계열의 앞 단계 완성 그림을 다음 단계의 참고로 사용했다. 겨울은 해당 단계의 완성 여름 그림을 편집한 완성 PNG다.
- 각 호출의 요청문은 `records/prompts/`에 보존했다. 목표 좌표·크기를 프롬프트에 써도 생성기가 그대로 따르지 않아, 최종 좌표는 프롬프트가 아닌 CSV와 등록 결과를 따른다.
- 부품을 잘라 조립하지 않았다. 후처리는 완성 이미지 전체에 적용하는 균일 축척·평행이동과 투명 캔버스 등록뿐이다. 겨울 알파를 여름 알파로 강제 교체하지 않았다.
- 원 생성 파일은 작업 폴더 `raw/`에 보존한다. 경량 ZIP에는 등록된 최종 44 PNG와 원본 해시·변환값을 넣고, 중복되는 고해상도 raw 및 폐기 시안은 넣지 않는다. 따라서 ZIP만으로 도시 합성은 재현할 수 있지만 원 생성물의 재등록 실행에는 별도 raw가 필요하다.
- `records/raw-inventory.json`은 최종·재시도·폐기 원본의 SHA-256을 기록한다. `registration-result.json`은 실제 채택된 원본 쌍과 등록 변환을 기록한다.

## 수정 이유

1. 영주관 1단계 최초 겨울판: 오른쪽 외곽 잘림. 여름판에서 같은 프레임으로 다시 생성했다.
2. 다리 3단계: 첫 예배당 문이 사람 기준보다 작았고, 확대 재시도에서는 다리 경간도 커졌다. 2단계의 세 아치 교량을 다시 기준으로 삼아 접근부 예배당을 가진 완성 그림을 재생성했다. 두 둑 접속은 통합 시 실제 도로 축 검증이 필요하다.
3. 목문·길드홀·여관 1단계 최초 겨울판: 바닥 눈이 외곽으로 늘어 계절 알파 정합 실패. 건물과 접지 외곽을 유지하며 지붕에 불규칙한 눈을 얹는 방향으로 다시 생성했다. 최초 실패 측정값을 `registration-result-before-retries.json`에 보존했다.
4. 첫 정적 도시 배치에서 후기 여관이 강 위로 확장됐다. 모든 시대에 동일하게 여관 부지와 주변 일반집 위치를 옮긴 뒤 최종 눈가림 표본을 만들었다. 평가 응답을 받은 뒤 표본을 바꾸지 않는다.

## 해석 한계

60–80% 눈 덮임은 생성 지시와 육안 목표이며, 지붕 면별 분할 마스크로 면적을 실측한 값이 아니다. 실루엣 IoU는 외곽 정합만 측정한다. 내부 문·창의 완전한 픽셀 일치나 실제 엔진 접지·가림·충돌·성능을 증명하지 않는다. 부지는 64×32 world px 격자를 기준으로 제안한 예약 범위이며 현재 엔진 점유값이 아니다.

5. 여관 1단계는 지붕 재시도 뒤에도 여름 접지 그림자의 알파가 달라 IoU가 낮았다. 채택한 겨울판에서 눈을 제거하는 완성 여름판을 다시 생성하여 계절 외곽을 맞췄다. 알파 강제 치환이나 판정 임계값 완화는 하지 않았다.
6. 영주관 문짝 높이와 시장 회관의 층고를 성인 기준으로 다시 대조하여 전체 축척을 보정했다. 다리 예배당은 경간과 사람 크기를 동시에 유지하기 위해 예배당 크기만 지정하여 완성 그림을 재생성했다.
