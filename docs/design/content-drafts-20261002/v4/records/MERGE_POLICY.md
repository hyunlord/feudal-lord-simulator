# 병합 판정 규칙

- 200개 ID 보존. A의 등록기 필드·명령·바인딩 계약을 기본으로 사용한다.
- B는 49개 delta, v3는 15개 delta이므로 원본 60개를 대신하는 전집으로 읽지 않는다. A→v3 판단→v3.1 판단을 의미 단위로 비교하며 기계적 덮어쓰기를 하지 않는다.
- 보편적인 영지 행정은 1300~1450으로 넓힐 수 있지만 역병·왕실의 특정 조세·법령처럼 역사 사건에 묶인 창은 근거 없이 넓히지 않는다.
- 등식 문턱은 실제 명령 범위와 선택 전후 변화가 살아 있는 구간으로 바꾼다. 봇의 800‰/1100‰ 사례를 포함하는지 별도로 검토한다.
- 소송 상시는 열린 실제 대상·단계·미결 조건을 없앤다는 뜻이 아니다. 존재하는 소송 단계에서 연도 창 때문에 막히지 않게 한다.
- 직접 감독 감사도 실제 감사·담당자·후임·처분 가능 조건을 지킨다. 없는 필드나 의미가 다른 명령으로 대체하지 않는다.
- 이미 같은 값을 다시 쓰는 선택은 변화로 세지 않는다. 의도적인 보류는 그대로 표현한다.
- 분할 장려금은 등록기의 실제 원자성 계약을 재확인한다. 과거 v3의 비원자성 경고를 현행 확인 없이 적용/삭제하지 않는다.
- 감사 회수·관계·충성 후처리를 중복 효과로 더하지 않는다.
- 019는 성향, 031은 위임 중 교체, 059는 직접 감독에서 위임으로 구분한다. ID 삭제·합병하지 않는다.
- 스키마 검증과 실제 게임 노출 빈도 검증은 구별한다. 후자는 이번 편집 결과만으로 통과라고 주장하지 않는다.
