# RB-WORLD-FIRE: 집의 화재와 물동이 무리

실제 장면10쌍·기하80조건 실패0을 확인했다. 구현 후보 `74fe1398`, 가림 수정 `ee3f0249`, 기준 본선 `9a48931d`. [선택·배치 계약](CONTRACT.md) · [원본 대조](provenance.json).

여름·겨울 물동이 무리 두 장과 4프레임 불길 한 장을 기존 사건 연출 계약에 연결했다. 불타는 집 앞에 작은 불길이 움직이고, 실제로 물을 공급하는 중이며 빈 공간이 있을 때 사람 무리가 나타난다. 기존 지붕 불·연기는 유지한다. 화재 발생·피해·주민 수·진화 규칙은 바꾸지 않는다.

## 장면과 한계

원래 게임 저장에서 집 한 채와 우물 하나를 통제된 빈 마당으로 옮긴 준비 장면이다. 급수 전·급수 중·진화 뒤, 여름·겨울을 비교한다. 급수 중은 줌 0.6·1.0·1.4, 나머지는 줌1.0으로 총10쌍이다. 확대 급수 장면은 계절마다110ms 대기 뒤 캡처하는 방식으로8프레임도 남겼다. 실제 첫·끝 기록 간격은 여름2.906초·겨울3.159초로, 캡처 비용이 포함되며 성능 측정이 아니다. 실제 게임 렌더로 촬영하되, 자연 플레이에서 이 배치나 겨울 화재가 발생한 증거로 쓰지 않는다.

안전한 빈 공간이 없는 밀집 시가지에서는 새 무리를 생략하고 기존 물통을 유지한다. 정적인 사람 무리이며 걷거나 실제 물을 운반하는 개별 주민 동작을 추가한 것은 아니다. 불길은 움직인다. 정상적인 연기·바람 등 벽시계 애니메이션 때문에 전후 전체 픽셀 차이를 새 그림만의 변화로 세지 않는다.

이전 후보의 변경 시험 전송 `astra-WORLD-FIRE-tests-74fe139`는 실행 전에 취소했다. 최종 내용의 영수증으로 대체하므로 중복 시험을 기다리지 않는다. 본선의 새 변경 시험 영수증 규칙을 병합했다. 게시 검사는 최종 문서까지 포함한 정확한 tree 영수증을 사용하며, `astra-WORLD-FIRE-final-tests` 실행의 실제 이름·수치·영수증을 보고ZIP에 남긴다. 엔진 변경이 없어 성장 가드레일은 해당하지 않는다. 깨끗한 클론 전체 시험은 RR16에 따라 게시를 막는 조건이 아니다.

## 원칙과 판단

- P-V1: 실제 활성 화재·급수 사실을 읽어 연출한다. 종료 틱 이후 새 연출을 남기지 않는다.
- P-V2: 7인 무리는 원본 성인50±5px를 세계17.6±1.76px로 줄이며 최대5무리다. 전체 발밑이 비어 있어야 한다.
- P-V3: 실제 여름·겨울 줌1.0/0.6에서 무리가 집 뒤에 숨지 않고 빈 지면에 서며, 기존 건물·밭을 침범하지 않는 것을 확인했다. 확대1.4도 확인했다. 0.6에서는 사람 행렬만 읽히며 개별 물동이 동작은 확실하지 않다.
- P-M1: 팩 id core, 그림·피벗·계절·프레임은 데이터 계약이다.
- P-X1: 렌더는 엔진 상태를 변경하지 않는다. 상태 불변·기한·로딩·깊이·벽·생산 구역 시험을 통과했다.

경계 파일 수정: drawBuildings·drawObjectRenderItems·objectRenderTypes·objectRenderSort·renderObjectFrameCache는 기존 세계 대열 연결점이다. 새 종류와 같은 프레임의 표시 영수증만 추가했다. UI 입력 파일과 엔진 파일은 건드리지 않았다.

첫 실제 이후 촬영(`astra-WORLD-FIRE-afterlight-4f8d331`)에서 무리가 집 지붕 뒤에 가려졌다. 바닥이 비어 있다는 검사만으로는 충분하지 않아, 불타는 집 앞쪽 깊이의 빈 자리를 고르게 수정했다(`ee3f0249`). 새 회귀 시험은 수정 전 실패·수정 뒤 통과했으며 관련18개 시험을 통과했다. 옛 기하 실행은 명령 시작 전 대기열에서 종료하고 수정 입력으로 다시 등록했다. 최종 시각 판정은 새 촬영만 사용한다.

## 본선 병합 뒤 재확인

본선의 크기 가드 복구를 받아 `buildingAppearance.ts`에 기존 무리 표시 영수증을 그대로 전달했다(`b3a7484d`). `astra-WORLD-FIRE-merged-view-b3a7484`에서 같은 저장·상태·카메라10쌍과 계절·급수 분기를 다시 확인했고 브라우저 오류는0이었다. 여름1.0과 겨울0.6 실제 화면에서도 무리가 지붕 앞 빈 땅에 남았다. 원래 전후 캡처를 대체해 숨기지 않고 재촬영 결과를 보고ZIP에 추가한다.

추가 집중 검사에서 프레임 캐시251줄이 기존250줄 가드를 넘는 것을 발견했다. 큐 병합·깊이 비교기를 동작 그대로 `objectRenderMerge.ts`로 분리하고 새 파일에도 같은 가드를 적용했다(`cf0ffec7`, `d63bea5c`). 관련32시험·타입·린트를 Mac에서 통과했다. 기존 비교기의 깊이·가로 앵커·id 순서는 바꾸지 않았다.

일반 대기열의 `astra-WORLD-FIRE-geometry2-ee3f024`는 사용자 지시에 따라 실행 전에 취소하고 게시용 gate로 옮겼다. 첫 gate `astra-WORLD-FIRE-gate-b3a7484`도 크기 가드 수정 중 실행 전에 취소했다. 최종 판정은 tracked dirty=0인 `astra-WORLD-FIRE-gate-final-d63bea5`만 사용한다.

기하 결과는80조건·실패0·미열림0이다. 최신 본선6d493e33 병합 뒤에도 입력 해시 `2de027e50cce22d1c17d1efd807693ba46562b89d7cb9cb85329f558d805951a`가 같아 결과를 그대로 사용한다. 크기 가드와 감사 규칙을 완화하지 않았다.
