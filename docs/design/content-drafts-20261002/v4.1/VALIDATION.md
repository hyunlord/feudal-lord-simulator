# 검증 결과

## 데이터 계약

v4 원고와 등록기 Schema의 레코드 형식을 유지했다. delta의 항목 수16, number 상한215만 범위에 맞췄고 Schema 검사와 ID·선택·역사 출처·맥락 키 구조 검사를 `validate.sh`로 수행했다(2개 Schema, 구조·증거 해시 단언249개).

- 변경16: 기존011 수정1 + 추가201–215의15.
- v4와 가상 병합215건, 기존 다른199건 보존.
- 신규 구성: 도시6·자연4·세력5.
- 각 원고 선택과 실행 선택 ID 일치, 최소 실효 선택2 정책 유지.
- 신규 상태·효과 명세 추가 없음. `unsupportedFilters` 없는16건을 실제 실행기로 검사.

## 실제 엔진 실행

LM-E9b 소스 복사본을 외부에서 번들링하고 생성 데이터 모듈 두 개만 **메모리에서** v4+delta로 대체했다. 원 저장소나 생성 파일은 쓰지 않았다. 단위 상태는 실제 저장 fixture에 조건별 합성 압력을 넣은 것이다.

## 수정 후 재검증한 발견

- 011 없는 파생 함수와 실제 바인딩에 없는 반복 키.
- 좌판세 조정에 권리 할인 함수를 잘못 읽던 초기안: agency.duesPermille로 변경.
- 우물 후보의 잘못된 discriminant `.type`: 실제 `.kind`로 변경.
- 우물 기존24/48을 새 비용 증가처럼 보이던 초기안: 기존값<24만 허용.
- 도시/세력 여름 일손 중복: 봄/여름으로 나눔.
- 일반 목재 수요를 자연으로 세던 초기 분류: 도시로 변경.
- 현 정책을 그대로 둘 길이 없는 반복 질문: 실제 R3 관계 대가가 있는 보류 추가.

독립 편집 검수는 최종 데이터에서 **PASS(문구·AST 의미 정합 범위)**. 별도 엔진 검사와 혼동하지 않는다.

## 증거가 말하지 않는 것

- v4.1 125년 seed1–3의 실제 분포·빈 해·연간30미만·성능·세이브 장기 회귀는 측정하지 않았다.
- 브라우저 카드 그림·렌더·UI 플레이 검증을 하지 않았다. 사용자의 요청은 콘텐츠 데이터이며 게임 설치는 금지돼 있다.
- 기존 분포 JSON은 엔진 담당자의 이전 v4e 실행이다. 새 실행처럼 표기하지 않았다.
- 후보를 일부 합성한 단위 검사는 실제 세계가 그 맥락을 얼마나 자주 만드는지 증명하지 않는다.
