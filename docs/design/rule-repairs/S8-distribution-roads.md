# R-8: 반복 배급 부족 가구의 곡창 진입로 복구

## 재현과 판정

`403cfa9` seed 5 자연 체크포인트 600,000틱에서 집 `construction-site-000062`는 기존 실제 최단 배급 거리가 33칸으로 범위 40 안이었다. 하지만 배급 간격이 1,230~1,660틱까지 벌어져 빵 0과 승급 유지 시간 초기화가 반복됐다. 곡창 7개 상한 때문에 새 곡창을 만들 수 없고, 기존 도로 복구는 연결 끊김만 처리해 이 경우에는 도로를 제안하지 않았다. 가까워 보이는 곡창 #39의 기존 출입구에서는 78칸이었다.

자연 원본을 실제 엔진으로만 5,246틱 진행해 기존 반복 관측이 처음 확정된 605,246틱을 파생 fixture로 보존했다. advisor·자원 주입·배치 편집은 없었다. 원본과 파생 해시·경로 메모 최적화가 포함된 작업 소스라는 제한은 `tests/fixtures/distribution-roads/README.md`에 있다. 이 파생 상태에서 수정 전 전체 advisor는 건물 조치를 선택했고, 도로 조치 기대 테스트는 실패했다. 이를 무조치 상태라고 부르지 않는다.

## 규칙과 구현

`autoplayDistributionRoads.ts:distributionRoadRecoveryAction`은 기존 반복 배급 관측의 qualified 또는 deficientSince와 현재 경로 identity가 일치하는 실제 입주 가구만 다룬다. 가동·필수 인력·사용 가능한 빵을 갖춘 완공 곡창에서 새로운 출입구도 후보로 보며, 가구와 곡창 조합은 결정적인 순서로 최대 24개다. 상한 또는 공통 검색 예산이 끝나면 불완전 판정을 표시한다.

실제 주택 접점에서 잠재 곡창 접점까지 기존 도로/벽/다리 통행 규칙으로 탐색한다. 후보 전체를 정상 `placeRoadLine`으로 투영하고 **각 접두 도로마다** `serviceSafeRoadAction`으로 미래 서비스 자리를 보호한다. 최종 실제 배급 거리가 도시의 기존 최단 거리보다 짧고 40칸 이내일 때에만 첫 도로를 반환한다. 매 결정에서 전체 증명을 다시 하므로 저장 계획·새 캐시·GameState 필드를 추가하지 않는다. 경제·시설 상한·배송·벽·도로 규칙은 바뀌지 않는다. 기존 `food_route_repair` 진단을 사용한다.

## 검증과 한계

전체 advisor와 실제 reducer가 120틱 간격으로 605,246 / 605,366 / 605,486틱에 총 17칸을 세 도로 명령으로 놓았다. 첫 두 명령만으로는 거리가 줄지 않지만 전체 투영 증명 후 실행한다. #39의 거리는 78→19칸, **도시 최단 거리는 33→19칸**이 됐다. 곡창 수는 7개로 유지됐다.

파생 상태에서 실제 advisor를 계속 실행한 24,000틱 재생(629,246틱 종료): 대상은 L1→L2→L3, 첫 L3는 626,470틱(시작 후 21,224틱), 마지막은 L3·빵 6·승급 진행 1,216틱이었다. 6,000틱별 빵 0 틱 수는 217 / 0 / 71 / 62다. **배송 거리와 승급 진전은 개선됐지만 빵 부족 완전 해소나 L4·24,000틱 안정 달성은 입증되지 않았다.** 618,000틱 표본은 마지막 배급 617,031틱, 626,800틱 표본은 마지막 배급 625,771틱으로 여전히 배급 사이에 재고가 소진됐다. 새 출입구가 실제 배급 수레의 이동·귀환에 사용되는 것도 마지막 상태에서 확인됐다. 공유 배급 경합의 구체 원인은 후속 읽기 전용 진단으로 남긴다.

실행 로그: `/tmp/r1-distribution-replay-{0,1,2,3}.json`, 최종 `/tmp/r1-distribution-replay-state.json`. 관련 회귀 16/16, typecheck 통과, diff 검사 통과. 부정 검사는 정상 관측, 휴업·인력 부족·빵 없음, 기존 최단보다 개선 없음, 폐쇄 성벽·예정 건물 점유, 예산 0의 미완성 증명 거부를 다룬다. 미래 서비스 자리 보전 기존 회귀도 함께 실행했다. 새 게임 5seed와 마지막 커밋 전체 회귀는 별도 최종 관문이다.
