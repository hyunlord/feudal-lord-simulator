## 적용과 검증

- 변경은 세 레코드의 `sender`뿐이다. 발동 조건·창·선택·효과·등록기 entries는 그대로다. 역할 표기에서 대표 화자를 한 명으로 명확히 했다.
- 실제 매핑: `src/content/registry/registryHoldCopy.ko.ts:6`의 `교회→bishop`, `도시 공동체→town`. 보류 비용은 `registryHoldConfig.ts`의 `HOLD_RELATION_DELTA=-2`. 기존 매핑만 사용한다.
- `scripts/buildRegistryV4.ts:57`은 sender.faction에서 senderFaction을 생성한다. 통합 담당자가 원고3건을 병합하고 기존 생성기를 다시 실행해야 런타임 복사본에 반영된다. 이번 납품에서는 생성기 실행·설치·코드 수정·커밋·푸시를 하지 않았다.
- 보류 관계 비용은 기존 엔진 경로가 한 번 적용한다. 새 faction_relation 효과를 추가하지 않는다. 본문의 다른 등장인물이나 수혜 집단에 비용을 나눠 부과하지 않는다. 기존 명시적 no_op 선택 문구를 새 관계 효과로 덮어쓰지 않았다.
- 원래 v4.1 레코드 스키마로3건 개별 검증, 패치 스키마로 배열 검증 통과. 배열 건수 제한만16→3으로 조정했고 레코드 계약은 동일하다. 원본 대비 sender 외 차이0. 게임 실행 결과는 미검증.
