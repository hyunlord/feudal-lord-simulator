## 1. 원인
- `src/render/presentation/presentedState.ts`의 `PREVIOUS`는 WeakMap이었다: 열쇠 = 지금 상태, 값 = `{ previous, value }`. 스토어가 넘기는 `previous`는 앞 틱의 게임 상태 객체 그대로이고(`gameStore.ts` `previousRenderStateRef` = `action.previousState`), 그 객체가 바로 앞 칸의 열쇠다. WeakMap의 값이 다른 열쇠를 강하게 쥐니, 가장 새 상태 하나가 살아 있는 한 모든 지난 상태가 사슬로 붙잡혔다(SMOOTH-G: 2분에 15,625개, JS 힙 465 MB).
- `PRESENTED`(상태 → 그리는 상태)는 같은 모양이 아니다: 값은 그 상태 자신이거나 그 필드의 얕은 복사(`{ ...state, walkers }`)라 다른 열쇠를 쥐지 않는다 — 그대로 두었다. 아래 측정에서 상태 수가 상수로 나와 이것도 확인됐다. 주민 걸음 캐시(`residentTrips.ts`)는 틱 넷까지만 쥔다.

## 2. 고친 것
- `PREVIOUS`를 한 칸짜리 캐시로: 열쇠는 두 틱 번호(앞·지금)와 같은 두 상태(한 틱 안의 플레이어 행동은 같은 틱의 새 상태를 만든다 — 틱만으로는 그 전 답을 돌려주므로 객체도 본다). 값에 앞 상태를 담은 칸이 하나뿐이라 붙잡는 것은 그리는 한 쌍뿐이다.
