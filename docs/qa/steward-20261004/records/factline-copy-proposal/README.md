## 이름·ID·숫자 계약

- template ID, callback 인수, `n`, `s`, `moneyWords`, `estateWord`, `josa` 호출과 모든 `${...}` 표현식을 순서까지 그대로 보존했다.
- stewardship.began의 `stewardId` 저장과 FIX-12 읽을 때 이름 해석은 `history.ts:865–890,925–936`의 기존 경로를 그대로 사용한다. 이름을 새로 저장하거나 고정 문자열로 대체하지 않는다.
- households는 누계라는 의미를 명시한다. cost는 설정금액이라는 의미를 명시한다. backlash는 기존 숫자를 그대로 보여 준다. 새 수치 계산·상태 분기·동기 추정은 없다.
- context가 없거나 unknown인 과거 기록에도 이 중립 사실줄이 적용되도록 제안한 전역 문구 변경이다. 과거 저장자료를 고치거나 이미 저장된 자유문자열을 마이그레이션하는 작업은 포함하지 않는다.

## 검증과 한계

`ruby build.rb`는 원문 대조, 14개 패치 생성, **이 폴더의 application-check 복사본에서만** git apply --check 및 실제 적용, 예상 결과 일치를 확인한다. `ruby validate.rb`는 소스 8개 파일·원문 구간의 SHA/내용, 수정 14줄 외 보존, 함수/ID/보간식 보존, 확정 보류 23개와 정확한 대응을 확인한다. 원래 저장소를 편집하는 명령은 없다.

원래 과장된 문장으로는 빈집의 포만·재혼 미확인·누계와 개별 전이·설정금액과 실제 지급·목책 공사 착수와 완공이 구분되지 않는다. 위 소스 반례가 교정의 근거다. 런타임을 만들어 가정한 결과가 아니다.

**패치를 채택해도 보류 23개가 자동 해제되지 않는다.** 독립 검수자는 실제 후보 headline과 새 사실줄의 조합을 재검수해야 한다. 새 context 캡처/엄격 schema/저장복원/읽기 시점 이름 계약은 각 후보의 기존 통합 조건으로 남는다. 기존 보류 인덱스를 이 작업에서 수정하지 않았다. TypeScript 컴파일·formatter 실행·UI·자연 발생·저장복원은 실행하지 않았다.

omo:programming과 TypeScript 기준을 읽었으며, 이번 허가 범위는 패치 산출물과 경량 텍스트 확인이다. 엔진 코드 설치나 formatter 실행으로 범위를 넓히지 않았다. graft 2회가 보고한 절약 추정치 합계는 80,174 tokens. 최종 판단은 실제 소스 원문을 다시 읽어 확인했다.
