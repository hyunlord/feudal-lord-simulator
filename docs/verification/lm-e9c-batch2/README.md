## 청원 생명주기와 제한

057·058은 일반 달력 청원 목록에 추가하지 않는다. 등록기에서 뽑힌 뒤에만 청원을 남기고 두 응답 경로가 같은 마감·응답 상태를 공유한다. 일반 청원 카드와 중복 노출하지 않으며 만료·세력 관계·결정 기록을 이중으로 적용하지 않는다.

v4.2 HOLD38과 이전 선택 보류는 그대로다. 새 무게 데이터가 큰 지출·세력 결렬의 동적 판정을 덮지 않는다. 엔진 저장 형태·코어 틱·인구·물류·공용 관문은 변경하지 않는다.

세 문구 변형은 현재 엔진 읽기 API만 제공하며 화면 소비자는 아직 없다. 렌더 레인 인계가 필요하다. 따라서 API 연결 수 3건을 켜진 사건 수나 플레이어에게 보인 문구 수로 세지 않는다.

## 검증 계획과 관측 범위

- 집중 시험: 청원 후보의 무변경, 선택된 청원만 보존, 응답/만료 중복 방지, 저장 왕복, 승계 기록 연결, 원래 당사자·원인 소멸 시 거부.
- 정확한 누적 집합: Engine B 독립 11건·문구 변형 3건. 전체 정적 지원 56건. 아직 실제 발생 횟수가 아니다.
- 1300–1320의 자연 20년 판에서는 147(1348–1355)과 080(1430–1450)의 창에 도달하지 않는다. 080은 마지막 1300–1425의 125년 판에서도 관측할 수 없다. 달력을 바꾼 준비 상태 시험을 자연 발생으로 기록하지 않는다.
- 게시 전 Mac EVA-AUTO, 정확한 최종 트리 test:changed, check:merge 및 변경된 카드 줄 기하 감사 필요. 원격 무거운 게시 관문만 --gate이며 20년 판은 --experiment다.

관련 원칙: P-M1 실제 세계 사실, P-C 원인 연결, P-D5/P-T3 결정의 층, P-T1/GP-7 실제 영주 결정 수와 전체 명령 수의 구분. 미관측 상태와 API-only 인계를 숨기지 않는다.
