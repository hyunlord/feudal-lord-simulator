# WALL-CHECK 보고서 — 서비스 자리를 깨뜨린 헌장 성벽이 왜 깔렸나(진단만)

관문: 진단 완료 — 검사의 버그가 아니다(구간을 따로 보지도, 성벽 칸을 빼지도 않는다). 마을의 성벽 찾기는 서비스 자리 검사로 8개 성벽을 모두 거절했고, 그러면 GROW-BLOCK-2a ①의 갈래가 "규칙만 맞는 가장 가까운 성벽"(`ruledCharterWall`, 서비스 자리·방 검사 없음)을 영주에게 청한다. 계획을 지키는 성벽은 있었으나(17개 중 5개, 그중 하나는 방·길까지 통과), 찾기의 시도 수(64·8)로는 나오지 않는다. 고칠 곳 하나: `autoplayEra.ts`의 그 갈래(영주 모드).

- **지시**: 사용자 판정 2026-10-23(Mac, 실험 칸 없이, 고정물 둘로; 검사의 버그면 작은 고침, 두 모드면 RR30 판정).
- **고정물**: `fixtures/lots/seed39-before-wall-37987-foodpre.save.json.gz`(성벽 직전), `…-wall-37987-…`(직후). 탐침 `scripts/wallCheckProbe.ts`. 실행 Mac.

## 고칠 곳 하나
`src/engine/autoplayEra.ts` GROW-BLOCK-2a ① 갈래(영주 모드만, `state.agency !== undefined` 안): 규칙만 맞는 성벽을 청하기 **전에**, 더 긴 찾기(시도 200 안팎)에서 서비스 자리·방·길을 지키는 성벽을 찾아 있으면 그것을 청한다. 없을 때만 지금처럼 `ruledCharterWall`. 샌드박스 봇의 찾기(시도 64·8, 검사 8)는 그대로라 두 모드에 걸리지 않는다(RR30 목록 갱신 없음).
- 값: Mac에서 성벽 하나의 서비스 자리 검사 약 0.4초(17개 7.5초). 이 갈래는 찾기가 실패한 걸음에서만 돈다.
- WALL-PLACE(성벽 놓기 자체를 다시 봄)와의 관계: 이 고침은 "계획을 지키는 성벽이 있는데 못 찾는" 경우만 메운다. 그런 성벽이 아예 없는 마을은 여전히 규칙만 맞는 성벽을 받는다.
