# 기록·연대기 설계서 v1 — "모든 것이 남는다"

작성 2026-09-26 · 사용자 요구: 내 결정·과정·결과가 전부 상세히 남고, 인물마다 살아온 역사가 있고, 다른 영주·상위 영주·국왕·대상인·종교 지도자 같은 세력도 각자 연대기가 있어서, 언제든 "그때는 어땠나"를 글과 그림으로 볼 수 있어야 한다.
참고 사례: Dwarf Fortress Legends(세계 전체의 기록 열람), Crusader Kings(인물 전기·가문·관계), RimWorld 역사 탭, Kingdom Come 코덱스. 우리 게임은 이 셋을 **한 도시와 그 주변 세력의 150년**에 맞춰 축소·집중한다.

## 0. 원칙
1. **기록은 나중에 붙이는 기능이 아니라 데이터 뼈대다.** 지금부터 모든 상태 변화가 `SourceRef`(B1)로 원인을 갖고, 그중 "이야기가 되는 것"이 기록 원장에 남는다. 나중에 소급할 수 없다 → **F0에서 원장을 만든다.**
2. **세 층의 기록**: 도시 연대기(무엇이 일어났나) · 인물 전기(누가 어떻게 살았나) · 세력 연대기(주변 세계는 어땠나). 셋은 같은 원장을 다른 축으로 본 것이다.
3. **결정은 대안과 함께 남는다**: 무엇을 골랐고, 다른 선택지는 무엇이었고, 예측과 실제가 어떻게 달랐는지.
4. **글 + 그림**: 기록마다 삽화 키(Wave 16·17 삽화, 초상, 문장)와 **그때의 지도 축소판**이 붙어 "그때 화면"을 볼 수 있다.
5. **읽을 만해야 한다**: 원장은 전부 저장하되, 연대기 화면은 중요도로 걸러 보여 주고, 원하면 전부 펼친다.

## 1. 기록 원장 (History Ledger) — 엔진
```ts
type HistoryRecord = {
  id: string; tick: number; date: {year, season, day};
  kind: "decision" | "event" | "person" | "faction" | "era" | "milestone" | "ledger";
  subject: ActorRef;                // 도시 | 인물 id | 세력 id | 가문
  actors: ActorRef[];               // 관련 인물·세력
  place?: {tile, buildingId?};
  cause?: SourceRef;                // B1 출처 추적
  summary: string;                  // 한 줄(한국어 문장 생성 규칙, *.ko.ts)
  detail?: Record<string, number|string>; // 수치(손실 가구 3, 금고 −40 …)
  decision?: { chosen: string; alternatives: string[]; predicted: Record<string,number>; actual?: Record<string,number> };
  severity: 0|1|2|3;                // 연대기 필터 단계(0 일상, 3 시대급)
  illustration?: string;            // 삽화 키
  snapshotId?: string;              // 지도 축소판
};
```
- **원천**: ① 플레이어 명령 전부(건설·구역·선포·청원 응답·대기근 대응·가동 중지 등) = `decision` ② 사건(F0-B)·시대(F0-C1) ③ 인물 생애 사건(출생·성인·혼인·직업·이사·병·사망·청원 참여·이탈) ④ 계절 결산의 큰 변화(인구 ±, 금고 ±, 등급 변화) = `ledger` ⑤ 세력 사건(E단계) ⑥ 이정표(첫 방앗간·목책 선포·시장도시·석벽 등).
- **저장**: append-only, 저장 파일에 포함(v15). 150년 캠페인 예상 1~3만 건 → 압축 저장(요약 문장은 저장 시 재생성 가능하게 템플릿 id + 파라미터로 저장).
- **지도 축소판**: 계절마다 128×128 미니맵 래스터(구역·건물·도로·물)를 원장에 첨부(600장/캠페인, 약 10MB). 시대급 기록엔 256×256 추가.
- **인물 생애**: `PERSON-0`(F1)에서 인물 id가 생기면 `person` 기록이 붙는다. 그 전(F0)에는 **가구 id** 단위로 남기고, 인물이 생기면 가구 기록을 가구주에게 귀속.

## 2. 세 화면 — 렌더
### 2.1 도시 연대기(타임라인)
- 상단: 1300→1450 연대 띠, 장·시대 구간, 시대급 기록 아이콘. 확대하면 계절 단위.
- 본문: 기록 카드(날짜·삽화·한 줄·수치·[그때 지도]·[관련 인물]). 필터: 종류·심각도·인물·세력·장소.
- "그때 지도" 클릭 → 축소판 + "이 위치로"(현재 지도로 카메라).
- 장 끝 연대기 한 쪽(F0-C1)은 이 원장에서 **자동 편집**된 요약본이다.
### 2.2 인물 전기
- 초상(풀·노화 단계 현재), 이름·역할·가구·집, 생애 연표(출생~현재/사망), 관계(가족·고용·청원 동료), 이 인물이 관련된 결정·사건 링크, 문장·상인 표식.
- 사망 시 마지막 항목과 유족·상속.
### 2.3 세력 연대기
- 세력마다 페이지: 문장·수장 초상·현재 관계(우호~적대 척도)·요구/약속 목록·**우리와의 사건 연표**·그 세력 자체의 연표(외부 세계 사건).
- 세력 종류(E단계 설계): 상위 영주(백작), 국왕과 왕실 관리, 인접 영주 2~3, 주교·수도원, 대상인 가문·외지 상인, 도시 공동체(부르주아), 농민 공동체. 각자 이해·기억(원한 기록)·연대기.
### 2.4 결정 기록
- "당신의 결정" 목록: 언제·무엇·대안·예측·실제·후속 사건. 대기근 대응·청원 응답·석벽 선택 같은 큰 결정은 카드로, 배치 같은 잦은 결정은 계절별 묶음.

## 3. 로드맵 위치
| 단계 | 작업 | 내용 |
|---|---|---|
| **F0** | **F0-C2 기록 원장 v0**(엔진) | HistoryRecord·append-only 저장·원천 ①②④⑥ 연결·계절 미니맵 스냅샷·장 끝 연대기를 원장에서 생성 |
| F0 | UI-4에 포함 | 연대기 페이지에 타임라인 v0(장 단위) |
| F1 | PERSON-0 + **CHRON-1**(렌더) | 인물 생애 기록·인물 전기 화면·결정 기록 화면·"그때 지도" |
| E | RIGHTS + **CHRON-2** | 세력 시스템(수장·관계·요구·기억)과 세력 연대기, 외부 세계 연표(왕위·전쟁·역병) |
| E | LEGACY | 캠페인 끝 유산 = 연대기 전체를 책으로(내보내기) |

## 4. 결정 필요
- 저장 크기 상한(원장+스냅샷)과 오래된 일상 기록의 자동 요약 시점.
- 외부 세계 연표를 고정(역사 그대로)할지 seed로 조금씩 흔들지.
- 인물 이름 생성(세례명·직업 성) 규칙과 겹침 방지.
