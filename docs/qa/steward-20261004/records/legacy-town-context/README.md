## 근거와 만들지 않은 분기

`legacyInterludes`는 장 시작보다 뒤인 정해진 날짜의 사건만 열고, 1394년 사건은 길드 존재 여부에 따라 길드 다툼 또는 장터 화재 하나를 선택한다. 길드가 없어서 실제로 화재가 일어났다는 역사 인과를 쓰지 않는다. 날짜로 임의 도시의 번영·특권·건축 양식을 추론하지도 않는다.

- staple의 가격배수는 설정된 **게임 효과**다. 실제 직물 거래·이윤의 발생이나 영국 경제 전체의 실제 변화라고 쓰지 않았다. 발생 시점 buildings의 weaver_house만 비교하며 공사장이나 현재의 작업장을 과거에 덧씌우지 않는다. 직조공 개인이 한 명도 없다는 뜻도 아니다.
- 길드는 실제 guild record가 있어야 다툼이 기록된다. 수장 ID/null은 당시 기록 상태만 뜻하며 사망·정통성·갈등의 원인을 만들어 내지 않는다. 개인 이름을 고정하지 않는다.
- `post`는 금고 한도 내에서만 지출한다. 장터 화재는 설정 수리비150을 전액 지급했다는 보장이 없고, 교회 증축 비용300도 동일하다. 두 이벤트의 정확한 post 반환 moved와 sourceRef를 캡처해야 한다. 해당 틱 금고 총변화는 다른 지출이 섞일 수 있어 사용할 수 없다. 미지급분이 자동 채무로 남는다는 문장은 쓰지 않았다.
- 화재 사건은 돈을 지출할 뿐 이 함수에서 실제 건물을 태우지 않는다. 화재 구역·불탄 집 수·인명피해 분기는 **실제 변수가 없어 작성하지 않았다**. 일반 화재 시스템 자료를 이 사건에 임의로 연결하지 않는다.
- naveRebuilt는 답변 승인 직후 true가 된다. 물리 공사장·단계·기간을 확인한 코드가 아니므로 **건설 진척·완공 기간 변형은 작성하지 않았다**. 원문15개 중 해당3개는 ‘기록되었다’와 실제 지급을 구분한다.
- 교회 청원의 금고 분기는 요청 시점 감당 가능성만 뜻한다. 청원 수락·돈 예약·나중의 지급·인부 확보를 보장하지 않는다.
- 폐위의 국왕 교체 기본 사건은 고정이다. 추가 문장은 factions.ts:423–431의 시작 관계로 절반 되돌리는 해당 조정값만 설명한다. 다른 사건까지 합친 최종 관계 차이와 혼동하지 않는다. 영주 충성심에 대한 보상·처벌이나 역사적 폐위 원인을 추측하지 않는다.

## 조합 사실 줄 보류

ADOPTION_LIMITS.json의 **6개**: 장터 화재3·회중석 증축3이다. 전자는 기본 사실 줄의 수리비 설정값과 실제 지급액을 구분해야 하고 실제 불탄 건물의 범위를 보증해서는 안 된다. 후자는 기본 사실 줄 ‘새 회중석이 섰다’와 즉시 flag만 세우는 엔진 상태의 차이를 최종 출력에서 검토해야 한다. 원고 headline과 기본 줄을 함께 읽는 검수 전까지 채택을 보류한다. 엔진 기본 줄이나 로직은 수정하지 않았다.

다른9개도 캡처가 검증되었다는 뜻은 아니다. 모든 후보는 발생 당시 정확한 record/campaign에 결합된 문맥을 요구한다. unknown fallback이 기본 사실 줄의 기존 문제를 고치지는 않는다.

## 엄격한 선택 계약 및 검사

CONTEXT.schema.json은 template별 필드와 enum, 추가 키 금지, 양식·safe tick·sourceHead·provenance·known/unknown을 검사한다. 참조 selector는 schema를 먼저 적용하고 recordId·tick·campaignId·template·sourceHead를 실제 선택 대상과 비교한 뒤에만 조건형을 쓴다. 없는 캡처를 현재 인물·작업장·금고·관계에서 복원하지 않는다. referenceVerified=true라는 값 자체는 역사적 사실의 증명이 아니며 캡처 구현의 별도 검증이 필요하다.

FIX-12: 새 이름 문자열·슬롯을 만들지 않고 기존 필수 history.summary(record,state)를 유지한다. 길드 수장 상태는 사건 때 고정하지만 후속 인명 표시는 stable ID를 사용해 읽을 때 조회해야 한다. 문구에 특정 이름을 박아 넣지 않았다.

`ruby validate.rb`:15개 정상·180fallback의 selector195건, schema 음성210건, 소스9파일·14구간 SHA/원문,15ID유일성·기준650 불변. schema_validator.rb는 사용된 schema 키워드의 경량 부분 구현이지 JSON Schema 전체 인증이 아니다. 실제 숫자·상태→enum 캡처,저장복원,엔진,이름 formatter,UI는 미실행이다. 일부/0지급이 자연 플레이에 얼마나 발생하는지도 미측정이다.

`build.rb`가 재현 작성기다. `prepare.rb`는 office-context 작성기의 형식을 가져와 이 6유형 전용 build를 만든 도구로, 다른 폴더에는 쓰지 않는다. build/validate 실행 후 SHA256SUMS를 갱신해야 한다. 독립 검수 대기이며 정본 수량에 합산하지 않는다.

새 역사적 주장은 추가하지 않았다. 기존 기본 역사 사건을 그대로 두고 현재 코드로 입증한 게임 문맥만 추가했다. 출처는 SOURCE_EVIDENCE.json과 용어 정본이다. graft1회, 추정 절감52,853 tokens(달러 미제공).
