# 사용자 목표 독립 검토

판정: PASS. 현재 코드, 최종 자연 엔진 결과, 실제 UI 상호작용 기록, 최종 대표 화면을 대조했다.

## 목표별 확인

1. 도로·성벽이 건물을 부자연스럽게 덮지 않기: `drawObjectRenderItems.ts`는 도로 재출력을 입체 객체 큐 앞으로 이동했다. `drawBuildings.ts`와 `occlusionModel.ts`는 일반 모드 자동 반투명을 제거하고 명시적인 윤곽 모드는 유지했다. 성벽을 무조건 뒤로 보내지 않으므로 앞쪽 벽의 정상 가림은 보존된다. 담당 렌더 검수의 240조건 매트릭스는 합성 상태임을 명시한다. 본 검토는 해당 코드와 기록을 대조했으며 렌더 검사를 직접 재실행했다고 주장하지 않는다.
2. 논리 중첩 방지: 공사장 누락 결함을 독립 발견·재현하고 수정 후 재현까지 완료했다. 양측1칸 간격 승인, 양측 접촉 거부, 목책/석벽공사 제외가 통과했다. 자세한 근거는 placement-review.md. 최초 관련79검사 및 수정 후19검사를 독립 실행했다.
3. 남은 도시 성장: `autoplayServices.ts`는 실제 미공급 원인으로 도로 복구/시설 확대를 판단하고 공사중복·인력부족 복제를 피한다. `autoplayCivicReserve.ts`와 `marketSettlement.ts`는 교회 수요/공사 자재가 자동 판매되어 건설이 막히는 상호작용을 교정한다. `tick.ts`는 최신 공사 배송·예약 상태를 판매 판정에 전달한다. `autoplayFoodPlacement.ts`는 후기 식량 시설을 곡창과의 실제 도로 경로로 비교한다. 자연 장시간 검증은 아래 최종 결과에 추가한다.
4. 시스템 설명: `docs/TOWN_SYSTEMS_V2.md`의 인력→생산→물류→배급→주택→노동력 흐름, 공공서비스/시장판매/곡창배급 구분은 현재 코드와 일치한다. 물·예배·쇼핑을 주민별로 구현했다고 과장하지 않는다. 도로·성벽 합성 검사판과 자연 엔진 상태의 브라우저 캡처도 구별한다.

## 반드시 유지할 한계

- 자동 성장/시설 선택/서비스 할당은 결정적 휴리스틱이며 모든 임의 지형과 인구 규모의 전역 최적 해를 보장하지 않는다.
- 기존 불법 저장 배치를 자동 이동시키지는 않는다.
- 시장 수용량 단위는 사람 수가 아닌 필지이며 시장이 빵을 배달하지 않는다.
- 설명서·최종 링크는 최신 final-report의 상태에 대응해야 한다. 실패 실행/이전 캡처는 이력으로 보존하되 최종 성공으로 섞지 않는다.
- GPU 후처리 픽셀 회귀는 별도 한계가 있으며 소프트웨어 Chrome 매트릭스와 기본 GPU 시각 캡처를 구분한다.
