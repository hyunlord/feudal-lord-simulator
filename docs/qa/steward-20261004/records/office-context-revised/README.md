## 근거와 원인 과장의 경계

- 후견 종료: lordship.ts:56–72는 null guardianId를 상위 영주 후견으로 정의한다. 170–181은 21세 이상일 때 종료한다. 같은 피후견 영주가 전후에 확인되고 사건 당시 나이가 유효한 21세 이상일 때만 새 문장을 쓴다. 특정 후견인 ID만으로 어머니·혈족임을 추정하지 않는다. 외부 역사에서 모든 후견 종료가 21세라는 보편 주장도 아니다.
- 수장 승계: history.ts:285–294는 전임자가 사망한 과거 인물이고 지도자가 바뀐 경우를 기록한다. householdId 비교는 같은 **가구**인지일 뿐 혈연·가문·상속권·정치적 지지의 증거가 아니다. 전임자 사망과 후임자 생존을 명시적으로 확인하며 인물이 누락되면 unknown이다.
- 청지기 사망: stewardship.ts:137–158는 관리 방식을 그대로 두고 후임을 고른다. 직접 관리의 장부 담당과 위임 관리의 청지기를 구별한다. 충성심·능력·부정 여부를 문구로 단정하지 않는다. 후임 인물의 존재·alive=true를 캡처 전제로 둔다. 기존 dead-steward 문제가 이 제안으로 고쳐지는 것은 아니다. 사망 기록에 estate ID가 저장되지 않으므로 발생 지점에서 정확한 영지를 함께 결합해야 하며 이름 문자열로 역추적하지 않는다.
- 관리 시작: ensureOversight는 권원과 점유를 모두 영주가 가진 지도 밖 영지에 direct 관리를 만든다. 관리 시작 **후** 중복 없는 활성 영지 수로 1곳/여러 곳을 구분한다. 한 번에 여러 곳이 늘어도 사건의 임의 순서를 만들지 않는다. ‘생애 첫 영지 획득’이나 ‘이 틱에 새로 소유권을 얻음’을 주장하지 않는다.

## 사실 줄의 조합 보류

`stewardship.began` 기본 사실 줄은 “영주의 손에 들어왔다”라고 쓰지만 producer는 **새 oversight** 여부만 확인한다. 원래부터 가진 영지의 뒤늦은 관리 개시에도 같은 기록이 가능하다. 해당 두 후보는 ADOPTION_LIMITS.json에서 조합 출력 검수 전 보류했다. 중립 사실 줄 제안은 “영주가 이 영지를 직접 보고 청지기가 장부를 맡기 시작했다”이다. 엔진 문구를 고친 것은 아니다.

다른 여섯 후보도 캡처 어댑터 없이 설치 가능하다는 뜻은 아니다. unknown fallback은 기존 사실 줄의 오류나 과장을 자체적으로 해결하지 않는다. 후견 종료·사망 기본 사실이 캡처 전제와 맞지 않으면 새 조건형을 선택하지 않는다.

## 선택 앞의 검증과 FIX-12

CONTEXT.schema.json은 template별 정확한 enum 필드, 필수 키, safe tick 범위, sourceHead, captureKind, known/unknown 및 referenceVerified 조합을 엄격히 검사한다. selector는 **먼저 schema를 검사한 뒤**, 대상 recordId·recordTick·template·campaignId·sourceHead 전체와 정확히 일치하는지 비교하고, known/verified인 경우에만 고른다. 실패 시 기본형이다. referenceVerified=true 자체로 역사적 진실이 증명되는 것은 아니며 실제 캡처 어댑터가 발생 당시 증거와 결합해야 한다.

새 headline은 이름을 박거나 이름 슬롯을 추가하지 않는다. 기존 history.summary(record,state)와 historyParams가 raw person ID를 읽기 시점 표시 이름으로 변환한다. 후견인·가구·영지 상태는 사건 때 고정하고 현재의 이름·직책으로 과거를 다시 분류하지 않는다. 과거 기록에 캡처가 없으면 unknown이다. 현재 나이에서 사망 시점을 역산하거나 현재 가구로 과거 관계를 보충하지 않는다.

## 검증

`ruby validate.rb`: 제안 schema·ID8 유일성·정본과 충돌 없음, selector104건(8선택·96fallback), 별도 음성 schema112건, 실제 소스8파일·18구간 SHA/원문, 정본SHA 불변을 검사한다. known 정상8건에는 각 문맥 분기가 한 번씩 있다. 틱·인물·영지의 실제 상태를 enum으로 만드는 코드는 **미구현**이며 fixture는 그 출력 계약을 시험한다. 후견인·가구 분기의 자연 발생 빈도도 측정하지 않았다.

검사기는 경량 Ruby schema 부분 구현이며 전체 JSON Schema 인증이 아니다. 실제 엔진·저장복원·history formatter·UI 실행은 하지 않았다. 원고의 독립 검수는 아직이며 정본650에 8개를 합산하지 않는다. build.rb는 작성 재현용이다. build/validate 이후에는 SHA256SUMS를 재작성해야 한다.
