# Engine B → 코어: 결정 예산과 개별 답변의 인과 연결

이 문서는 감사 결과를 게시하고 코어 소유 작업을 넘기는 요청서다. **렌더 중단 예산은 사용자 판단대로 P-T1 범위에 맞으며, 아래 개선 요청을 감사 문서 게시의 차단 조건으로 삼지 않는다.** 전체 실제 답변 수와 화면 중단 수는 다른 측정이다. B는 코어·저장 스키마·공용 관문을 변경하지 않는다. 이미 완료된 감사와 남은 제품 요구를 구분한다.

## 화면 중단과 실제 답변을 분리한 예산

[렌더 중단 원자료](../verification/pause/results.json)의 실행 `render-PAUSE-measure-f001a2a-f001a2a`는 lord slice/bot, seed 1–5 각 20년이다. 같은 철의 여러 새 사유는 한 번만 멈추고 즉시 계속하는 화면 규칙으로 100년 중 연간 중앙값 **1**, 최대 **4**, 총 중단 **101**회다. 최신 파일의 `reasonsTotal` 합과 `byTemplateAllSeeds` 합은 모두 **136**이다(22+25+19+37+33). 전달된 133과 3건 차이가 있으므로 133을 파일에서 확인한 값으로 쓰지 않는다. 상위 사유는 소송 방어 `lordMattersDue.suit_defence` **36**, `stewardship.escalated` **32**, `estate.suit_judged` **24**다. 사유 수를 독립된 결정 수로 합산하지 않는다.

[문구 변형 원자료](../verification/variants/results.json)는 별도 준비 화면/자연 노출 감사다. 기본 bot 판의 041·048·056 영주 청원 노출은 0, 067은 forest-s3/slice-s3에서 각 1회, 078은 0이다. 영주가 직접 종류를 맡는 판과 기본 청지기 판, 준비한 캡처와 자연 노출을 섞지 않는다. 이 파일은 20년 중단 예산이나 125년 실제 답변의 추가 표본이 아니다.

반면 [실제 답변 재현](../verification/eb-weight/answer-replay-92bbc7d/README.md)은 source `2485af4`, 도구 `92bbc7d`, seed 1–3 각 125년이며 원본 중간 87·최종 3 상태 일치를 확인했다. 고정 trace 무게표 기준 무거운 답변 **836**, 연간 중앙값 **2**, 최대 **6**, 조용한 해 **46/375**, 4건 초과 **26년**이다. 등록 답변은 **198**, 연간 최대 **2**다. 이는 중단 최대4를 뒤집는 수치가 아니다. 코어에는 별도 결정 유입/응답 예산 개선 과제로 넘기며 문서 게시를 막지 않는다. 미분류 선언 2건을 보충하면 838/초과27년이나 정식 836과 섞지 않는다.

## 개별 답변 → 결과 → 다음 행동 계약

재현 명령·원자료·상세 ID는 [기존 trace 인계](engine-B-weight-trace.md)에 보존했다. 아래는 원하는 코어 동작이다.

- **083:a**, 정적 후보 **144·150**: 실제 선택이 `order_timber` 등 비세율 명령인데 다른 선택의 세율 명령 때문에 dues target을 얻지 않게 한다. 083의 합성 원장 단위 재현은 오귀속을 보였으며 자연 미래 실행 증명은 아니다. 실제 세율 유지 선택의 지속 권리 추적은 보존한다.
- **061:b·077:a·130:a**: 실제 `set_exception_rules` 변경과 이후 청원 상신이 선택에 연결되도록 target/읽기 계약을 정한다. 단위 대조에서 규칙은 바뀌었으나 target·즉시 연결 기억은 비었다. 무효과 선택이나 소식으로 재분류하지 않는다.
- **038**: seed1 실제 답변8의 자체 ID 직접 후속은0/8이다. root 병합 후보와 개별 답변의 정식 소속을 읽을 수 있게 하되 inferred 후보를 인과 증명으로 승격하지 않는다. 무효 시도와 성공 답변도 구분한다.
- **140:b h-007606@117001**: 실제 감사 h-007676@118320, h-007909@122320, h-008117@126320은 존재하지만 이전 원인4개만 담고 이 결정을 누락했다. 원인 상한·선정/병합을 검토하고 결과 없음으로 표시하지 않는다.

## 별도 인계의 상태

문구 변형 기록 요청: 렌더 A는 041·048·056·067·078 다섯 변형을 카드·칩에서 소비한다. 답변 확정 때 **실제로 표시한 변형 ID**를 원본 사건/선택 ID와 함께 보존하고, 연대기는 그 ID로 같은 문구를 읽게 해 달라. 재열람 시 현재 상태로 변형을 다시 고르지 않는다. 변형이 없던 답변·구 저장은 기본 문구를 유지한다. 저장 필드명·이행은 엔진 소유 계약으로 정하며 B가 GameState/저장 스키마를 선행 변경하지 않는다. 048·078의 자연 경로 미노출은 [EB-FREQ 추가 목록](../verification/eb-freq/most-likely-causes.md)에 별도로 기록했다.

RR22/REMOTE 요청: `tests/engineBWeightAuditCheckpoints.test.ts`의 `readdirSync`는 `mkdtempSync`로 만든 임시 checkpoint 출력 디렉터리만 검사하고 src를 순회하지 않으므로, “walks its generated temporary checkpoint directory; imports src” 분류 사유를 독립 검토해 달라([정확한 요청](engine-B-checkpoint-test-scan.md)); 공용 관문 예외를 B가 직접 추가하지 않는다.

[MOD-SLOT 제안·실증 인계](engine-B-mod-slot.md)와 [계약 후보](../design/module-state-contract.md)는 **이미 전달 완료**했다. 격리 prototype commit `938f2f492a4cef74833913ac6e8758932112dd72`의 실제 함수 시험을 포함하며 공식 채택/본선 병합만 별도 결정이다. 제안 생성 대기 항목으로 다시 세지 않는다.

엔진 검토 순서는 사용자 지시대로 MONEY-SINK 뒤다. 그 순서를 B의 감사·게시 중단 조건으로 쓰지 않는다.

이 요청서는 소스 읽기와 기존 증거 재검산으로 작성했다. 새 장기 실행·화면 검증·코어 수정은 하지 않았다. 중단 예산 수용과 감사 게시를 유지하면서 코어 인과/중복/도착 조정 요구를 후속 소유 작업으로 남긴다.
