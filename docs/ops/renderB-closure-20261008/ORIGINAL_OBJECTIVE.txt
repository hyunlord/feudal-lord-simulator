## 첫 일: ASSET-ARCH-1 — 그림이 코드 없이 들어가는 계약 장치
visual-architecture.md 4절대로:
1. **그림 계약(manifest) 형식**: 종류별(건물 본체·상태 층·땅 소품·워커 짐·땅의 변화·랜드마크·사건 연출·사건 삽화·초상·지역 지도)로 필드를 정하고 JSON Schema로 검증. 렌더가 로드할 때 잘못된 항목은 원자적으로 거부.
2. **데이터 주도 그리기 장치**: 종류마다 계약을 읽어 그리는 장치를 **한 번** 만든다. 엔진 데이터(가구 직업·형편·필지 원형·땅 단계·계절·사건 id 등)로 고르는 규칙도 계약에.
3. **증명**: 지금 이미 설치돼 있는 한 종류(예: 집 앞 직업 표지 Wave 37 또는 땅의 변화 Wave 42)를 새 계약 장치로 옮기고 **화면이 바이트·픽셀 기준으로 같거나(같은 저장·카메라 캡처) 더 나음**을 보이고, 그다음 **설치 안 된 한 묶음(예: 직업 세계 그림 trade-world)을 코드 없이 데이터만으로** 설치해 보인다.
4. 설치 계획(install-plan-20261003)의 "작은 연결(나)" 425장 중 계약 장치로 데이터만 넣으면 되는 것이 몇 장이 됐는지 다시 센다.

## 그다음 (회차로 계속)
- **설치 계획 1~3단계를 데이터로**: 1단계(영주 화면용 그림 중 세계 쪽), 2단계(NAT-3 날씨·계절·봄, 땅의 변화), 3단계(직업 세계·랜드마크·사건 연출·창고 눈·시대 집·간판·동물·운송). 영주 화면(UI) 쪽은 렌더 A가 하니 계약 데이터만 준비해 넘긴다.
- **사람 키 정본 통일**(결정: 바이블 17.6px 기준) — 엔진 그리기 배율·문 높이·연출 무리 크기를 한 번에 맞추고 비교 캡처.
- 이미 다른 세션이 맡은 작업(렌더 A의 LM-R1 등)과 겹치지 않게 DISPATCH_LEDGER를 확인.

## 커밋·검사 규칙
- 작업 가지 `astra/renderB-<작업>` → AGENTS.md의 관문(새 시험, `npm run check:merge`, 화면 입력을 바꾸면 ui-geometry, 무거운 실행은 `scripts/remote/run.sh`로 DGX·기하 감사는 실행기 규칙대로) → **깨끗한 클론** → 본선 merge·push → 가지 삭제. **이력 재작성·강제 푸시 금지**(푸시 전 로컬 재구성은 허용).
- 커밋마다 **실제 게임 장면 전후 캡처**(같은 저장·같은 카메라, 줌 1.0·0.6, 여름·겨울)를 `docs/verification/<작업>/`에(3MB 상한).
- 장부: 설치한 그림의 `installed_by`, 작업 지시 장부(DISPATCH_LEDGER)의 네 줄 체크와 커밋 해시.
- 판정이 필요한 선택은 **멈추지 말고** 규칙을 지키는 쪽을 기본으로 고르고 보고서에 "판단: …"으로 표시.
