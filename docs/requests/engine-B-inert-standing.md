# EB-INERT 상시 묵인 시제품

관문: 구현·단위 검증 완료, 새 375 seed-년·비영주 해시·브라우저 측정 전. 이전 72c77f6의 100%/무효과0/해시5개 일치는 새 규칙의 결과로 재사용하지 않는다. 가지는 `codex/engine-b-inert`이며 본선 병합은 엔진이 한다.

## 규칙

- 영주가 명시적으로 묵인하면 `standing["audit:<estateId>:<personId>"] = "lenient"`. 청지기별 `auditTolerance`에 최초 감사 ID, 시작 시점, 오류+빼돌림 합계, 답 직후 충성도, 철별 손실액을 보존한다.
- 철별 손실은 `ceil(기준액/16)`이며 실제 남은 영지 수입을 넘지 않는다. 과거 미회수액을 다시 차감하지 않는다. 장부는 총 입금과 `audit_tolerance_loss` 음수 항목을 함께 남겨 합계가 실제 순수입과 같게 한다.
- 새 감사의 공개 합계가 **원래 기준액의 두 배를 초과**, 충성도가 답 직후보다 하락, 청지기 교체, 방침 철회일 때만 영주의 새 감사로 올린다. 기준액0이면 양수 오류 발생이 확대다. 자동 처리 감사는 충성도를 올리거나 정책 기준을 갱신하지 않는다.
- 청지기 교체·사망·재임명은 이전 방침을 재활성화하지 않는다. 예전 청지기의 미처리 감사는 기록을 보존하지만 카드·미리보기·직접 답·시간초과 처리에서 제외한다. 철회는 기존 `set_standing_policy` 명령의 `lord` 설정이며 다음 감사는 오류0이어도 다시 결정한다.
- 영주 모드만 변경한다. 구형 `toleratedErrors`의 유한 압력은 저장 호환용으로 그대로 읽되 같은 감사 손실을 중복 부과하지 않는다.

## 화면·흔적

기존 상시 방침 화면의 영지 묶음에 청지기 이름·비용·철회 버튼을 붙였다. 자동 감사와 실제 철별 손실은 청지기 보고, 장부, 기존 연대기 줄에서 읽는다. `answerEffects`는 답 당시 감독 방식과 조건 변경을 보존한다. 이후 철의 현금을 최초 답의 이전/이후 값에 덧붙이지 않는다. 실제 계절 손실의 `decision_effect`는 최초 답 ID를 가리키며 3년 뒤에도 같은 방침이 유효하면 연결된다. 자동 감사가 새 영주 답을 만들지 않는다.

## 저장

선택 필드 `StewardRecord.auditTolerance`, `AuditRecord.decidedBy/policyAuditId/superseded`, `trace.answers[].effects`. 구판의 부재는 그대로 남으며 과거 방침/효과를 역산하지 않는다. 승인된 TRACE-LINK answerEffects 구현·검증기를 최소 이식했다. 잠정 v57 지문은 준비 fixture로 확장했으며 최종 통합 판 번호는 사용자 지시대로 엔진이 정한다. 일반 fingerprint 생성기의 판 변경 거부는 손대지 않았다.
