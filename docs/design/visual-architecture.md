# Charter & Kin — 시각·에셋 아키텍처 v1 (초안, 2026-10-04)

목적: 게임이 **방대하고, 자세하고, 복잡하고, 질이 높게 "느껴지게"** 만드는 그림·에셋의 구조와 만드는 방식을 하나로 정한다. 지금까지 40여 Wave와 실험(성공·실패)에서 배운 것을 원칙으로 굳히고, 그림을 **빨리, 많이, 일관되게** 게임에 넣을 수 있는 구조를 만든다.

## 1. 지금 어떻게 하고 있나 (진단)

| 항목 | 현황 | 문제 |
|---|---|---|
| 그림 생산 | Astra가 Wave 단위로 대량 생산, 판정·장부 엄격 | **생산 >> 설치**: 확정됐는데 게임에 없는 그림 약 2,200장(설치 계획 대상 858) |
| 설치 | 렌더 한 세션이 그림마다 코드 연결 | 설치 대기 744장 중 **425장이 "작은 코드 연결"**, 282장이 "새 기능" — 그림 하나 넣는 데 코드가 필요 |

## 2. "방대하고 자세하게 느껴진다"는 것은 무엇인가

플레이어가 느끼는 풍부함은 그림 장수가 아니라 다음 넷에서 온다.
1. **보는 거리마다 읽을 것이 있다** (줌 단계별 의미)
2. **세계가 시간에 따라 변한다** (계절·세대·사건·땅)
3. **모든 사실이 눈에 보이는 흔적을 남긴다** (직업·부·재난·결정의 결과)
4. **가까이 볼수록 이야기가 나온다** (누르면 사람·가문·영수증·연대기)

그러니 **"같은 것을 많이"가 아니라 "엔진의 사실 하나마다 그림 하나의 흔적"**이 목표다.

---
## 3. 원칙 (실험에서 굳힌 것)

1. **조합 단위는 크게.** 건물·나무·사람은 **완성 그림**으로. 벽에 붙는 부품, 얼굴 부품, 지형 조각 흩뿌리기는 하지 않는다.
2. **다양성은 직교하는 층의 곱으로.** 완성 그림(기본형 몇 개) × **상태 층**(계절·눈·판자·낡음·부유) × **땅에 서는 소품**(직업·형편) × **움직임**(워커·짐·연출) × **빛·날씨**. 층이 서로 독립이라 곱이 커진다.
3. **보는 거리에 맞춰 투자.**
   - 먼 줌(0.5~0.6): 실루엣·랜드마크·지구 색·연기·계절 색 — **랜드마크 성장, 지구 분위기, 사건 핀**
   - 중간 줌(1.0): 건물 상태·마당 소품·무리·연출 — **상태 층, 소품, 행렬**
   - 가까운 줌(1.4~2): 소품 세부·짐·걸음 — 있으면 좋음, 주력 아님
   - 화면(UI): **초상·사건 삽화·지역 지도** — 가장 크게 보여 **품질 대비 효과가 가장 큼**
4. **세부는 누르면 나온다.** 작은 집 하나를 다르게 그리는 대신, 누르면 그 집 가구의 직업·형편·이력·영수증이 나오게. 그림은 "눈길을 끄는 신호", 깊이는 데이터.
5. **기준은 하나.** 비율(사람 키)·광원·팔레트·피벗은 **바이블 하나가 정본**, 엔진 그리기 배율도 그걸 따른다.

## 4. 에셋 구조 (제안 — 데이터 주도)

모든 그림을 **"그림 묶음 계약(manifest)"**으로 넣는다. 렌더는 **종류마다 그리는 장치를 한 번만** 만들고, 그 뒤로는 **데이터(CSV/JSON)와 파일만 넣으면** 게임에 나온다.

| 종류 | 계약에 들어가는 것 | 엔진에서 고르는 기준 |
|---|---|---|
| 건물 본체 | 종류·등급·변형 id·캔버스·피벗·발판·계절판 | 건물 종류·등급·seed 변형 |
| 상태 층 | 대상 본체·층 종류(눈·판자·낡음·부유·시대)·함께 변환 규칙 | 계절·빈집·나이·부·연대 |
| 땅 소품(마당·집 앞·표지) | 원형·직업·형편·발 기준점·놓는 자리 규칙·계절판 | 가구 직업·형편·필지 원형 |
| 워커·짐 | 역할·짐 종류·프레임·발 기준점 | 가구 직업·운반 물자 |
| 땅의 변화 | 단계·접속 규칙·계절판 | 엔진 땅 단계 데이터 |
| 랜드마크 성장 | 계열·단계·발판 확장 규칙 | 엔진 성장 조건(칙허·증축·후원) |
| 사건 연출 | 연출 종류·무리·놓는 자리·지속 | 등록기 사건 id |
| 사건 삽화(UI) | 사건 id → 그림 | 등록기 사건 id |
| 초상(UI) | 인물 id·혈통·나이 단계·시대판 | 인물 데이터 |
| 지역 지도(UI) | 지도 id·땅 종류·슬롯 좌표 | seed·영지 배정 |

**효과**: 설치 대기의 "작은 연결 425장"이 대부분 **데이터 넣기**로 바뀐다. 새 그림이 와도 렌더 코드가 필요 없다.

## 5. 만드는 방식 (생산 → 검증 → 설치)

1. **사양 먼저**: 엔진 사실(필드·상태)마다 "어떤 시각 흔적이 필요한가"를 표로 — **시각 흔적 지도(Visual Hook Map)**. 흔적이 없는 사실, 사실이 없는 그림을 찾는다.
2. **Astra 생산**: 계약 형식 그대로(캔버스·피벗·계절·CSV), 바이블 자동 검사(크기·광원·팔레트) 통과분만 납품. **실제 게임 장면 합성**으로 판정(색·수치만으로 판정하지 않는다 — 이번 석벽 실수 교훈).
3. **INBOX**: 장부 자동 검사(행=그림, LFS).
4. **설치**: 계약 데이터만 넣으면 끝. 설치 = 데이터 커밋 + 실제 장면 캡처.
5. **검증**: 기하 감사(UI), 시각 검사기(후보), Astra QA(눈), 사용자 판단(최종).

---
## 6. 우선순위 (보이는 정도 × 자주 보는 정도 ÷ 설치 비용)

1. **초상·사건 삽화·지역 지도** — 크게 보이고, 설치 비용이 작고, 영주 모드(인물 중심)의 핵심
2. **상태 층·땅에 서는 소품·워커 짐** — 도시가 "사는 것처럼" 보이는 주력, 계약만 생기면 대량 설치 가능
3. **땅의 변화·계절·날씨** — 시간이 흐르는 느낌
4. **랜드마크 성장·사건 연출** — 150년과 결정의 결과를 보여 줌, 엔진 조건이 필요
5. **작은 집·사람의 세부 변형** — 18px에서 안 읽힘, 최소한만

## 7. 작업 체계 (속도)

- **렌더 A(지금 세션)**: 영주 모드 화면(LM-R1~R3)과 UI.
- **렌더 B = Astra(새 권한)**: **세계 그리기 장치와 그림 설치** — 먼저 4절의 **데이터 주도 계약 장치**를 만들고(ASSET-ARCH-1), 그다음 설치 계획 1~3단계를 데이터로 쏟아 넣기. 자기 가지에 커밋, 같은 병합 전 검사 통과 후 본선, 렌더 A와 **파일 경계 분리**(UI·영주 화면 = A, 세계 그리기·에셋 카탈로그 = B).
- **실행기 둘**: DGX(클론·장기 판) + Mac Studio(기하 감사), 무거운 실행 동시 상한.
- **판정**: Claude가 회차마다 원격 대조, 사용자는 수직 조각 플레이로 방향 판정.
