# 종료 화면의 개별 무거운 답 확인

공식 light kept 실행 `engineB-tlink-slice-browser-retry-7a4c6ae`, 깨끗한 `7a4c6ae7e208dc8ad4b5678651713e84a34377dd`. 같은 root에 묶이는 실제 reducer 답2개를 준비하고 종료 시점만 옮긴 경계 fixture다. 자연125년 판이 아니다.

1280×800에서 정상 스크롤 뒤 `h-000002`와 `h-000004` 모두 화면에 보였다. 하단 연대기 버튼→두 번째 기록 실제 클릭으로 상세를 열었다. 연도별 목록 행 자체에는 클릭 동작이 없다. 저장 왕복 동일, tick20000 유지, browser errors0, exit0. 이미지3장을 직접 확인했다.

이 화면의 ‘뒤따른 일’에는 같은 tick의 청원 처리 기록도 포함된다. 이는 엄격한 미래 직접 연결률의 분자에 포함되지 않는다. 준비 fixture의 영지 이름home과 기존 빈 ‘예측과 실제’ 열이 보이며, 전체 UX 승인을 주장하지 않는다.

첫 `engineB-tlink-slice-browser-7a4c6ae` 실행은 셸 인용 문제로 driver 이전에 exit126이었으며 증거로 사용하지 않는다. 성공 실행 command45.5초. 파일별 SHA와 실제 관측값은 result.json에 있다.

`executed-driver.mjs`는 실제 원격 `.remote/tlink-slice-capture.mjs` 바이트 그대로다(SHA256 `4bd72eb374df475757fd6fce5878b5cd9b4c0657dddffb04420e9f25de3522ba`). 상대 import를 위해 재실행할 때 저장소 루트의 `.remote/tlink-slice-capture.mjs`에 복사한다. 원격 공식 실행기의 FLS_REMOTE_PORT로 별도 dev 서버를 열어 실행하며, PLAY-1 서버는 사용하지 않는다.
