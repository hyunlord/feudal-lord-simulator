# SEASONS 설치·실제 화면 보고

눈 그림 6장을 연결했다. 눈송이 3종·날리는 눈 띠 1종·발자국 2종이다. 지붕·나무·그루터기의 눈과 해빙은 대상별 위상으로 천천히 바뀌고, 늦가을 첫서리와 봄 복귀도 달력 진행에 맞춰 나타난다. 엔진 규칙과 저장 형식은 바꾸지 않았다.

구현 커밋은 `8f463a2069dd1062008bf81580cf1dd25c417ce8`이며, 눈 6장의 출처와 설치 장부를 같은 작업에서 반영했다. 현재는 실제 화면 증거를 모은 작업판이다. **깨끗한 클론 전체 회귀 5,024개와 빌드는 통과했다. 기하 2,262조건도 실패0·미개방0으로 통과했다. check:merge·본선 게시가 남아 있다.** 관문 완료나 게시 완료라고 판정하지 않는다. 회귀 수정 전 캡처 HEAD는 `b661beddb20f2d9bc2d5000aca8cb9383f2ac677`, `dirty=true`였다. 그루터기 위상 수정도 캡처에 들어갔다. 현재 첨부한 전후 화면과 호출 수는 회귀 수정 후 `astra-SEASONS-repair-capture-b3cdecf`의 41프레임으로 갱신했다. 이 실행의 기반 HEAD는 `b3cdecfd`, dirty snapshot의 변경 파일 46개는 `cda5764f`와 일치한다. 회귀 수정 전 src/render·public/assets 전체 파일 SHA는 IMPLEMENTATION_SHA256.json에 기록했다. 전체 목록은 캡처 이후 수집했다. 별도로 실제 DGX 실행 트리의 변경·신규 구현·시험·스크립트·눈 그림43파일 SHA를 당시 구현과 비교해 모두 정확히 일치했다(CAPTURE_INPUT_MATCH.json). 현재 수정본과의 일치는 REPAIR_INPUT_MATCH.json에 따로 기록했다.

## 남아 있는 전체 요구

이번 묶음은 눈 그림 6장과 대상별 계절 위상이다. 그늘과 북향 지붕을 구분해 잔설이 더 오래 남는 조건은 아직 구현·검증하지 않았다. 봄 그림 8장의 설치도 남아 있다. 따라서 이 묶음의 관문이 통과하더라도 NAT-3 전체나 설치 계획 1~3단계의 완료로 표시하지 않는다. 현재 묶음을 본선에 게시한 뒤 남은 요구를 이어서 처리한다.

## 같은 저장과 실제 조작

전후 초기 21쌍의 원본 저장 SHA·해독 엔진 상태 SHA·실제 표시 상태 SHA·틱·지정 타일·줌·카메라 영수증이 일치했다. 기준판은 초기 21장과 움직임 보충 21장 중 겹치는 첫 장을 빼서 고유 41프레임, 수정판은 완전한 41프레임이다. 실제 1배속 움직임을 캡처했으며 이후 프레임은 촬영 중 틱이 진행되므로 틱 일치나 픽셀 동일성을 주장하지 않는다. 양쪽 모두 실제 일시정지·휠 줌·드래그 이동·재개를 확인했다.

여름·겨울의 줌 1/0.6 전후 8장, 한겨울·초봄 지붕의 같은 조건 전후 8장을 포함했다. 모두 실제 캔버스 PNG를 1280×800 그대로 JPEG 품질40로 압축한 확인본이다. 자르기·크기 변경·합성·그림 수정은 하지 않았다. 원본·파생 SHA와 원본 경로는 CAPTURE_DERIVATIVES.json에 있다.

## 화면 판정

담당자의 실제 화면 검토 결과: 겨울 첫날은 지붕과 그루터기에 눈이 즉시 덮이지 않는다. 한겨울에는 지붕의 눈이 점차 늘고 그루터기도 서로 다른 위상을 보이며, 늦겨울에는 충분히 쌓인다. 초봄은 녹는 지붕 눈과 잎 없는 나무를 남겨 기준판의 즉시 초록 전환과 구별되고, 늦봄에는 초록과 눈 제거가 이어진다. 줌 0.6에서도 실루엣을 유지했다. 초여름 시작에 봄 초록이 잠시 남는 것은 점진 전환의 의도다. 움직임 15번 프레임에서 눈송이와 날리는 눈 띠를 확인했다.

발자국은 작고 희미하다. 두 그림의 실제 그리기 호출과 지면 지지 시험은 근거가 되지만 모든 발자국이 화면에서 분명히 보인다고 주장하지 않는다. 성능 A/B 측정도 이 보고의 근거에 포함하지 않는다.

## 원시 실패와 보정 근거

원 기준판과 교체된 첫 수정판은 각각 오류16건(개발 텔레메트리 취소1건, 잘못된 하네스 단언15건)으로 종료1이었다. 기준판 움직임 보충은 텔레메트리 취소3건으로 종료1, 회귀 수정 전 수정판 전체 실행은 텔레메트리 취소4건으로 종료1이었다. 네 실행의 원시 실패를 그대로 보존한다. 그 밖의 기록 오류는 없지만 무오류 실행이라고 부르지 않는다. 취소 원인은 확정하지 않았다.

단언 오류는 proof port가 엔진 원본이 아니라 주민 보행자를 추가한 표시 상태를 반환하는 데서 발생했다. 원본 저장을 바꾸지 않고 production `withResidentWalkers`로 표시 상태를 별도 유도했으며, 실제 화면의 전체 상태 SHA 및 전후 상태 SHA와 일치함을 확인했다. 주민을 지우거나 검사를 생략하지 않았다. 원본 엔진 SHA와 표시 SHA 및 코드 위치는 PRESENTATION_PROJECTION.json에 분리 기록했다.

## 겨울 전체 연속 재생

`astra-SEASONS-cycle-b3cdecf`는 같은 겨울 저장에서 실제 1배속으로 23000→24000틱, 100틱 간격 11프레임을 기록했다. 겨울 전체가 지나 봄에 도달했으며 카메라는 고정됐다. 마지막 화면은 정상적인 겨울 결산 창이고, 이 창이 게임을 멈춰 추가 초봄 5프레임을 기다리던 장치가 시간 초과로 종료1했다. 원시 오류는 텔레메트리 요청 취소14건과 이 시간 초과1건이다. 정상 종료 또는 목표16프레임 완료로 바꾸어 기록하지 않는다. 초봄 해빙은 앞의 별도 전후 캡처로 확인했다. 프레임·상태 SHA와 오류 원문은 CYCLE.json에 있다.

### 전체 회귀에서 발견한 두 실패와 수정

`astra-SEASONS-clone-b3cdecf`의 깨끗한 클론 전체 회귀는 5,021개 통과·2개 실패였다. 실패를 통과로 간주하지 않았다. `renderer.ts`가 실질 252줄로 250줄 제한을 넘었으므로, 기존 캔버스 배율 계산을 `renderDevicePixelRatio.ts`로 그대로 옮겼다. 그리기 순서와 계산식은 같다. 기존 렌더 계약·소스 검사 15개가 통과했다.

C25에는 빈 지면에도 alpha를 복원하는 불필요한 호출이 두 번 추가돼 있었다. 실패 재현 시험을 먼저 추가하고, 값이 바뀐 경우에만 복원하도록 고쳤다. 서리 그림이 없는 칸에서도 alpha를 바꾸지 않는다. 관련 집중 시험 29개와 타입 검사가 통과했다. 이후 C25 16개 중 14개는 이전 기록과 일치했고, 가을·겨울 두 장면만 점진적인 나무 변화와 눈 쌓임 때문에 달랐다. 결정 `RB-SEASONS-C25`에 따라 두 해시만 갱신했으며 동일 장면 두 번 그리기와 16개 장면 검사는 그대로 통과했다. 이 두 수정은 아래의 전체 회귀와 실제 장면 재확인으로 검증했다.

수정 커밋 `cda5764f`의 실제 화면 재검증은 `astra-SEASONS-repair-capture-b3cdecf`로 완료했다. DGX 실행 트리의 변경 파일 46개 SHA가 해당 수정 커밋과 일치한다(`REPAIR_INPUT_MATCH.json`). 41프레임 중 전후 초기 21쌍의 저장·표시 상태·틱·카메라가 일치했다. 실제 조작에서 23813틱 일시정지 유지, 줌 1→1.1, 화면 중심 80/30 이동, 23817틱 재개를 확인했다. 여름·겨울과 한겨울·초봄의 두 줌 화면, 늦봄 숲, 눈 움직임을 직접 열어 확인했다. 텔레메트리 요청 취소4건으로 원시 종료는1이며 원인을 확정하지 않았다. 본문의 화면 판정과 그림 호출 수는 이 수정 후 실행을 기준으로 한다. 깨끗한 클론·전체 회귀 결과는 다음 절에 기록했다. 최종 병합 검사가 남아 있다.
