## Phase 19 — F/H 렌더 기준·저장소 용량
- 커밋: `e9b6cec` (결정 문서1파일; 원본 `f30d335`).
- 바뀐 것: 정확 픽셀 비교는 CPU/software 고정 환경으로 표준화했다. 기본 GPU는 허용 오차가 있는 시각·플레이 검수 대상이다. 캔버스 설정·LFS 규칙은 변경하지 않았다.
- 측정: 아래 표는 감사 시점 공유 저장소의 논리 바이트다. MB=1,000,000바이트이며 단일 브랜치의 깨끗한 clone 크기와 다르다.
- 테스트: 읽기 전용 Git 객체·LFS 포인터/원본 대조. 제품 동작 변경 없음.
- 확인 못 한 것: 기본 GPU의 엄격 픽셀 동등성은 주장하지 않는다. 실제 도로 소실이 관찰되면 재현 상태와 함께 별도 조사한다.
- 사용자 결정 필요: 향후 새 검증 PNG만 LFS로 넣을지 선택. 현재 정책은 그대로다.

모든 refs의 도달 가능한 고유 PNG blob은318.81MB, JSON은4.32MB다. 현재 HEAD만의 수치가 아니다. Git이 선택한 packed 저장 표현에서 PNG67.23MB·JSON0.12MB이며, 중복 pack·loose까지 합산한 물리 점유량으로 해석하지 않는다. `count-objects`, `ls-tree`, `rev-list`, `cat-file`, `verify-pack`을 교차 집계했다. [상세 감사](repository-audit.json)

권고는 **향후 새** `docs/verification/**/*.png`만 LFS로 관리하는 것이다. 원본 payload·다운로드 파일·LFS 전송 비용은 남으며 기존 이력을 줄이지 않는다. 해당 경로의 현재 PNG는2개816,728바이트여서 즉시 큰 절감은 기대하지 않는다. 대안은 현행 JPEG 중심 정책 유지다. 사용자 선택 전 `.gitattributes`, 이력, 압축·정리 명령을 변경하지 않았다.
