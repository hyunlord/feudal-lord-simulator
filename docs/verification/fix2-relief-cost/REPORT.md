# FIX-2 구휼 비용 보고서

지시(사용자, MARKET-1 뒤에 붙인 작은 작업): "구휼 예측·실제 금고 변화가 수입 0이면 '그대로'로 나와. 구휼 비용 = 배급한 빵 × 시장가(곡창 방출이면 방출 가치)로 예측과 실제 둘 다 계산하게 고쳐."
명세: [1장 명세](../../design/flow-chapter-one.md) FC-2a(새 절), [기록 원장 명세](../../design/history-ledger.md) HL-3 표·실제 줄, [장부 명세](../../design/ledger.md) L-6. 결정: FC12. 엔진 세션, 렌더 0줄, 저장 형식 그대로(v17), 검증 DGX.

## 원인
- 예측(`bigDecision`)이 구휼 금고를 `지금 − 지난 계절 수입 × 2`로 셌다. 수입이 0이면 0이 빠져 "그대로"였다. 수입이 있어도 구휼은 가난한 가구의 한 계절 빵(이 마을은 8덩이 × 15d = 120d)까지만 사므로, 수입 1,200이면 −2,400으로 크게 부풀었다.
- 실제(`fillActuals`)는 두 계절 뒤의 금고를 그대로 읽었다. 수입이 0이면 구휼은 아무것도 사지 않아(FC3 예산 = 지난 계절 수입) 금고가 그대로였고, 곡창의 빵을 나눠 준 몫은 어디에도 적히지 않았다.

- **한 계절의 구휼**(FC-2a, `reliefSeason`): 나눌 빵 = 가난한 가구 1/4의 한 계절 배급량. ① 현금으로 먼저 산다(예전 규칙 그대로: 지난 계절 현금 수입과 금고 50 % 가운데 적은 것, 첫 곡창의 빈 칸까지, 산 빵은 곡창으로). ② 모자란 몫은 곡창의 빵에서 방출한다. 방출 가치 = 그 빵을 지금 시장에서 팔면 받을 값(시장가; 투기가 같은 빵을 파는 값).
- **장부**: 산 몫은 예전처럼 `famine_relief` 현금 항목이다. 방출 몫은 `famine_relief` 현물 항목(`in_kind`, resource `bread`, 곡창마다 한 줄, 출처 사건 + 곡창)이다. 현물 항목은 금고와 계절 수지(현금만 셈)를 바꾸지 않는다. 방출한 빵을 따로 옮기지 않는다(여느 때처럼 마을 거래로 나간다). 그래서 시뮬레이션은 그대로다.
- **예측**: 결정 때 수치로, 결정 뒤 두 계절(due)까지의 구휼 계절마다 ①②를 되풀이한다(금고는 산 값만큼, 곡창 빵은 방출한 만큼 줄여 다음 계절). 예측 금고 = 지금 − 비용 합. 기근 결정 카드(UI-4 모달)는 엔진 예측을 그대로 읽으므로 렌더 수정 없이 카드 숫자가 바뀐다.
- **실제**: 결정 때 금고 − (결정, due] 사이 그 사건의 구휼 항목(현금 + 현물) 합. 결정 기록 params에 `eventId`·`treasuryAtDecision`을 더했다(`HistoryParams`는 열린 기록이라 저장 형식은 그대로). 두 값이 없는 옛 기록은 예전처럼 due 때 금고를 읽는다.

## 관문 결과

### 수입 0에서도 구휼 비용이 예측과 실제에 나온다 — [relief-cases.json](relief-cases.json)
`scripts/reliefCostRun.ts`를 본선 `85069063`(전)과 FIX-2 `82dbf474`(후)에서 같은 코드로 돌렸다. 1장 테스트의 준비된 마을(인구 176, 곡창 1, 시장 1, 금고 5,000d), 1315년 봄(60,000틱) 대기근 도래, 그때 구휼, 전체 틱으로 due(62,000)까지.

| 경우 | 전: 카드 예측 / 실제 | 후: 카드 예측 / 실제 | 후: 구휼 항목 |
|---|---|---|---|
| 수입 0, 곡창 빵 3,000 | 5,000 / 5,000 ("그대로") | **4,760 / 4,760** | 현물 −120(빵 8) · −120(빵 8) |
| 수입 0, 픽스처 곡창(빵 7) | 5,000 / 5,000 ("그대로") | **4,895 / 4,895** | 현물 −30(빵 2) · −75(빵 5) |
| 지난 계절 수입 1,200(C3), 픽스처 곡창 | 2,600 / 5,000 | 4,760 / 4,895 | 현물 −30 · −75 |

- 셋째 경우 예측과 실제가 다른 것은 예측의 성질이다. 예측은 지난 계절 수입 1,200이 두 계절 이어진다고 보고 한 계절 빵 8덩이를 산다고 셌다(−240). 실제로는 다음 계절 현금 수입이 0이라 사지 못하고 곡창에서 방출했다(−105). 예전 예측(−2,400)은 한 계절 빵의 값을 넘어 수입 × 2를 셌다.
- 카드 문구(엔진 예측 그대로): 전 `금고 5000d(지금 5000d)` → 후 `금고 4760d(지금 5000d)`.

### 시나리오 C11 — 통과 (`tests/flowChapterOne.test.ts`)
- 수입 0 · 곡창 빵 3,000: 카드와 원장 예측 = 5,000 − 2 × 8 × 15 = 4,760. params `eventId`·`treasuryAtDecision`. 두 계절 시작마다 현물 −120(빵 8, 출처 사건·곡창), 금고·곡창 빵 그대로. due에 실제 = 4,760.
- 옛 기록(params 없음)은 due 때 금고(5,000)를 읽는다.
- 수입이 있으면 현금이 먼저다: 수입 75(빵 5) → 현금 −75 · 현물 −45, 곡창 빵 20 → 25. 빵이 가득한 곡창은 살 자리가 없어 전부 방출한다.
- 예측은 곡창 빵이 줄어드는 것을 센다: 빵 7이면 첫 계절 7덩이, 둘째 계절 0 → 예측 −105.
- 나눌 빵이 없으면(수입 0 ∧ 곡창 빵 0) 비용 0: 예측이 "그대로"이고 장부도 그대로다.
- 기존 C3(구휼 현금 구입·"수입 0이면 사지 않음")·C9(연대기 결정 인용)·C10(저장 왕복)도 그대로 통과한다.

### 시뮬레이션 동일
같은 마을에 곡창 빵 60을 두고 구휼로 3,000틱(63,000까지) 전체 틱을 돌렸다. 원장·기록·경로 캐시를 뺀 세계 해시 `1c6250ab53384a12`, 현금 항목 해시, 롤업 해시, 금고 4,941d가 본선과 FIX-2에서 같다. 다른 것은 FIX-2 장부의 현물 항목뿐이다(61,000 −120 · 62,000 −120 · 63,000 현금 −90과 현물 −105). 경제·배치·공사·서비스·승급 규칙을 바꾸지 않았으므로 가드레일은 돌리지 않았다(AGENTS.md "UI·문서만 바꾼 작업"에 준함, 봇 0줄).
