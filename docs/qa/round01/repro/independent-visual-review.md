# 독립 시각 검수 — QA ROUND 01

검수 범위: 저장된 실제 브라우저 JPEG와 0.1초 간격 연속 프레임. 브라우저 조작·게임 코드 열람·수정 없음. 좌표는 1600×1100 원본 화면의 대략적인 픽셀 좌표다. 파일명에 따른 상태명은 촬영자의 기록을 따르며, 픽셀로 확인하지 못한 원인은 미확정으로 둔다.

## 확실히 보이는 현상

1. **건물 표면 위 인물 / 일부 인물 위치 고정.** `11-1380-paused-settled.jpg`의 큰 곡창 벽면 (1076,157), (1096,184), 작은 집 지붕 (950,348), (968,377)에 사람이 겹쳐 있다. `1380-5x/00,05,10,15,19.jpg`에서도 같은 인물들이 같은 위치인 반면, 아래 도로의 수레와 다른 사람은 이동한다. 이 비교를 `independent-actors-sheet.jpg`에 00→05→10→15→19 순서로 담았다(원본 ROI x880,y100,w330,h400). **보이는 위치/가림 문제는 재현**, 정적인 그림 부속인지 주민의 멈춘 이동인지, 유휴/작업중인지 등 원인은 이 증거로 단정할 수 없다. 모든 워커가 고장났다는 결론은 부적절하다.

2. **실행 중 숲의 빠른 외형 변화.** `1380-forest-5x` 00→19 프레임에서 여러 수관이 크게 달라지며 도로/석벽은 같은 위치에 남는다. 상단은 두 프레임 모두 1380년 여름이다. ROI x600,y100,w300,h320의 JPEG RGB 절대차 평균은 18.0223/255, 평균 RGB 차 15 초과 픽셀은 39.201%다. 같은 ROI의 `1380-forest-paused` 00→19는 0, `1380-paused`의 독립 참나무 ROI x340,y820,w190,h165도 0이다. **움직임이 실행과 연결되며 정지하면 멈춘다는 증거**이며, 단순 계절 경계 전환만으로 설명하기 어렵다. 흔들림 구현·성장·이미지 교체 중 무엇인지는 미확정이다. JPEG 차이율은 움직인 나무 개수나 버그 확률이 아니다.

3. **축소 시 큰 표현 단절.** `20-1380-zoom0605.jpg`에서 거의 모든 건물은 흰 벽/갈색 지붕의 단순 도형, 나무는 검은 테두리 녹색 원으로 바뀐다. `22-1380-zoom1427.jpg`의 상세 손그림과 이질감이 크다. 저해상도 LOD의 의도 가능성이 있으므로 오류로 단정하지 않고 '축소 시 화풍/건물 종류 판독 유지' 검토 항목으로 등록할 가치가 있다.

4. **UI 재료·틀의 불일치 및 장부 열 잘림 후보.** `14-1380-calendar.jpg`의 달력은 무장식 평면 직사각형, `19-1380-chronicle-settled.jpg`의 연대기는 이중선 장식 카드, `17-1380-ledger.jpg`의 품목 버튼은 브라우저 기본형에 가까운 흰 사각형이다. 같은 제품 UI의 재료/모서리/버튼 규칙 불일치가 보인다. 장부 창고 열의 목재 숫자는 오른쪽 경계 x≈1579에서 잘려 보인다. 가로 스크롤로 읽을 수 있는지는 이 검수에서 확인하지 못했다. 연대기 카드 자체는 반복 항목의 폭/높이가 일정하며, 모든 글상자가 들쭉날쭉하다고 일반화할 수 없다.

## 단정하면 안 되는 항목

- **성벽 끊김:** `11`/`14`에서 왼쪽 위 (440,245)와 호수 북쪽 (805,500) 부근에 열린 틈이 있다. 길이 통과하고 벽 끝에 기둥/돌단부가 보여 성문 개구부일 가능성이 있다. 문루/문짝이 없어서 끊겨 보이는 인상은 확인되지만, 의도치 않은 기하 단절 또는 통행 버그는 픽셀만으로 확정할 수 없다.
- **물 가로지르는 성벽:** 현재 검수한 화면은 호수 가장자리를 따라 벽이 둘러선 모습이다. 긴 벽이 호수 내부를 횡단한다고 확실히 말할 수 있는 구간은 찾지 못했다. 바닥 타일/다른 카메라의 추가 확인 전에는 미재현으로 둔다.
- **같은 길 반복 건설:** 정지 이미지와 2초 클립은 건설 명령 주체·반복 횟수를 증명하지 못한다. 자동 발전/튜토리얼/시험 훅 원인이라고 추정해 적지 않는다.
- **일꾼 정지 이유:** 2초 동안 위치가 같아도 유휴, 시설 장식, 보간/애니메이션 문제 등은 구분되지 않는다. 화면 상세에 상태가 나오는지 추가 관찰이 필요하다.

## 체크리스트로 일반화할 항목

- 같은 카메라/계절에서 실행과 일시정지 각각 20프레임을 비교해 수목 수관/줄기/접지가 연속적인지.
- 건물 전면·후면을 지나거나 작업하는 주민의 발 접지와 깊이 가림이 적절한지.
- 정적인 활동 인물과 이동 주민이 시각적으로 구분되고, 멈춘 이유를 선택 상세에서 찾을 수 있는지.
- 줌 임계점 전후의 종류 판독성과 화풍 일관성, 도형 fallback 여부를 확인하는지.
- 성문 개구부를 일반 벽 단절과 구분할 수 있는지. 물 경계는 시각과 실제 지형을 별도 확인하는지.
- 장부 각 열의 마지막 숫자/버튼이 스크롤·펼침에서 접근 가능한지, 다른 패널의 공통 버튼/틀 규칙과 맞는지.

## 픽셀 차이 계산 재현 명령

아래 명령은 원본 JPEG를 디코딩한 RGB 배열을 비교한다. JPEG 압축 차이가 포함되므로 정확한 움직임 거리(px)나 엔진 좌표 변화량으로 해석하지 않는다.

```sh
node - <<'JS'
const sharp = require('/Users/rexxa/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/sharp');
(async () => {
  for (const scene of ['1380-paused', '1380-forest-paused', '1380-forest-5x']) {
    const base = '/tmp/fls-qa-raw-round01/' + scene + '/';
    const first = await sharp(base + '00.jpg').raw().toBuffer({ resolveWithObject: true });
    const last = await sharp(base + '19.jpg').raw().toBuffer();
    const roi = scene === '1380-paused'
      ? { x: 340, y: 820, w: 190, h: 165 }
      : { x: 600, y: 100, w: 300, h: 320 };
    let sum = 0, count = 0, changed = 0;
    for (let y = roi.y; y < roi.y + roi.h; y++) {
      for (let x = roi.x; x < roi.x + roi.w; x++) {
        let difference = 0;
        for (let c = 0; c < 3; c++) {
          const index = (y * first.info.width + x) * 3 + c;
          difference += Math.abs(first.data[index] - last[index]);
        }
        sum += difference;
        count++;
        if (difference > 45) changed++;
      }
    }
    console.log(scene, roi, 'RGB MAE', sum / (count * 3), 'fraction over mean RGB 15', changed / count);
  }
})();
JS
```

## 추가 검수 — 10초 간격 인물과 예측 창

검수 파일: `96-actors-10second-sheet.jpg`, `91-middle-wool-forecast.jpg`, `92-wool-panel-scroll.jpg`. 아래는 선행 검수의 보완이며 이전 기록을 덮어쓰지 않는다.

### 인물: 관측과 추정 분리

- **관측:** 96 비교판의 위 두 칸과 아래 두 칸 모두 큰 곡창 벽에 두 인물, 작은 집 지붕에 두 인물이 같은 건물상의 위치에 남는다. 몸의 자세/미세 위치는 달라져 정지 비트맵과 픽셀 동일하다고 할 수는 없다. 바닥을 따라 다른 위치로 이동한 모습은 이 네 인물에서 보이지 않는다. 특히 작은 집 왼쪽 지붕 인물의 발이 계속 지붕 표면에 걸려 있는 인상이 유지된다.
- **관측:** 비교판 좌상단의 녹색 인물은 첫 칸에 보이다가 다음 칸에는 없으며, 화물 아이콘·연기 및 다른 활동 표현도 달라진다. 이 때문에 전체 화면이 정지한 상태라는 설명과는 맞지 않는다. 다만 잘린 비교판 안에서는 해당 인물이 어디까지 걸어갔는지 연속 경로를 추적할 수 없다.
- **촬영 기록에서 받은 사실:** 위행은 첫 00/19프레임, 아래행은 10초 대기 뒤의 00/19프레임이다. 이미지 자체로 10초 경과를 측정한 것은 아니다.
- **판정:** '일부 인물은 몸을 조금 흔들지만 장소는 고정, 다른 활동은 진행'이라는 설명이 증거에 맞는다. '이동 주민이 10초간 교착' 또는 '장식 NPC라 정상' 중 어느 설명인지 판단할 근거는 여전히 없다. 인물 상세/분류를 확인하기 전까지 원인 미확정으로 유지한다.

### 양모 공납 예측과 스크롤: 정상 확인 범위

- **관측:** 91에는 현재 재정 1115d, 현물 납부의 계절당 현금 107d와 두 계절 뒤 금고 901d, 즉시 현금 납부 340d와 금고 775d, 거절 시 차감 510d와 금고 605d가 읽힌다.
- **표시 산술:** 1115−2×107=901, 1115−340=775, 1115−510=605이므로 이 화면에 제시된 수입/지출 가정과 예측 금고 수치는 서로 맞는다. 실제 두 계절 뒤 경제 결과를 검증했다는 뜻은 아니다.
- **관측:** 91의 아래쪽 버튼은 내용 영역 하단에 일부만 나타나지만, 92에서는 내용이 위로 스크롤되고 `나중에 정하기` 버튼 전체가 오른쪽 아래에 보인다. 따라서 이 사례는 '영구적으로 버튼을 못 누르는 잘림'의 증거가 아니다. 스크롤로 하단 동작에 접근 가능한 정상 사례다.
- **관측:** 세 선택 카드의 폭과 좌우 정렬은 같고, 첫 카드만 긴 설명으로 높다. 이 사례에서 서로 다른 카드 높이를 무조건 '들쭉날쭉 버그'로 분류하지 않는다. 스크롤 가능함을 처음 보았을 때 쉽게 알아차릴 수 있는지는 별도 사용성 평가다.
