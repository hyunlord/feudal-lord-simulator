## 2. 틀 토큰 (먼저)
- 조사: 틀 두께가 약 30곳에 손으로 복사됐고(모달·환영 화면 16 px 직접, 판 칸 10 px, 그림 도우미마다 배율 ÷2·×0.7·×1.5 …), 안쪽 여백 토큰은 없었다. 틀 있는 33개 중 20개가 8 px 요구 전부터 내용이 칠한 틀 위에 앉아 있었다(사건 카드 −5 px, HUD 목표 칩 −11 px …). 9-slice 값은 모서리 크기라 칠한 테두리(판 3 px 대 32 px)와 다르다.
- `scripts/frameTokens.*` → `src/styles/frameTokens.generated.css` + `src/ui/frameTokens.generated.ts`: 틀 33종(css 17·틀 층 12·통그림 4)마다 그리는 두께와 그림에서 잰 안전 여백, 공통 `--frame-gap: 8px`. 모든 틀 규칙과 그림 도우미(wave8/14/19/25, 인물 카드·전기·세력 쪽·결정 비교)가 이것을 읽는다. 표면 루트는 `data-frame="<종류>"`, 틀 없는 표면은 `flat`.
- 계약: 모든 틀 표면의 계산된 `border-width` = 안전 여백, `padding` = 8 px → 브라우저의 내용 상자가 곧 감사의 "틀 안". 시험이 생성 파일 일치·직접 쓴 두께 0·알 수 없는 종류 0을 본다.

- 병합 전 검사 `ui-geometry`(강제): 기준 목록(줄 × 조건 × 검사 × 요소 경로, px 없음) 밖의 새 실패, 고쳐졌는데 남은 항목, 이유 없이 늘어난 기준, 새 예외, 열리지 않거나 등록 안 된 표면이면 실패. 입력은 UI에 닿는 파일만(엔진만 바꾼 푸시는 "no UI inputs changed"로 통과). 경고 무시는 이유(세 낱말 이상)와 같은 이유의 커밋 꼬리 `UI-Geometry-Override:` 필수, 병합 전 검사가 범위 안 무시 횟수와 이유를 찍는다.
- 고침 무리가 찾은 감사 도구의 오판(모두 고침, 느슨하게 한 것 아님 — 계약대로 잰다): 칠한 두께로 틀 안을 잼(안전 여백이어야), 틀 안 칸에 8 px를 두 번, 통그림에 가로·세로 배율을 따로(카드가 아래로 자라면 원이 어긋남), 틀 층·그림 칸을 넘침으로 셈, 아무것도 칠하지 않는 줄(위기 종·행동 칸 …)에 8 px 요구. 도구 쪽: `--only`가 끝 점 없으면 아무 줄도 안 고름 → 접두어로 읽고 고른 줄을 찍고 없으면 오류. 일시정지 저장의 장 끝 쪽이 안 열리던 흔들림(UI-9b)의 원인: 장면이 열린 뒤 5초에 쪽이 뜨는데 불러오기가 그보다 늦으면 감사의 첫 Escape가 막 뜨는 쪽을 닫았다 → 장 끝 장면은 20초.

## 5. HUD 면적 (사용자 판정 UIAUDIT-D1)
- 틀 여백 때문에 1280 × 800에서 예산을 넘음(보통 6.4 % / 6 %) → 1280에서만 +0.5 %p: 보통 6.5·배치 6.5·건설 15.5·구역 8.5 %(1920·태블릿 그대로), 작은 줄임(알약 칸 여백·칸 사이·글 13 px). 측정(DGX, 같은 빌드 세 번 `hud/run1~3.json`, 사용자 통과 규칙 "세 번 모두 예산 안"): 1280 보통 6.5 · 건설 15.3 · 배치 6.5 · 구역 7.8~7.9 · 구역(종류 고름) 8.3~8.4 · 선택 17.2 · 장부 23.0 · 2장 성벽 공사 6.5 %, 모두 안. 1920 보통 3.3 %, 태블릿 보통 7.3 % / 8 %.
