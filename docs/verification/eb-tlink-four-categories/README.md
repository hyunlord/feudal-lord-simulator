# EB-TLINK 네 분류 관문

기존 미래 직접 연결 점수를 지우지 않고, 동일 원본의 성숙한 무거운 답을 새 기준으로 분류한다. 이 디렉터리는 도구와 관측 소스의 사용 계약이다. 실제 seed별 새 점수와 통과 여부는 공식 재생 완료 뒤 별도 보관한다.

```sh
node scripts/engineBTlinkOutcomeCategoriesRun.mjs CONFIG SCORE OBSERVER_ROOT EXPECTED_HELPER_SHA NEW_OUTPUT
```

- `CONFIG`와 `SCORE`: 원래125년 answer-replay 설정 및 원본 점수 파일. 원자료로 점수를 다시 계산해 전체 객체가 일치해야 진행한다.
- `OBSERVER_ROOT`: 공식 관측 실행의 `seed-1/manifest.json` 등과 답별 압축 전후 상태. 입력 seed 집합은 CONFIG와 같아야 한다.
- `EXPECTED_HELPER_SHA`: 검토한 관측기 소스의 SHA256. 이번23d 관측은 `c2d00a7ea303ec9f4165f614e55d8759eb65dad0eff5adaf180a58c98fffda8b`다.
- `NEW_OUTPUT`: 존재하지 않는 보고서 경로. 인증 실패 때 부분 보고서를 만들지 않고, 기존 파일도 덮어쓰지 않는다. 완료 보고서는 시제품 관문에 따라 종료0/1을 반환한다.

## 분류와 분모

| 분류 | 요구 증거 |
| --- | --- |
| (가) 결과 보임 | 원래 정확한 자기 답 ID 미래 연결, 또는 실제 상태의 실질 변화 |
| (나) 무효과 | 검토한 처리 경로 전체의 실질 변화0. 처리 기록 변경은 제외 |
| (다) 설명 미완 | 미래 기대가 연결되지 않았거나, (가)/(나)/(라)를 확정할 증거가 부족함 |
| (라) 관측 부족·조건 미충족 | 3년 미완료는 기존 분모 밖. 조건 미충족은 전체 관측창의 명시적 증거 필요 |

시제품 관문은 성숙 답 중 (다)≤10%, 최종 관문은 (가)≥80%다. 두 판정은 독립적이다. 원래 점수 객체·SHA·미래 직접 분자/분모·기존 pass도 보고서에 그대로 남긴다. 즉시 변화0이어도 미래 기대가 아직 검증되지 않았다면 (나)로 바꾸지 않는다.

이번 공식 집계의 외부 확인값은 seed1–3·전체836·성숙816·관측 부족20·기존 미래 직접334다. 재사용 가능한 도구에는816을 고정하지 않으며, 각 실행의 원래 인증된 분모를 보존한다. 미분류 phase 답2개는 따로 보관하고 원래 분모에 더하지 않는다.

## 실제 변화의 범위

`engineBTlinkOutcomeEvidence.mjs`는 소스 핀이 검토한 구현과 일치할 때 실제 금고·관계·청지기 교체·세율·정책·감사/감독 방식·목재 명령 변화를 읽는다. 완전한0효과 증명은 현재 외부 영지 청원과 tolerate 감사에 한정한다. 다른 명령의 미검토 변경은 불명으로 남긴다. 새 엔진 소스는 핀을 검토 없이 갱신해 통과시킬 수 없다.

청원 `open→refused`, `decidedBy=lord`, 감사 `pending→tolerated`만으로 (가)가 되지 않는다. `trace`나 장부 전체를 처리 기록으로 무시하지 않으며, 알 수 없는 변경 경로가 있으면 완전한 무효과로 단정하지 않는다. 실제 화면 렌더링의 전수 검증과도 구별한다.

## 관측 소스와 검증 경계

[capture-source.json](capture-source.json)과 [정확한 관측 소스](capture-23d.ts.gz)는 실행에 제출한 바이트를 보존한다. 압축을 풀어 원래 `.omo/evidence/tlink-immediate-replay.ts` 위치에 복원하고, 같은 제품·도구 핀의 깨끗한 checkout에서 공식 DGX 실행기로만 돌린다. 새 출력 디렉터리를 요구하며 부분 실패를 완료 자료로 받지 않는다. 이 소스는 이번 고정23d 원자료 재생용이다.

관측기는 모든 원래 명령·답 ID, 전체 수집 parity, 최종 원시 상태 해시를 대조하고 답 직전/직후 상태와 전체 차분을 기록한다. loader는 원래 답 직후 command checkpoint에도 대조한다. 원래 자료에 답 직전 checkpoint가 없는 경우 그 값은 **새 공식 관측기의 측정**이며, 옛 자료가 독립적으로 보관한 값이라고 주장하지 않는다. 게시할 때 공식 실행 영수증과 seed manifest 해시를 함께 보존한다. 원시 중간 상태 hash 필드는 원시 바이트가 별도 보존되지 않아 형식만 확인하며, 보존한 canonical 상태와 차분은 직접 재계산한다.

관측 실행 `engineB-tlink-immediate-3ecee4b`은 슬롯을 받아 seed1–3을 재생 중이다. 여기에는 네 분류의 실제 통과 수치를 아직 싣지 않는다. 기존 확정 코어 무효과127건은 [엔진 요청서](../../requests/engine-B-inert.md), 감사94건의 처리 증거는 [별도 보관](../eb-tlink-audit-settlement/README.md)에 있다.

중간 원본의 seed1 `h-002358` / 038 `defer`는 답 직후 `estates.claims[1].strength`가55→50으로 바뀌었다. 판독기는 같은 주장 ID가 유일하게 같은 위치에 남아 있을 때 이 수치 변화를 권리 효과로 읽는다. `registryV4.ts:191`의 실제 변경과 `estateSuits.ts:179`의 심리 소비 경로를 소스 해시로 고정했다. 대상 교체·중복 ID·동일 값은 효과로 세지 않으며, 이 보완만으로 모든 효과가0이라는 증명을 만들지 않는다. 관련25시험 통과는 도구 검증이며, 미완료 관측을 전체 판의 점수로 사용하는 근거가 아니다.

046의 주문 소진 가설은 별도 준비 상태에서 실제 reducer로 검증했다. 주문16에서 취소를 제시한 뒤 주문0 상태로 답하면 `offerChoices`가 빈 배열이고 사건은 `invalid`가 된다. 일반 `decision` 이력은 남지만 trace의 성공한 답은 늘지 않고, 기존 수집기가 `invalid_registry_answer`로 제외한다. `tests/engineBTlinkSpecifiedTown.test.ts`가 이력 존재·무효 상태·실제 게임 값 불변·수집기 제외를 함께 확인한다. 따라서 이 사례를 성공한 무효과 답으로 추가하거나 정본 조건을 중복 수정하지 않는다. 처음 세웠던 “일반 결정 이력도 없어야 한다”는 가설은 이력 기록과 성공 분류의 기존 구분에 맞지 않아 폐기했으며, 전체125년의 자연 발생 증거로 확대하지 않는다.
