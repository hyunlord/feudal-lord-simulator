# 저마다의 영지 — 직접 조작하는 탐사 시제품

최소6축 요구에 대해8축(농업·교역·제작·군사·신앙·학문·해상·외교)을 구현했다. 각0~100, 합계100 이하의 연속 배분이며 예시 버튼은 편집 가능한 배분값이다. 영주는 건물을 놓지 않는다. 가구가 실제 후보 점수·비용·지형·숙련·원료/수요·경쟁·접근성을 비교하고 seed에 따라 선택한다. UI와 봇은 같은 경제·계약·전투 모듈을 실행한다.

그림은 SVG 자리 그림이다. 같은 초기 seed1/강가/24명/재고에서 게임 내144일(144회 압축 정산) 자란 농업·제작·군사 세 도시를 나란히 표시한다. 승인된 Astra 그림을 복사한 결과가 아니며, 원 PC의 물류·혈통·법정·연례 운영을 온전히 이식한 결과도 아니다. 사용자가 허용한 별도 단순화 모델이다.

## 직접 해보는 순서

동봉 prototype/RUN.md의 `node server.mjs`로 브라우저를 연다. 별도 의존성 설치 없이 사전 빌드 JS를 실행한다.

1. 방침 화면에서 지원 비중을 섞어 적용한다. 예산 초과는 거부된다.
2. 영지에서12일씩 또는 자동으로 성장시키고 시설 구성·재고·선택 이유를 읽는다.
3. 이웃에서 서로 필요한 재고를 제안하거나 출정 목적/입구를 선택한다. 계약은 거절·기한·유한 재고/운송비가 있다.
4. 전투의 실제 이동 경로·보급·노출·손실·약탈량을 확인한다. 소집한 주민은 다음 경제 정산의 일손에서 빠진다.
5. 같은 시작 세 방향 비교로 돌아가고, 기록을 저장한 뒤 새로고침/재현해 이어한다.

독립 AI 검수자는390×693 Chrome에서118초에 방침→성장→약탈→이유→비교를 마쳤다. 이는15분 이내 기능 순환의 관찰이며 사람의 독해 시간·흥미·다음 날 잔존을 측정한 값이 아니다. 검수 원문에는 관찰 성장의 흥미와 약한 전투 긴장이 모두 들어 있다.

## 실제 구현 경계

| 항목 | 시제품에서 확인할 것 | 제품에서 추가할 것 |
|---|---|---|
| 성장 | 8축 후보 점수, 유한 상인 재고, 원장, 비용을 낸 재건축 | 계절·권리·기술 확산·복잡 물류, 장기간 인구/수요 안정 |
| 공간 |21×21 지형·길·시설 위치가 경로/노출을 바꿈 |독립 성벽/문·창고 분산·해상 이동·정찰 정보 정책 |
| 전투 |한정 약탈과 관문 공성, 결정론 재현, 실제 손실·보급 |다도시 명령 순서·권위 서버·중복지급 방지·동맹/영토 |
| 외교 |실제 재고 예약·운송비·교환·불가침·위반 보상 |복잡 협상/권리·동맹 정치·동시 계약 정산 |
| 저장 |규칙/콘텐츠/소스·초기상태·명령·결과 해시 일치 재현 |인증·계정복구·서버revision·규칙 이행/시즌 |
| 모바일 |세로 화면,44px조작 목표,좁은 화면·저장·복원 브라우저 검사 |실기기 배터리/발열·백그라운드·푸시·스토어 |
| 외형 |기본/저녁 지도색만 바꾸는 무료 미리보기 |상품·결제·환불·시각 가독성/정보공정성 운영 |

화면을 닫아 둔 동안 서버에서 자라는 기능은 없다. 자동 정산은 열린 브라우저에서만 작동한다. 일시정지 가능한 로컬 탐사판과 멈추지 않는 제품 서버 시간은 다르다. 최종 게임은 장려금·인재·법을 통해 더 많은 조건을 바꾸는 설계지만, 이 시제품의 직접 조작은 방침 배분·계약·전투로 좁혔다. 장려금/인재/법이 구현돼 있다고 주장하지 않는다.

## 눈에 보이는 차이와 아직 약한 부분

세 도시 비교에서 농업은 길을 따라 퍼진 밭과 큰 식량 재고, 제작은 공방과 공구 재고, 군사는 북쪽 길의 경비 시설과 낮은 은화를 보인다. 이는 건물 도형과 색만 바꾼 스킨이 아니라 같은 모델에서 실제 생업·재고·위치가 달라진 결과다. 반면 사람 이동 애니메이션·행렬·독립 성곽은 없다. ‘서로 다른 게임을 하는’ 수준의 장기 경험까지 확인했다고 결론내리지 않는다.

승률과 다양성의 수치는 전체 리그/보충 실험 보고서로 따로 판단한다. 예시 한 화면의 농업 식량이 많다는 사실을 보편적 우승률로 바꾸지 않는다.
