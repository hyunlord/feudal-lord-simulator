# 고정 사건 7개 — 제안 사실행 조합 독립 검수

**제안 조합 7/7 DRAFT COMPOSITION PASS. 현재 엔진의 기존 사실행 보류 7/7은 유지한다.** 이 판정은 지정된 headline과 미설치 패치의 새 사실행을 함께 읽은 원고 품질 판정이다. 엔진 설치를 원고 완료조건으로 추가하지 않았다.

## 소스·capture 경계

- 성장: history.ts:406은 14세 경계 확인이며 일 배정 확인이 아니다. 수정 계약의 부모 둘 고유 조회, subject 현재 people 소속, 부모 현재 people/alive/leftYear 없음/동일 householdId가 필요하다. 과거 이주 부모의 예전 householdId를 동거로 세지 않는 독립 재검수 결과를 유지한다. 새 사실행은 역사적 법정 성년·새 노동 배정을 덧붙이지 않는다.
- 석벽: history.ts:461은 era=stone_town 이정표. era.ts:108–140은 기존 completed 구간에 교체 공사장을 추가한다. 따라서 completed는 석재 교체 완료와 다르다. 비어 있지 않은 유효 구간 배열·고유 ID·명시 boolean이라는 capture 조건을 유지한다.
- 사제: plague.ts:511–522는 curacy.vacantSince와 청원을 만들며 history.ts:651이 기록한다. 새 사실행은 실제 사제 인물 사망·역병 사인을 제거한다. buildings의 기존 church/chapel만 세고 공사장·현재 독해 시 건물은 사용하지 않는다.
- 모든 requiredSlots=[]; 이번 7개 패치 사실행도 매개변수/이름 슬롯이 없다. FIX12 이름 조회를 새로 우회하거나 고정 이름을 저장하지 않는다.

## 검증·보존

패치의 실제 추가 줄에서 사실행을 추출해 7개와 결합했고, 패치의 삭제 줄이 현재 engine source에 남아 있음을 확인했다. 수정 후보 source10파일/20구간 SHA·원문 일치를 재확인했다. 후보 전체·패치·현재 historyCopy 파일 SHA를 CHECKS.json에 남겼으며 실행 전후 불변이다. 원래 ADOPTION_LIMITS와 정본을 수정하지 않았다.

현재 엔진 옛 사실행과 결합하면 성장의 노동 시작, 석벽 물리 완공 독해, 사제 실제 사망의 기존 문제가 남는다. 그러므로 제안 조합 합격을 현재 엔진 보류 해제로 해석하면 안 된다. 실제 capture 구현·저장복원·formatter·UI 실행은 이번에 하지 않았다. 정본 합산·설치·커밋·push 없음. 새 graft 호출0회; 직전 독립 source 검토를 사용하고 source SHA/구간을 재확인했다.
