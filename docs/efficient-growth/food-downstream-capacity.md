# 가득 찬 농장과 부족한 방앗간을 구분

기준 `064ad248` seed5는 1,200,000틱에 24필지 중 L4 14, 인구436으로 실패했다. 실제2,400틱 빵320, 식사322/336, 밀666생산·640소비·17수출이었다. 방앗간4개는 모두 작업 중이고 밀12~15개, 원료 대기0/9,600틱이었다. 곡창7개에는 밀665개가 있었으며 모든 방앗간이 모든 곡창에 연결됐다. 하지만 농장5개가 `output_full`이어서 기존 전역 차단문이 방앗간 증설까지 막았다.

**원인 검증.** 원료 운송 단절, 실제 농업 생산 부족, 하류 방앗간 부족의 세 가설을 비교했다. 원료 재고와 경로·원료 대기0은 단절 가설을 반박한다. 동일 실패 상태에서 정상 비용으로 도로 하나와 방앗간 하나만 추가하고 12,000틱 진행했다. 마지막 창은 빵400·식사403/433·인구561, 원료 대기0이었다. 밀822생산−800소비−17수출=+5로, 마지막 창의 개선은 비축량 소진에 의존하지 않았다. 인구 회복으로 수요가 늘어 여전히 결식이 남았으며 합격으로 세지 않는다.

**변경.** 농장 출력 포화는 추가 농장 차단 근거로 유지한다. 단, 완전한 실제 관측 창에서 방앗간 원료 대기가0이고, 현재 모든 방앗간이 작업 가능하며, 실제 빵 부족을 충당하는 원료가 모든 방앗간에 연결된 곡창에 충분하면 방앗간 용량 부족으로 진단한다. 재고는 곡창마다 한 번만 센다. 서로 분리된 지구의 재고는 이 예외의 근거로 합치지 않는 보수적 제한이 있다. 거리·생산 상수로 처리량을 발명하지 않으며 기존 증설 상한·인력·완공 후 관측 창은 그대로다.

**검증.** 음식·기존12,000틱 성장 집중 회귀256개 통과 뒤 원료 부족·현재 입력 고갈 음성 사례2개를 추가했다(전용8개 모두 통과). TypeScript 통과. 예전 농장23개 실패 상태는 원료 대기1,712/7,200틱으로 여전히 운송 문제이며 방앗간을 추가하지 않는다. 정상 조언자로 seed5 실패 상태를24,000틱 이어가면 방앗간2개를5,520틱 간격으로 추가하고, 그 뒤 실제 상류 부족에 농장1개를 추가했다. 최종 인구636·빵466·식사458/486·원료 대기2.90%로 개선됐지만 완전 복구는 아니다. 모든 이어하기는 예산 종료 뒤 원인 확인이며 자연 성장 합격 증거가 아니다. 새 기본8필지·5개 지도 최종 QA가 남는다.
