# 실측 원료 부족보다 곡창을 먼저 짓던 성장 회귀 수정

기준: `64f2db76` 전체 회귀 2,058개 중 11개 실패. 이 변경은 식량 우선순위 결함과 식량 정책에 종속된 두 테스트만 다룬다. 경제·기본 8필지·관측 2,400틱·인구 합격 기준·D24는 변경하지 않았다.

## 원인과 실제 재현

정상 `DEFAULT_GAME_STATE`에서 기존 조언자·리듀서·틱 엔진으로 12,000틱을 진행했다. 세 가설(관측 시간, 운송/인력, 조언 우선순위)을 같은 기록으로 구별했다. 4,025틱에 방앗간의 완공 후 2,400틱 관측이 끝났고 원료 부족을 이미 측정했지만, `foodCoverageAction`이 먼저 새 곡창을 선택했다. 새 곡창이 완공된 4,542틱부터 추가 관측이 시작되어 밀밭은 6,942틱까지 늦어졌다. 기존 시설 인력은 충족됐고 관측 결과도 `effective=true`여서 반복 방지나 인력 부족이 원인은 아니었다.

| 동일 12,000틱 정상 실행 | 수정 전 | 우선순위만 수정 후 |
|---|---:|---:|
| 최고 / 마지막 인구 | 82 / 45 | 104 / 97 |
| 마지막 주택 | 4 | 6 |
| 4,025틱 선택 | 곡창 | 밀밭 |

실측 생산 부족에 따른 밀밭·방앗간 조치를 선택적 곡창 증설보다 먼저 적용했다. 실제 단절 도로 복구는 여전히 최우선이다. 생산 증설을 결정하지 않은 경로/운송/인력 진단에서는 기존 배급 범위 복구가 계속 가능하다. 관측 대기와 모든 시설 상한은 그대로다.

## 검증과 파일

- `autoplayFood.ts`: 위 우선순위 한 곳 수정.
- `autoplayPhase12Part5.test.ts`: 원래 최고 100명·최종 80명·최고의 75% 유지·배급 기준을 그대로 통과. 첫 식량 공사 세 건이 밀밭→방앗간→밀밭임을 추가 확인.
- `autoplayMaterialPolicyPortable.test.ts`: 건강한 비축량을 가진 수작업 상태에서 새 정책은 구형 확인 메타데이터를 만들지 않으며, 명시적으로 전달된 기존 메타데이터와 자재 공사 기록은 어댑터·리듀서가 함께 보존함을 검사. 자재 런타임은 불변.
- `autoplaySustainability.test.ts`: 이론적 시설 수만으로 추가 방앗간을 요구하던 합성 상태를 관측 없는 증설 금지 검사로 변경. 실제 관측 기반 식량 회귀는 유지.
- 식량·관련 검사 234개 통과 후 수정한 메타데이터 파일 4개 통과(분리 실행); 별도 12,000틱 회귀 통과. TypeScript 및 diff 검사 통과.

전체 회귀 재실행·8필지 L4·5개 seed 효율/캡처 검증은 동일 QA 담당자의 후속 단계다. 12,000틱 회복을 최종 자연 성장 합격으로 해석하지 않는다. 임시 추적 파일과 디버그 저널은 요약 후 제거했다.
