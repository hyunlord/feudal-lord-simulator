# EB-WEIGHT: 실제 저장에서 10배속 결과 노출 확인 준비

실행 전이다. `engineBLiveSpeedCapture.mjs`는 원본 seed1의 005 답변 저장(h-002653, tick40015)에서 기존 속도 인장을 두 번 눌러 5배속과 10배속을 확인하고, 정상 UI 루프로 최대 3000틱을 관측한다. 원본 소스는2485af40046793f1856829fa1161dc4431942aa7, 저장 manifest SHA256은e4615d5a01c18d7b6adba9f3eec12c570f0ab14041266e947305674c04e2b93d다.

새 기록 중 답변 이후이고 정확히 그 답변 ID를 원인으로 갖는 결과만 집계한다. 자동으로 노출된 실제 결과 ID와 수동 연대기 탐색을 구분한다. 자동 결과를 먼저 관측한 경우에만 정지 상태에서 답변→실제 결과→원인 왕복을 확인한다. 알 수 없는 대화상자나 추가 결정이 필요하면 선택하지 않고 중단하며 실패 자료를 보존한다.

이는 봇이 없는 새 후속 진행이다. 원래125년 판의 이후 상태나 결과 ID가 같다는 주장이 아니며, 한 건의 성공으로56건 전체 가시성을 증명하지 않는다. 화면 proof는 표시 상태만 제공한다. 자동 식별은 기존 `lord-moment:<historyId>` 표면에 한정하며 다른 표면은 미검증이다. 스크린샷 판독과 실제 DGX 실행, 서버 정리 확인은 아직 필요하다.

오프라인 확인: 새 기록 경계3시험과 기존 서버 정리4·설정 제어3·Playwright 출처5시험, 합계15개 통과. 관련 lint와 diff 검사 통과. 제품 소스·저장 형식·화면 변경은 없다. 역사 재현이 종료되고 실제 출처·산출물·프로세스 정리를 검증한 뒤 실험 줄 하나로 실행한다. 기존 공용 관문 실패와 P-T1·P-C3 미완료 상태는 유지한다.
