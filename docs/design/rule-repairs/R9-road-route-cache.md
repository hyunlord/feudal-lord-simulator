# R9 도로 위치→건물 경로 메모이제이션

## 원인과 변경 범위

고정 커밋 `403cfa9c43937cc273b8aa622537d8643021e2b7`의 seed3 자연 상태 324,000틱을 조사했다. 건물109·이동자75·공사8개 상태에서 `routeIsIntact → returnPath → resolveRoadToBuildingRoute`가 이동 중 수레의 같은 도착 도로 칸에서 귀환 경로를 매 틱 다시 구했다. 기존 건물 쌍 경로 캐시는 이 조회를 처리하지 않는다. 프로필에서 `resolveRoadToBuildingRoute`는 `advanceTick` 표본 시간의 약60%였다. 별도120틱 조회 기록은4,181회 중3,579회(85.6%)가 동일 그래프·시작 칸·목적지 조회였고 경로 차이는0건이었다.

`resolveRoadToBuildingRoute`에만 최대2,048개 FIFO 경로 캐시를 추가했다. 기존 BFS·접점 정렬·동률 선택을 그대로 호출해 그 결과(경로 또는 `null`)를 보관한다. 경로 검증을 생략하거나 이동·생산·건설·자동 성장 규칙을 변경하지 않는다. 저장되는 `GameState.pathCache`와 별개의 런타임 파생 캐시이며 저장 스키마와 전체 상태 출력은 바뀌지 않는다.

## 무효화와 상한

- 바깥 `WeakMap` 키인 불변 타일 배열의 참조 변경은 도로·다리와 접안 칸·건물 점유·지형 변경을 반영한다.
- 한 배열에는 현재 그래프 버킷 하나만 보관한다. `width`, `height`, `roadRevision`, 기존 `roadTopologySignature`의 완공 성벽·기본 문·추가 문이 바뀌면 버킷을 교체한다.
- 조회 키에는 시작 칸, 목적지ID·종류·위치, `buildingFootprint`의 실제 너비·높이를 포함한다. 합필을 고정 종류 크기로 대체하지 않는다.
- 재고·작업자·틱은 이 경로 함수의 그래프 입력이 아니므로 키에서 제외한다. 캐시 키를 위해 게임 상태를 수정하지 않는다.
- 2,048개를 넘으면 가장 오래 들어온 항목 하나를 제거한다. 자연120틱 후 실제 항목2,048개·경로 좌표72,457개였다. 진단용 JSON 직렬화 크기는1,361,180바이트이며 V8 힙 사용량이라고 해석하지 않는다. 타일 배열을 더 이상 참조하지 않으면 해당 WeakMap 버킷도 회수 가능하다.

## 기준 상태와 검증

원본 fixture: `tests/fixtures/routing/seed3-403cfa9-324000.json.gz`. 비압축 SHA256은 `cb85c6f37c236f27d3c0a4336766b1a22e002817be57d54fa187c9bc1872fa84`다. 고정 커밋으로 실행 중이던 seed3 체크포인트를 그대로 복사했고 자원·건물·경로를 주입하지 않았다.

변경 전에 새 행동 고정 검사6개를 통과시켰다. 변경 후에는 성공·실패 경로, 불변 도로·다리·완공 벽·문 변경, 같은ID의 위치·종류·합필 점유 변경, 지도 크기·revision, 요청 순서,2,048개 상한을 검사한다. 자연120틱에서는 유지된 런타임 캐시와 매 틱 새 타일 배열로 비운 캐시 모두 기준 전체 상태 SHA256 `877a1953f818adbb9e52df842901b8eac8aa363189a608b4d44cace54ede95d3`와 일치한다. 직렬화된 `pathCache`1,214개 항목도 비교에 포함된다.

## 프로파일러 없는 전후 측정

원본403 코드와 원본403에서 `routing.ts`만 바꾼 독립 임시 복제본을 비교했다. 매 표본은 새 Node 프로세스·동일 원본 상태로 시작해 정상120틱을 진행했다. 다섯 쌍을 번갈아 실행했으며 CPU 프로파일러는 껐다. 호스트의 다른 작업 부하는 포함된다.

| 2 | 475.94 | 290.06 |
