# S8 가드레일 후속 — 석조 진입 시 저장 공간 막힘 해소

## 자연 재현과 진단

`403cfa9` seed 5의 504,000틱과 528,000틱 원본 상태를 `tests/fixtures/storage-recovery/`에 편집 없이 보존했다. 창고 5곳의 재고는 24,000틱 동안 원목323·목재281·원석50·석재346(1000/1000)으로 동일했다. 석공소는 원석1·석재19로 20/20이며 가용 석재365/400만 시대 조건에 부족했다. 실제 전체 조언은 `none`이었다.

각 창고 목재는 48/60/53/60/60으로 품목별 판매 비축60 이하이다. 시장은 빵(가격5)을 원석(3)·원목(2)보다 먼저 팔고, 해당2,400틱에는 시장2곳의60회 판매가 모두 빵이었다. 석재는 기존 시대 비축400으로 보호된다. 기존 창고 자동 확장의1000은 일반 목표이며 창고 건설을 금지하는 게임 규칙이나 효율 가드레일의 시설 상한이 아니다.

**영구 정지라고 판정하지 않는다.** 동결된 수정 전 실행도 이후 식량 시설을 더 짓고 자재 공간이 열려 564,000틱 관측에서 석조 시대에 도달했다. 이 수정은 다른 시설의 우연한 자재 소비를 기다리는 대신 실제 목표를 막은 저장 공간을 봇이 해결하게 한다.

## 최소 명세와 구현

- `autoplayStorageRecovery.ts:needsStoneStorageRecovery`: 목책 시대에서 실제 석재 시대 조건이 미달이고, 공용 창고의 석재 입고 공간이 없고, 가동·인력·도로 조건을 갖춘 석공소의 완성 석재가 꽉 찬 내부 버퍼에 남을 때만 저장 확장을 제안한다.
- 진행 중인 창고 공사가 있으면 추가하지 않는다. 석재 충족·여유 창고·빈 완성품 버퍼·가동 중지·내부 버퍼 여유에서는 제안하지 않는다.
- `autoplay.ts:storageAction`: 위 조건일 때 일반1000목표에 도달했어도 기존 `buildAction('storehouse')`를 호출한다. 자재40·법적 배치·서비스 공간·성벽·배송 접근 검사는 기존 경로를 그대로 사용한다. 한 곳씩 완공 후 최신 상태를 다시 판정한다.
- 경제·용량·생산·시장 판매·R6 공사 판매 비축·저장 스키마는 변경하지 않는다. 새 시설 수 비율이나 상한도 만들지 않는다.

## 검증

- RED: 수정 전 자연504,000틱 전체 조언 `none`; 합법 창고/도로 조치를 요구하는 테스트 실패.
- GREEN: 자연 상태에서 전체 조언·실제 reducer·정상 tick(조언120틱 간격), 자원 주입 없이 창고1곳을 추가하고 **524,761틱에 석조 시대** 도달. 경과 **20,761틱 ≤24,000틱**, 초기 실행 약31초.
- 반례: 석재가 충분함, 공용 창고에 공간 있음, 석공소 완성품 없음, 내부 버퍼 여유, 생산 중지, 창고 공사 진행 중에서는 확장하지 않음.
- `tests/autoplayStorageRecovery.test.ts`와 관련 서비스·목재 회귀, typecheck 결과는 최종 보고에 기록한다. 전체 회귀·5개 seed 최종 판정은 본 작업의 최종 커밋 검증과 별개이며 이 제한된 테스트로 대체하지 않는다.
