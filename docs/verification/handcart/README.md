# RB-HANDCART: 실제 운반자의 손수레 1장

Wave 13 확정 손수레 시트 **1장**을 네 방향·보행 두 자세로 연결했다. 기존 운반자의 방향·걸음·실제 화물을 읽으며 새 운반자나 운송 규칙은 만들지 않는다. 제품 커밋은 `62e4a720`, 실제 화면 기준 본선은 `bd626bf2`다. 게시 전 변경 시험·기하·병합 검사는 별도 실행 결과로 마무리한다.

그림은 원본과 바이트가 같고 384×148이다. 손잡이 피벗·발에서의 변위·짐 접점은 `core` 팩의 `walker-transport` 계약에 있다. 투명 여백이 넓어도 짐은 기존 9.68 세계 px 너비를 유지한다. 합성 인물·기존 배우 경로 모두 연결했고 새 그림이 늦게 오면 기존 수레를 쓴다. 인물이 아직 없을 때 수레만 먼저 나타나지 않는다. [계약](CONTRACT.md) · [등록 자료](registration.json) · [출처](provenance.json).

## 실제 화면에서 바뀐 것

여름·겨울 줌 1.0·0.6와 운반자 확대 장면을 합쳐 **전후 16쌍**을 확인했다. 저장 SHA·상태 SHA·틱·카메라·운반자 위치·화물·외형은 모두 같다. 인물을 옮기거나 짐을 심지 않았다. 여름 운반자 둘은 집 뒤에 있어 이 장면만으로 손잡이 접점을 판정하지 않았다. 가을 강변의 남성 운반자와 겨울 길가의 여성 운반자로 확인 범위를 보완했다.

확대판에서는 거친 목재 수레의 바퀴·적재함이 새 그림으로 바뀌고, 남성의 곡물 짐과 겨울 운반자의 빈 수레·빵 짐이 손잡이에 이어진다. SE·SW·NW 방향에서 이를 확인했다. **NE 방향 접점은 나무·건물에 가려져 미판정**이다. 4방향×2자세의 자르기·앞뒤 순서는 시험으로 별도 확인했으며 이를 가림 없는 실제 화면 판정으로 바꾸어 적지 않는다.

줌 0.6에서도 새 수레는 세계 캔버스에 그려진다. 그러나 개별 화물 종류·바퀴살 회전까지 눈으로 읽는다고 주장하지 않는다. 준비판에서 남성 손 최대 잔차 3.43 세계 px가 남았고 기존 외투·손 소품은 손잡이와 겹칠 수 있다. 지붕·나무의 가림은 기존 도시 깊이 순서다. 바람·눈·연기는 벽시계에 따라 움직이므로 전후 전체 픽셀 차이를 수레의 변화로 계산하지 않는다.

문서에는 여름·겨울 전후 8장과 실제 확대 4쌍을 남겼다. 확대판은 화면 일부를 같은 비율로 4배 최근접 확대했다. [전후 기본 8쌍](comparison.json) · [보완 8쌍](detail-comparison.json) · [판정과 한계](visual-verdict.json). 전체 JPEG·입력 저장·재현 코드는 전달 ZIP에 포함한다.

첫 보완 캡처는 새 시트가 오기 전 기존 수레의 로딩 대체 경로가 상세 기록 2,000개를 채웠다. 최종 그림 표시를 단정할 수 없어 실패 기록을 보존했다. 출처별 횟수는 제한 없이 세고 새 시트의 실제 그리기를 기다린 뒤 마지막 두 프레임만 다시 기록했다. 이때 제품 코드는 바꾸지 않았다. 채택한 네 실행에서 네트워크 요청 취소 4건은 별도로 남겼으며 페이지 예외 0과 혼동하지 않는다.

## 원칙 점검

- P-V1·P-X1: 실제 carter의 위치·방향·화물만 읽는다. 전후 상태 해시로 시뮬레이션 불변을 확인했다.
- P-V2·P-V3: 세계 크기에서는 작은 수레, 확대에서는 손잡이·짐을 확인했다. NE 접점과 바퀴 회전 판독 한계는 남긴다.
- P-M1·P-T5: 그림·방향·자르기·부착점·짐 폭은 계약 데이터에 있다. 같은 종류를 추가할 때 화면 코드에 경로·좌표를 넣지 않는다.

원본에 caBX가 없어 제거는 0건이다. 제작 기록에 없는 도구 모델·정확한 생성 시각·seed를 추정하지 않았다. 원본 제작의 자르기·축소·바퀴 무늬 회전 기록은 [제작 기록](source-record.json)에 보존했다.

## 관문 줄 이전과 현재 게시 상태

본선 크기 가드 복구 `8936a469`를 포함했다. 기존 `astra-HANDCART-geometry-62e4a72`는 실험 줄에서 실행 전 취소했고, 관문 줄 재등록 `astra-HANDCART-geometry-gate-f12ea64`도 미커밋 장부가 포함된 dirty=1 입력이라 취소했다. 둘 다 합격 증거로 쓰지 않는다. 첫 실행의 --only 원문은 복구하지 못했으므로 동일 목록이라고 주장하지 않는다. 깨끗한 커밋 입력에서 `hud.status-pill,hud.time-cluster,hud.action-dock,map.selection.house` 네 줄을 --gate로 다시 검사한다. 결과의 dirty 값을 강제로 바꾸지 않는다.

이 기록 시점에는 최종 변경 시험·기하·병합 검사와 본선 게시가 끝나지 않았다. 제품·출처·실제 화면 장부를 한 커밋으로 정리했으며, 이후 관문 결과는 해당 실행 이름과 함께 판정한다.
