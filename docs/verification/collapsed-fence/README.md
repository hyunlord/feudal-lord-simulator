# 폐울타리 두 장 — 실제 화면과 설치 근거

**준비 장면 6쌍의 실제 소비는 통과했다. 0.6배에서 폐울타리 세부 판독은 통과로 보지 않는다.** 게시 전 실제 화면 기록이며 최종 관문 절차와 실행 증거는 문서 끝 및 ZIP에 기록한다.

최종 기준 7de6dce4ccd8d581105246c177a5ff839780420e → 통합 제품 2fd03f3493bd6620f591a7885214bf4c40d65996. 첫 제품233be9a2에서 확인한 화면을 LOGS 본선 뒤 다시 촬영했다. 여름·겨울 × 줌1/0.6/3, 1280×800 실제 게임 브라우저 화면이다. 문서에는 after 6장과 before 근접 2장을 싣는다. before/after 전체 6쌍은 두 작업 폴더의 output/rb-collapsed-fence-{before,after}에 보관되어 있다. 모든 쌍에서 저장 SHA, 실제 state SHA, tick, 카메라가 같다. `browser-audit.json`에 두 anchor의 실제 PNG draw와 큐 내용을 기록했다.

원본 128×160과 피벗64,120을 유지하고 균일 .25로 그려 세계 canvas32×40이 된다. 줌3은 원본을, 줌1과0.6은 기존 공용 mip cache를 소비한다. 양축 확대값 동일·음수 축 없음·회전/shear 없음도 실제 draw 기록으로 확인했다. 여름에는 여름 그림, 겨울에는 겨울 그림을 각각 두 위치에서 그렸다.

## 화면에서 보인 것

- 3배: 기존의 큰 직선 패널이 빠지고 낮은 부러진 레일과 틈이 보인다. 그 뒤/옆의 정상 패널과 문은 유지된다. 새 잔해는 기존 정상 패널보다 작고 낮다. 여름 첫 위치는 기존 빈집 잡초와 상당 부분 섞이며 겨울에는 밝은 레일이 더 잘 보인다.
- 1배: 위치를 알고 비교하면 틈과 작은 잔해를 찾을 수 있다. 그림 자체만 보고 폐울타리라고 빠르게 판독하는 힘은 약하다.
- 0.6배: 세부 레일과 파손 뜻을 판독하기 어렵다. 이를 가독성 합격이나 도시 전체에서 읽히는 변화라고 부르지 않는다.
- 근접 장면에서 새 사각 블록, 도로 위 큰 패치, 강제 뒤집기·찌그러뜨림은 보이지 않는다. 다만 선언 ground footprint 안에 모든 실제 alpha가 들어가는 픽셀 증명이나, 움직이는 워커가 양쪽으로 지나가는 가림 증거는 아니다.

## 실제 소비·복귀

새 그림은 `house-44-42-0`의 `(44.5,11.75)`와 `house-46-42-0`의 `(45.5,11.75)`에 놓였다. 브라우저가 가져온 실제 `withYardHurdles`에서 두 원래 직선 panel ID는 없어지고 각 집마다 대체 ID가 정확히 하나씩 생겼다. 원래 ID와 새 ID를 동시에 넣지 않았다. depth는 새 anchor 합56.25/57.25이다.

같은 browser module과 ground scene 객체에서 복사한 상태의 residents를1로, abandonedTick을 없애거나, tick을 abandonedTick 전으로 바꾸면 두 원래 패널이 복원되고 새 ID가 사라졌다. 이는 실제 큐 소비 함수의 복귀 검증이다. 표시 중인 게임 state를 바꾸지는 않았으므로 **재입주·되감기 복귀 화면을 촬영했다고 주장하지 않는다.** Mac 회귀153/153 및 NAT-5 이전36장 고정 digest도 그대로다.

## 준비 저장의 한계

원본은 `tests/fixtures/distributor-entry-seed5.json.gz`를 정상 loadSaveFile로 읽었다. 두 집은 이미 residents0이지만 abandonedTick이 없어 준비 과정에서 그 필드를 추가했고, 여름·겨울 중간 tick을 지정했다. 모든 변경을 `prepared-scene-manifest.json`에 적었다. 물체·마당·건물·인구를 추가하지 않았다. 이 원본 tick은1,200,000으로 HUD가1600년을 표시한다. **1300–1450 캠페인의 자연 도달/폐가 발생 증거가 아닌 렌더 조건 준비 장면**이다.

## 최신 본선 합친 뒤 재촬영

`astra-FENCE-final-before-7de6dce`(57.5초)와 `astra-FENCE-final-after-2fd03f3`(58.3초), 두 실행 모두 오류0·6뷰이다. 두 실행의 관련 프로세스가 종료된 뒤 관문으로 넘어갔다. 화면의 작은 배율 판독 한계는 이전 판정과 같다. 새 패널을 크게 보이게 하려고 원본을 확대·왜곡하지 않았다.
