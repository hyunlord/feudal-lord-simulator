# 공사 비축 판정 비용 최적화 검토

판정: 구현 차단 사항 없음. 읽기 전용 검토이며 무거운 실행 검증은 추가하지 않았다.

- `wallDeliveryAvailable`는 비축 자원이 다르면 원래 가용 재고를 그대로 반환한다. 양수 재고만 모으므로 기존 `every(...===0)`는 false다. 새 자원 불일치 조기 반환은 동치다.
- 양수 floor가 없으면 각 가용 재고 >0에서 floor 0을 빼도 >0이다. 기존 결과가 true일 수 없으므로 조기 반환은 동치다. 공급처가 없을 때도 기존 length>0가 false다.
- 가용 재고는 실물 재고에서 stockReserved를 뺀 값이다. 그 값이 0인 건물은 기존에도 sourceStocks에 포함되지 않았다. 해당 건물의 경로 계산만 생략하며 예약된 물자를 가용 재고로 취급하지 않는다.
- 양수 재고인데 경로가 null이면 여전히 제외한다. 혼합 공급처 중 비축되지 않은 접근 가능한 양수 재고가 하나라도 있으면 every가 false인 규칙을 유지한다.
- 국고 목재는 건물 재고와 별도다. 양수 국고 재고일 때 집의 경로를 계속 검사한다. 집 자체 재고 0을 건너뛰더라도 국고 분기의 집 경로 검사에는 영향 없다. 석벽에는 국고 목재가 섞이지 않는다.
- site 예약량은 constructionDeliveryNeed에서 빠진다. 배달 필요량 0이면 기존과 같이 false다. 공사 우선 정책도 그대로 false다.
- 새 캐시·상태·저장 스키마 없음. 새 테스트는 불일치/0 floor/공급처 없음/경로 없음/국고 분기를 직접 다룬다. git diff --check 통과.

증빙 표현 한계: `/tmp/r1-wall-reserve-after.log`의 실제 키는 `fullStateEqualExceptDerivedPathCache:true`이며 캐시 개수 165/165다. 이 파일만으로 캐시 내용까지 동일하다는 주장은 확인할 수 없다. 일반적으로 호출 생략은 route port의 파생 캐시 채움 횟수를 줄일 수 있으므로, 전체 GameState 동일 주장에는 별도 실제 deep equality 증거를 붙여야 한다. 불리언 판정 동치와는 별개다.
