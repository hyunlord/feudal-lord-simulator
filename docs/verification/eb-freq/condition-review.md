관문: 정본 대조34/34 일치 · 현재 어댑터 결함075 수정 · 집중 회귀19/19 통과(Mac). 역사 B476의 개별 실패 원인은 이 수정으로 소급 확정하지 않는다.

[앞17 원문·실험](condition-audit-first17.json)과 [뒤17 원문·실험](condition-audit-last17.json)은 기존 역사40 중 조건34를 정확히 나눈다. 각 행에 병합 전 정본 파일·JSON pointer·행 번호·SHA, 실제 생성기 변환 뒤 AST, 바인딩/맥락/선택지 전제, 사실 생산 소스, 과거 실행 증거와 최신 실행의 구분을 담았다. `readCanon`과 실제 `withPetitionContextAdapter`·`withChapterPetitionAdapter` 및 생성기 strip을 거친34개 모두 현재 생성 명세와 같다. 이것만으로 맥락 어댑터가 옳다고 판정하지 않고 원문 발신자·조건과 실제 읽기 함수를 따로 대조했다.

075의 정본 발신자는 소송 서기/영지 관리인이다. 기존 맥락은 본거지 인물 명부의 청지기만 허용하여, 실제 영주 소유·점유 영지에 재직 중인 성인 관리인이 있어도 제안이 사라졌다. 동일 상태의 본거지 청지기만 제거하는 순수 counterexample에서 재현했고, 본거지 청지기 우선은 유지하면서 실제 영지 관리인을 대체 서기로 읽도록 고쳤다. 사망·떠남·미성년·비청지기·비재직·타인 소유/점유·감독 불일치는 제외하고 고정된 당사자를 교체하지 않는다. 정본 조건식·선택지·확률·경제·저장·화면은 변경하지 않았다.

회귀는 새16개 중 기존 코드에서4개 실패(RED), 수정 뒤16개와 기존 묶음2의3개 모두 통과(GREEN). 타입 검사·범위 ESLint·diff 검사도 통과했고, 독립 검토에서 정본보다 넓어지는 조건이나 구현 결함을 찾지 못했다. 이것은 바인딩의 재현과 수정 증거이며 자연 노출 증가나 역사075의476번 탈락 모두의 설명은 아니다.

061의 작은 권리 사실 생산자는 존재하지만 기본 봇의 전역 권리 상신 규칙이 경로를 억제한다. 019의 직접 감독·주의력과 현직 제외 상인/농민 후보 전제는 정본 자체다. 031은 청지기 모드, 059는 직접 감독 경로다. 이 경우 사실 생산 부재나 어댑터 결함으로 이름을 바꿔 조건을 완화하지 않았다. 147의 원래 시대창32계절 확률 실패 증거도 유지했다.

추가 변형048·078은34개 밖이다. 048의 정상 영주 마을 목초지 생산 공백은 [엔진 요청](../../requests/engine-B-freq-facts.md)에 실제 원청원17·변형0 및 준비 상태 변경을 명시했다. 샌드박스/천 생산 봇의 구역 칠하기는 정상 영주 생산 증거가 아니다. 078은019 제안 경로와 봇 정책을 구분하며, 엔진에 실제 후보 생산자가 없다고 주장하지 않는다.

역사40의 조건34·경쟁4·시대2는 당시 자료의 유력 분류로 보존한다. 이번33개 무결함 판정은 검토 범위에서 더 좁은 구현을 발견하지 못했다는 뜻이며, 모든 자연 경로가 반드시 도달한다는 보증이 아니다. 추가 장기 실행을 감사 게시의 선행 조건으로 두지 않는다.
