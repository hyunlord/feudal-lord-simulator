## 묶음 전체 결정 빈도 재판정

새 판 없이 Mac에서 보존된 두 답별 보고서를 다시 셌다. seed3개×125년의375개 seed-년을 모으며 결정0건인 해도 포함한다. 세 영지의 같은 달력 해를 더한125칸이 아니다. 빈도에는 끝의3년 관측 부족 답도 포함하고, 결과 연결률의 성숙 분모816/842만으로 세지 않는다. 각 해의 답 ID로 재구성한 건수가 기존 비교 파일의 연간 배열과 모두 일치한다.

seed별 총수는245→280, 282→262, 309→322이고,4건 초과 해는8→10, 7→4, 11→13이다. [pooled-frequency-review.json](pooled-frequency-review.json)에 입력 해시, 계산 정의,375칸, 사건·선택지별 증감 전체,4건 초과 해의 모든 답 ID와 새 판정이 있다. 이전 [comparison.json](comparison.json)의 seed별 관문은 당시 실행 원자료로 보존하며, 현행 판정은 이 추가 자료를 따른다.

라의 관측 부족22건은 3년 관측 분모 밖이다. 전체 답은836→864, 원래 미래 직접 연결 점수는334/816(40.93%)→590/842(70.07%)이다. 새 분류 점수와 구분해 원본 점수도 보존했다.

기준 답변 판은 보존된 공식 `23d1226` 측정이다. 요청된 `db750c16`과 결정 카드 표현 차이가 있으며, db750을 새로125년 돌린 결과라고 주장하지 않는다. 기준 압축 보고서 SHA256은 `5519e0d87775f5c48dd3629f36b676cdc49d7e4c35b32a1f5f4459bc03d14d33`이다. 비영주 비교는 별도로 실제 db750 대72c 원시 상태를 비교했다.

## 빈도 증가의 관측 근거

특허 거절 답은 seed 1/2/3 각각71→56, 81→39, 84→39로 줄었다. 감사 묵인 답은33→81, 38→67, 24→87로 늘었다. 새 오류가 실제로 남으므로 무효과는 없어졌지만, 영주에게 돌아오는 감사 횟수는 증가했다. 이는 종류별 관측이며 각 증가분 전체의 반사실적 인과 증명은 아니다.

| 결정 종류 | 전 | 후 | 증감 |
| --- | --- | --- | --- |
| 감사 묵인 | 95 | 235 | +140 |
| 감사 처벌 | 27 | 26 | −1 |
| 특허 청원 거절 | 236 | 134 | −102 |
| 수리 청원 | 164 | 162 | −2 |
| 지대 감면 청원 | 52 | 49 | −3 |

특허 반복은 줄었고 증가의 주된 종류는 감사 묵인이다. 소스72c77f6의 반복 경로도 확인했다. `src/engine/stewardshipConsequences.ts:20`은 드러난 오류까지 합해 매 철 `ceil(미회수/16)`을 네 철 새로 부과한다. `src/engine/stewardship.ts:357`과366은 그 손실을 청지기의 오류에 더하고,391은 오류가 양수면 다음 감사를 pending으로 올린다. 그 감사를 다시 묵인하면 같은 생성 경로를 탄다. 오류0·충성100 보고 하향(`stewardshipConsequences.ts:27`)은 이 양수 오류에 적용되지 않는다.

특히 계속 재직하고 매 철 가용 수입이1 이상이며 다른 오류가 없는 경우에도, 미회수4→철당1씩 네 철→다음 감사 오류4가 가능해 올림 때문에 스스로 사라지지 않는다. 이는 소스 산술로 확인한 조건부 반복 경로이며, 관측 증가140건 전부를 그 경로에 귀속했다는 뜻은 아니다. 엔진 검토 대상은 **기존 묵인의 후속 손실이 다시 묵인 압력의 원금이 되어 새 상신을 반복하는 규칙**이다. 실제 손실·원인 연결을 유지하면서 후속 보고와 새로운 영주 결정을 구분해야 한다. 이번에는 규칙·저장·기존 scorer를 변경하지 않았다.

seed 1 최대6건은1338년이다. 기존5건(징집, 수리, 042, 전비, 감사)에 비해 새 판에는092가 함께 나타났다. 실제 답 ID와 시각은 [frequency-detail.json](frequency-detail.json)에 있다. 답 집합과 선택도 바뀌었으므로 단순히 같은 다섯 답에 처리 기록을 더했다고 해석하지 않는다. 규칙·문턱을 결과에 맞춰 바꾸지 않았고 후속 수정은 아직 없다.

## 증거와 재검증

- [comparison.json](comparison.json): seed별·합산 분류/연간125칸/관문 및 기준선 한계.
- [categories.json.gz](categories.json.gz): 답별 실제 변화와 분류 증거, 원래 점수, 도구 핀.
- [legacy-score.json.gz](legacy-score.json.gz): 변경하지 않은 미래 직접 연결 점수.
- [manifest.json](manifest.json): 실행 ID·소스·보관 파일 및 원시/압축 SHA256.
- [producer-status.json](producer-status.json), producer/rescore 로그·종료 코드·시간: 생성 성공과 채점 단계 실패를 구분.
- [비영주 해시](../native/README.md): seed 1~5 모두 일치. 최대 tick을 실제 실행 tick으로 오인하지 않는다.

Mac에서 압축 해제 바이트 일치와 manifest 파일 SHA를 재검증했다. 사용자 화면 수용 검사나 본선 통합 검증은 이 증거에 포함되지 않는다.

원칙 점검: P-D2/P-C3는 실제 변화842건·무효과0으로 확인했다. P-T1 결정 빈도 비증가는 변경된 묶음 기준에서도 총수+28과4건 초과 해+1로 충족하지 못했다. 통과 인계로 바꾸지 않았으며 감사 반복 규칙을 후속 검토 대상으로 남긴다.
