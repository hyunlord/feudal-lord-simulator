# RB-HERDS 확장 — 정적 목축군 3장

기존 a 1장 제품·출처·6쌍 실제 캡처는 상위 폴더에 그대로 보존한다. 추가 제품 커밋은 `ed483f09`이며, 새 렌더 코드를 쓰지 않고 기존 farm-prop 계약 데이터와 PNG 세 장만 추가했다. 전체 HERDS 설치는 네 장이다.

|원본 파일|기존 소품 ID 종류|시트|한 셀|셀 pivot|기존 그림 몸통 → 새 그림 몸통|
|---|---|---|---|---|---|
|sheep_cluster_moving_b-v1.png|sheep_flock_b|576×112|144×112|72,74|3 → 5|
|cattle_drove-v1.png|cattle_pair|768×144|192×144|96,95|2 → 3|
|pig_cluster-v1.png|pig_pair|512×96|128×96|64,63|2 → 4|

모든 시트는 NE·SE·SW·NW 네 방향 한 프레임이다. `staticCluster:true`, `animation:false`이며 파일명의 moving/drove는 이동·보행을 뜻하지 않는다. 원본 제작 기록은 개별 동물 시트 첫 행을 정수 좌표로 합성했고, 설치는 받은 완성 PNG 바이트를 그대로 복사했다. 원본과 런타임 SHA256, PNG 청크(`caBX` 모두 0), 셀별 원래 멤버 위치는 provenance.json과 source-records.json에 있다. 최초 생성 tool/model/date/seed 누락값은 unknown으로 둔다.

배율은 모두 기존 `WAVE13_ANIMAL_SCALE = 0.20670180722891565`다. 양 b 세계 캔버스는 약29.77×23.15px, 소는39.69×29.77px, 돼지는26.46×19.84px다. 개별 종을 양 a 폭에 맞추지 않는다. 각 방향의 시트 pivot은 셀 원점 x를 더한 값이며 공용 adapter가 crop 원점을 빼서 그린다. 미러링·별도 색 보정·프레임 생성은 없다.

기존 prop의 ID·좌표·종류 선정·깊이·소품 개수·경제 가축 집계를 그대로 쓴다. pair라는 레거시 ID가 남아도 실제 그림 속 개체 수는 위 표처럼 바뀐다. 그림의 개체 수를 엔진 수량과 같다고 주장하지 않는다. 양 a와 b만 새 그림이고 c/d는 기존 그림을 유지한다. 봄 동반 양은 동일 소비자의 준비된 crop bounds를 읽고, 이미지 실패 때 기존 그림과 기존 bounds가 함께 유지된다.

현재 준비 저장은 기존 a 검증과 같은 여름1500·겨울3500 저장이다. 양 b(42,12), 소(43,7), 숲 가장자리 돼지(35.3,8)는 이미 그 저장의 farmProps에 존재한다. 추가 소품·구역·동물·배치를 넣지 않는다. 18개 전후 뷰를 별도 검증하며 a의 이전 6쌍 결과를 확장 그림의 검증으로 재사용하지 않는다.
