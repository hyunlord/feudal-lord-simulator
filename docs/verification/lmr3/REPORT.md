## 1. 만든 것 — LM-R3 1단계
- **제목·로고**(`src/ui/brand/`): `GameLogo`(한·영 × 가로·세로 × 밝은·어두운 바탕)·`SealMark`(32·64·256 세부)를 키트의 외곽선 SVG에서 스크립트로 만든다(`scripts/brandArt.ts`, 원본마다 `docs/design/brand/SHA256SUMS`와 대조, 다시 돌려도 같음). 한 화면에 여럿 있어도 id가 겹치지 않는다. 색은 키트의 것(`BRAND_COLOURS`, UI 색판이 아닌 브랜드 색).
- **게임 이름**: "인장과 가문"(`KO_UI.appName`), 창 제목 "인장과 가문 · Charter & Kin", 한국어 설명, 인장 파비콘(키트의 32 px 인장을 그대로 데이터 URI로), `<html lang="ko">`. 옛 이름("봉건 영주 시뮬레이터"·"Feudal Lord Simulator")은 코드에서 없어졌다(시험).
- **로딩 화면**에 로고, **일시 정지** 머리에 작은 인장.
- **시작 화면**: 로고가 머리, **영주 모드로 시작**(유일한 주 단추, "처음이라면 이 모드로")과 **샌드박스**(보조), 샌드박스 안에 "목표와 함께 켬/끔"(켜면 목표형 캠페인). 아무 데나 눌러 시작하기는 그대로 없다(LR1-D7).
- **가문 고르기**: 모드를 누르면 가문 단계 — 이름 20개(한국어 읽기, 라틴 표기 작게), 고른 문장 128 px와 후보 넷(문장 id `<이름 열쇠>`, `<열쇠>-2` …를 `armsRecipe(armsHeraldrySeed(id))`로 그림), "다른 문장 보기", 주 단추 "이 가문으로 시작". 기본 드 해버럴 / haverel. 엔진의 새 게임 선택지 `house`·`mode`로 보낸다 — 고른 가문이 영주 화면·장원 청원 원형 문장(LR1-D5)·연대기에 나온다(시험: 드 레이븐홀트 / ravenholt-7로 시작해 영주 가문 1번으로 읽힘). 원형 문장의 이름표가 라틴 이름이던 것을 한국어 읽기로.

## 2. 만든 것 — PLAY-2(Astra 둘째 플레이의 화면 몫)
1. **소송 걸기**(마찰 4): 단추에 비용("소송 걸기 · 5s", 엔진 `file_suit` 시험 실행), 아래 한 줄 "지금 걸면 심리에서 청구 쪽 45 · 방어 쪽 80. 지금은 방어 쪽이 더 큽니다. 증거나 후원을 더해야 합니다" — 심리는 두 힘을 비교한다(`src/engine/estateSuits.ts:108-123`, 같으면 방어 쪽), 지렛대는 엔진 명령(증거·후원)만. SUIT-THREAD의 `verdictNow`·`reachable`이 오면 그 값으로.

3. **연말 카드 → 연대기**: [연대기에서 보기]가 그 해 범위로 연다.
4. **연대기 목록 제목**(마찰 7): 원래 사건과 고른 답("교회 궤짝에 맡긴 증서: 보관한 증서를 증거로 낸다", 청지기의 처리는 "… — 청지기가 관습대로 처리했다").
5. **10배속**(마찰 5): 빠른 속도 인장의 모서리에 "×5·10", 지금 속도가 진하게 — 시간 칸 크기 그대로(1280: 248×64, 태블릿: 264×68).
6. **목책 안내**(마찰 10): 영주 모드에서 "직접 그어 주세요" 대신 마을의 길 — 마을의 청이 있으면 청 칩에서 들어주기, 조건이 덜 찼으면 "목책 둘레는 마을이 잡아 영주에게 청합니다 … 아직 인구 12/60"과 영주의 첫 지렛대, 마을이 둘레를 찾지 못했을 때만 "이때만 영주가 직접 긋습니다". 두 줄이 붙어 보이던 것(캡처 139)을 고침.
7. **가족 소식**(마찰 9): 출생·혼인·사망 소식에 기록이 주는 사람(아이·어머니·아버지·배우자)의 이름과 전기 단추 — 기록에 없는 사람(첫아이의 이름)은 비움.
8. **가문의 일**(마찰 8): 유언·상속 다툼·감사·지도 밖 청원의 칩은 답할 때까지 줄에 남고(카드를 닫아도, 새 칩이 와도), 유언 칩은 기한을 말한다. 미응답 목록은 어댑터 하나(`src/ui/lord/decisions/lordMattersDue.ts`) — SUIT-THREAD의 `lordMattersDue`로 바꾼다.
