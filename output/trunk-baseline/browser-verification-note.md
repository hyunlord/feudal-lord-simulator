# B8 브라우저 검사 시점 교정

최종 제품 빌드의 첫 재검사에서 page-reload만 tick1169→1208 불일치였다. 원본 실패 증빙은 b8-clean-browser/browser-continue.json에 보존한다. 기준 캡처의 자원바는 가용 목재82였지만 읽힌 auto-1은 국고70+재고목재11로 이전 상태였다. 복원 상태는 가용목재82와 일치했다. 기준 시점 telemetry에는 interval1169만 있었고 pause1208은 아직 저장 중이었다. 탭 재열기1819는 일치했다.

가설: 실제 복원 손상 / 일시정지 후 시간 진행 / 기준 파일을 너무 일찍 읽음. 화면 자원바 전후 일치와 뒤늦은 auto-2@1208 기록으로 마지막 가설을 확인했다.

scripts/verifyBrowserContinue.mjs에서 1500ms 고정 대기를 제거했다. 제품의 수동 저장을 같은 직렬 큐 뒤에 요청해 완료 telemetry를 기다린다. 그 뒤 **가장 최근 자동 저장**이 수동 저장한 일시정지 도시와 상태 SHA까지 동일한지 먼저 확인한다. 자동 저장 실패를 수동 저장으로 가리지 않는다. 이어하기 뒤에도 새 수동 저장 완료를 기다려 비교한다. 게임·저장 동작은 수정하지 않았다.

최종 결과는 b8-final-browser/browser-continue.json. 이 변경은 검증 스크립트만이므로 e97d6a8에서 진행 중인 seed의 제품/계측 코드는 동일하다.

최종 실행: `b8-final-browser/browser-continue.json`, reload1210틱·tab1820틱, 모두 SHA 일치. 전/후 캡처의 튜토리얼 안내 문구가 초기 단계로 돌아오는 차이는 보였으며 GameState/재고 복원과 구분해 후속 후보로 기록한다.
