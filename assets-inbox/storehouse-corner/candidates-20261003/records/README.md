### 창고

대상은 현재 변형 목록의 기본형, B형, C형 전체다. 눈 전용 투명 PNG를 각각 대응하는 원본에 같은 크기·같은 기준점으로 겹친다. 건물 본체는 포함하지 않는다.

| 후보 | 대응 원본 | 지붕 alpha 피복률 |
|---|---|---:|
| storehouse_a_snow-v1.png | public/assets/buildings/storehouse.png | 71.97% |
| storehouse_b_snow-v1.png | public/assets/buildings/variants-wave2/storehouse_b-v1.png | 70.10% |
| storehouse_c_snow-v1.png | public/assets/buildings/variants-wave2/storehouse_c-v1.png | 62.63% |

피복률은 원본 그림에서 따로 추적한 지붕 면을 분모로 한 alpha 가중 면적이다. 처마 아래 벽·문·수레는 제외했다. 기와가 불규칙하게 드러나며, 지붕 실루엣 밖으로 눈이 번지지 않게 등록했다. 표의 수치는 수작업 지붕 경계에 따른 측정값이다. 경계 ±2px 민감도도 QA.json에 남겼으며, 그 민감도 구간 전체를 60–80% 합격 조건으로 사용하지 않았다.

생성본은 원본 크기로 한 번 축소한 뒤, 지붕 마스크와 원본 alpha로 제한했다. C형 생성본은 원본 정렬을 위해 (-3,-9)px 이동했다. 이 이동은 눈을 최종 원본 캔버스에 등록하는 내부 처리이며, 설치 시 오프셋은 세 형 모두 (0,0)이다.

### 모서리

좁은 중앙 기둥과 두 방향으로 짧게 돌아가는 상부 문루 접속부를 한 조각으로 만들었다. 목책은 참나무 기둥·보·버팀대, 석벽은 따뜻한 회색 석재·모서리 다듬돌·짧은 받침부다. 전체 성문이나 성벽을 덮는 그림이 아니다.

두 방향의 상부 접속부를 벽 끝에 겹치고 기둥 발을 모서리 기준점에 둔다. 권장 시작 배율은 목책 0.145833, 석벽 0.147368이다. 이는 현 성벽 높이에 맞춘 약 28 world px 높이의 합성 확인값이며, 카메라 확대율을 별도로 곱한다. 좌우 반전은 광원 방향을 바꾸므로 기본 설치 방법으로 제안하지 않는다.

여름·겨울은 같은 캔버스·피벗을 쓴다. 겨울 생성본에서 눈색 픽셀만 상부에 가져오고 아래 몸체는 여름판을 유지했다. y≥140 영역의 RGBA 차이는 두 재료 모두 0픽셀이다. 실제 눈 두께 때문에 상단 alpha 경계는 조금 달라질 수 있다.

엔진 연결 참고: `src/render/gateCornerModules.ts`의 모서리 접속부 배치 및 앞/뒤 순서, `src/render/drawWallFaces.ts`의 성문 끝 기둥 처리. 이 패키지는 해당 코드와 에셋 등록표를 수정하지 않는다.

## 기록과 무결성

`manifest.csv`와 `manifest.json`에 7개 후보의 이름·규격·피벗·SHA256·생성 이력이 있다. CSV에는 대사식 요약이 아닌 실제 전체 생성 프롬프트가 들어 있다. `records/generations.json`은 B형 보강 전 시도를 포함한 8회 생성 이력과 참조 관계를 담는다.

원본 생성 이미지는 생성 도구 보관 경로에 그대로 보존했다. 경량 ZIP에는 전체 해상도 생성 원본 대신 1회 축소한 중간 PNG를 넣고, 원본 경로·SHA256·규격을 기록했다. 프로젝트 원본 참조 9개는 파일 그대로 동봉했으며 HEAD와 해시가 일치한다. 제작 중 실패한 Swift 변환 시도와 초기 검사판은 최종 ZIP에 넣지 않았다.

`records/register-snow.m`, `records/register-corners.m`은 후보 후처리 기록으로, 게임 소스가 아니다. 전자는 눈색 추출·지붕 등록, 후자는 미세 투명 잡점 정리와 여름 몸체를 보존한 겨울 합성을 수행한다. 삽화 생성은 image_gen.imagegen을 사용했다.

`SHA256SUMS`는 자기 자신을 제외한 ZIP 내 모든 파일을 검사한다. 압축을 풀고 `shasum -a 256 -c SHA256SUMS`로 확인할 수 있다.
