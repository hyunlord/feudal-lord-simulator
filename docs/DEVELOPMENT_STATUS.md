이번 기록은 서비스·성능 우선순위 변경과 후속 도시 성장·가림 수정을 함께 보존한다. 브랜치는 `codex/phase15-organic-ground`이며 별도 배포 승인을 의미하지 않는다.

## 후속 구현: 도시 성장·가림

도로를 입체 물체보다 먼저 그리며 일반 건물의 자동 반투명을 제거했다. 성벽 검사는 완성 건물뿐 아니라 건물 공사장의 전체 점유도 보호한다. 성곽 도시 이후 시장·교회 공급 확장, 교회 자재 판매 보호, 실제 도로 운송 거리를 고려한 식량 시설 건설을 추가했다. 자세한 시스템 설명과 최신 검증은 [도시 시스템 v2](TOWN_SYSTEMS_V2.md)에 정리한다.

아래 성능 측정과 392808틱 결과는 **이전 우선순위 작업 당시 기록**이며, 후속 구현의 결과와 구분한다.

## 작동하는 게임 흐름

- 도로·교량·성벽 통과 규칙에 따른 자재 운송과 빵 배급, 재고 예약·반환·저장 용량.
- 인구 기반 노동력, 원료·인력·도로에 따른 생산, 자재 배송과 인력을 요구하는 건설.
- 물·빵·곡창·시장·교회·성벽 조건의 주택 발전과 두 필지 합필. 생활 등급 하락 시 건축 형태 보존.
- 자립·목책·석벽 도시 목표, 공급 위기·정착지 포기, 자동 개발.
- 성벽/건물 최소1칸 간격과 다중 타일 앞뒤 가림. 기존 저장 도시는 자동 재배치하지 않는다.

## 이번 우선순위 구현

`population/serviceAllocation.ts`와 `engine/householdServices.ts`가 엔진과 UI의 공통 서비스 판정을 제공한다. 우물12·시장24·교회32 주거 필지 한도, 합필은2필지이고 빈집도 자리를 유지한다. 시장은 기존3명 일꾼과 연결 도로, 교회는 연결 도로가 필요하다. 우물은 초기 정착을 위해 주민이 직접 이용하는 거리 기반 공동 서비스로 유지한다.

이용 가능한 공급자가 적은 주택을 먼저 배정하고 같은 조건에서 합필을 우선한다. 주민 수와 배열 순서가 바뀌어 공급이 흔들리지 않는다. 복잡한 임의 공급망의 전역 최적 배분을 보장하지 않는다. 자동 우물 건설도 공사 중 공급량을 포함해 수용량 부족을 처리한다.

매 틱 노동력 배분 후 서비스와 시장 판매를 계산한다. 신규 입주자는 다음 틱부터 일한다. 별도의 유료 우물 인력·세금·임금·수리비 경제는 추가하지 않았다. 주택과 시설 상세창에 공급 중단 이유 및 담당 필지를 표시한다.

완성 성벽을 원래 깊이 순서 위치에서 기기 해상도 캐시로 재사용한다. 카메라·확대·DPR·화면 크기·벽/문 형태·재질·이미지 로딩이 바뀌면 다시 그린다. 나무 흔들림과 주민·시설 애니메이션은 유지한다. 컨텍스트별 캐시는8M픽셀 한도이며 브라우저/GPU 전체 메모리 한도가 아니다.

## 재현과 이식성

`npm ci`, `npm run build`, `npm test`. 별도 lint 명령은 없다. 승인 원본25장은 `docs/asset-evidence/accepted-art/sources`에 바이트 그대로 보존했고 매니페스트는 저장소 내부 경로를 사용한다. 과거 생성 위치는 integration.json의 historicalSourcePath에 남긴다. 이전 합필 원본6장은 legacy-compounds에 보존하고 실제 실행은 현재 historical-houses 파일을 사용한다. 정식 아트 검증은 인접한 작업 폴더 없이도 실행된다.

`installAcceptedArt.mjs`는 과거 제작 환경용 설치 도구로 기본 경로가 기기 환경에 의존한다. 일반 실행·빌드·원본 검증에는 필요하지 않다. 테스트·증빙 완료 집계는 이번 커밋 메시지와 함께 기록한다.
