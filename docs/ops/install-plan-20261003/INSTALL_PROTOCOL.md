# 설치 세션 공통 계약

1. 시작 시 최신 HEAD와 장부를 다시 읽고 이 계획의 기준 HEAD와 비교한다. `confirmed`·`installed_by`·`replaced_by`가 바뀐 행은 자동 복사에서 빼고 새 상태를 대조한다. 수령 원본은 수정하지 않는다.
2. INSTALL_LISTS의 가만 데이터 작업으로 취급한다. 나·다는 SPECS 선행 조건을 먼저 구현한다. 새 기능을 장식으로 임의 대체하거나 존재하지 않는 엔진 상태를 추측하지 않는다. 새 작업 ID가 제안된 경우 렌더의 dispatch 항목으로 먼저 명시하되, 이미 있는 LM-R1/R2/R3·NAT-3/NAT-5는 그대로 사용한다.
3. 원본 SHA/실제 규격을 INVENTORY와 대조한다. 그림 크기·피벗 누락은 `(width/2,height)` 같은 추정으로 채우지 않는다. 캔버스 기준점과 알파 경계, 스프라이트 셀 기준점을 구분한다. 좌우 반전하지 않는다.
4. PNG의 caBX/jumb/c2pa 메타데이터 청크만 제거하고 픽셀·알파·캔버스를 보존한다. JPEG는 JPEG 경로, PNG는 PNG 경로를 쓴다. 기존 목표 파일은 target_before_sha256를 확인하고 정확한 경로만 교체한다. 다른 변형·겨울 짝·원본을 지우지 않는다.
5. 조각을 지정된 카탈로그 객체에 병합하고 생성 스크립트의 원본 목록도 같은 계약으로 갱신한다. 새 키 추가만으로 그리기가 보장되지 않는다. ID→선택→로더→그리기 소비자와 preload/실패 fallback을 확인한다. 잘못된 URL·규격·누락 키에서 기존 그림/기존 도형 fallback이 유지되어야 하며 무한 재요청·빈 화면은 실패다.
6. docs/provenance/assets.csv에 원본 경로/SHA, 런타임 경로/SHA, 원 납품 생성 기록·프롬프트·후처리·usedIn을 기록한다. 도구가 공개하지 않은 모델/seed는 지어내지 않는다. 복사와 실제 소비자 연결·캡처가 확인된 행만 INVENTORY의 installed_by_proposed를 installed_by에 쓴다. ledger_reconcile은 재복사 없이 현재 공개 파일 해시와 기존 정본 작업 ID를 확인하여 그 ID만 채운다. 전 장부 재생성 대신 관련 행만 변경한다.
7. 카탈로그 검사·typecheck·관련 소규모 회귀 후 각 SPECS의 캡처를 수행한다. 0.6/1.0/1.4, 여름/겨울과 해당 봄/가을, 동일 seed/카메라/DPR/상태를 기록한다. 움직이는 날씨는 정지 JPEG만으로 합격하지 않는다. 브라우저·무거운 회귀는 저장소 AGENTS 원격 실행 규칙을 따른다. 성능 추정값을 성능 측정으로 쓰지 않는다.
8. 실패하면 그 설치 작업의 public 변경·카탈로그·생성기·provenance·installed_by만 함께 되돌린다. 다른 세션의 변경을 되돌리지 않는다. 받은 inbox 원본과 승인 상태는 유지한다. 실패 그림은 설치 완료로 세지 않고 원인/재현 캡처를 남긴다.

검증 전 ledger 값을 채우는 실행 스크립트나 자동 설치 스크립트는 이 ZIP에 없다. 설치 권한은 렌더 세션에 남아 있다.
