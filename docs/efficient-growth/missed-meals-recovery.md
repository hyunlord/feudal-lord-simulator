# 결식·운송 병목·증설 효과를 실제 흐름으로 구분

기준 `2e037032`: 전체 회귀 2,085개 통과 뒤 기존 8필지 검증은 600,000틱에 **실패**했다(8가구 중 L4 7, 인구 249, 안정 중단 91회). 경제 수치·기본 8필지·공사 운송·D24는 변경하지 않았다.

**원인과 반증.** 원료 선보충, 서비스 자리 예약, 출입구 수정의 세 가설을 비교했다. 서비스 변경 전후 첫 24,000틱의 20개 건설 행동은 같았다. 360,000틱 상태의 밭 6개는 실제 밀 360개를 생산했지만 식사 수요 192개와 실제 전환량으로 필요한 밀은 384개였다. 먼 곡창의 밀 92개와 방앗간의 빵 18개가 부족량을 상쇄해 공급 충분으로 오판했다. 같은 상태에서 조언자 없이 4,800틱 비교한 마지막 창의 빵 생산/소비는 기존 선보충 181/181, 이전 제조분 기준 174/179, 완성 빵 한 수레 우선 184/178이었다. **운송 수정만으로 복구를 입증하지 못했다.**

결식 때 모든 비축량을 무조건 배제한 첫 후보도 새 600,000틱 실행에서 **실패**했다(인구 255, 밭 23·방앗간 3·곡창 1). 가득 찬 밭이 많아 실제 밀 생산은 362에 머물렀다. 새 밭에 밀 20개만 쌓여도 관측기가 효과 있음으로 판정하여 쓸모없는 증설을 반복했다. 이 후보·실패 원본을 보존했다.

**현재 후보 변경.** ① 방앗간에 기존 수레 적재량만큼 빵이 있으면 정상 배달을 먼저 시도하고, 목적지가 없으면 원료 보충으로 넘어간다. ② 실제 결식·음의 생산 수지가 함께 관측되면 쓰이지 않은 재고로 공급 완료를 선언하지 않는다. 다만 기존 밭이 실제 `output_full`이면 농지 증설을 막고 운송을 먼저 진단한다. 모두 먹은 도시에는 기존 비축량 공제를 유지한다. ③ 완성된 식량망의 새 밭은 **실제 밀의 사용 가능한 곡창 입고 + 2,400틱 후 빵 생산 증가 또는 결식 감소**가 있어야 반복 증설 근거가 된다. 수레에 실린 화물·예약·새 밭의 자체 재고는 입고로 세지 않는다. 도시 전체의 후속 개선은 시간상 함께 관측한 근거이며, 특정 밀알의 인과 추적을 주장하지 않는다. 최소 초기 식량망은 명시적으로 구분하며, 구형 관측의 증거 누락은 반복 증설 권한을 주지 않는다.

**검증.** 식량·운송 집중 회귀 301개, TypeScript 통과. 실제 제조 후 빵 18개가 쌓인 상황·목적지 가득 참·공유 예약·취소·매 틱 물량 보존을 검사했다. 입고 관측기 유무의 30틱 전체 운송 상태가 같았다. 실패한 밭 23개 상태의 추가 2,400틱에는 건설 행동이 없었다. 이전 밭 6개 상태에서는 정상 비용·조언자로 밭 한 개만 추가하여 인구 256, 마지막 식사 192/192, 원료 대기 14.44%를 회복했다. 새 기본 상태 120,000틱은 밭 5·방앗간 2·곡창 1, 식사 144/144였으며 관측 밭의 실제 밀 입고 56개를 확인했다. 이 짧은 원인 검증은 처음부터의 엄격 합격과 구별한다.

후속 실행은 입고 관측의 거리 경계 결함을 고치기 위해 중단했고, 다음 실행은 서비스 배치 탐색 비용 때문에 277,920틱에서 중단했다. 후자는 읽기 전용 일시정지로 마지막 상태를 보존했다. 두 중단은 엄격 검증 합격·실패로 세지 않는다. 구형 밭 관측의 저장된 성공 플래그만으로 재증설하지 않는 회귀도 추가했다. 새 기본 상태 엄격 검증 결과는 최종 실행 후 기록한다. 전체 회귀와 5개 지도 검증은 같은 QA 담당자의 최종 소스 검증으로 남는다.
