# ASTRA Wave 12 — 시설 후보 전체 묶음

상태: **candidate**. 게임에 설치하지 않았습니다.

## 구성
- 완성 본체 29 PNG: `assets/bld/`
- 같은 캔버스의 가동 오버레이 28 PNG: `assets/active/` (도랑은 가동 없음)
- 96×96 아이콘 29셀을 담은 시트 3 PNG: `assets/icons/`
- 확인 그림 4 PNG: 전체 동일 원본 배율, 공방 OFF/ON, 물가 산업시설, 24px 아이콘
- `assets.csv`: 후보 파일 60개, 전체 프롬프트·참조·처리·SHA256
- `buildings.csv`: 시설별 본체/오버레이/아이콘 셀/캔버스/피벗 연결
- `검수표.md`, `records/`: 생성 기록, 등록 좌표, 기계 검사, 원본 참조 해시

의뢰서의 명시된 변형을 펼치면 본체는 29종입니다. 29 + 28 + 아이콘 시트 3 = 후보 PNG 60개이며, 확인 그림을 포함하면 PNG는 총 64개입니다. 공방 켬/끔 두 뷰는 확인 그림 02 한 장에 함께 있습니다.

## 배치
본체와 active를 **같은 위치, 같은 피벗, 동일 배율**로 합성합니다. 오버레이 offset은 모두 (0,0)입니다. 아이콘 셀 좌표는 buildings.csv에 있습니다.

첨부에는 숫자 피벗이 없었습니다. 따라서 기존 파일과 같은 숫자 피벗이라고 주장하지 않습니다. 신규 후보의 앞쪽 접지점을 측정해 CSV에 명시했습니다. 1칸 공방은 첨부 L2와 같은 137×137 캔버스, 약118px 실그림 폭으로 맞췄고 큰 시설은 발판에 맞는 별도 캔버스를 사용했습니다. 추후 콘텐츠 설치에서 이 신규 배치 계약을 적용해야 합니다.

파이프라인 문서의 기본 배율은 원본×0.5이며 줌0.6은 원본×0.3입니다. 확인 그림01은 모든 시설을 원본1:1로 놓아 크기를 비교합니다. 02 하단은 원본0.3 축소입니다. 런타임/DPR/충돌/경로/애니메이션 검증은 하지 않았습니다.

다리 참조는 3×3 부품 시트입니다. 첫 데크 조각만 사용해 예배당을 끝 옆에 붙인 예시를 확인 그림01 하단에 넣었습니다. 등록 소켓은 최종 시각 합성에 맞춘 후보 좌표이며 게임의 확정 소켓이 아닙니다. 부두는 독립 끝 모듈이고 도랑만 X방향 경계 일치를 검증했습니다.

## 제작 및 역사 제약
본체·가동 소품은 imagegen으로 제작하고, 생성 배경 번짐 제거·한 번의 목표 배율 축소·알파 마감·좌표 등록을 수행했습니다. 제화공/재단사는 생성된 닫힌 덧창을 본체에 마스킹하고 active가 원래 열린 상점 픽셀을 복원합니다. 창 불빛은 생성 광원 소스를 창 내부에 등록한 뒤 가독성을 위해 황색(R220,G154,B62)/alpha165로 수동 보정했습니다. 알파0 경계에는2px RGB bleed를 넣었습니다.

주거용 굴뚝 없음, 작업 화로·가마에만 배출 구조. 여관은 안뜰·마구간·그림 간판, 영주관은 석조1층 홀+목골조 날개, 길드홀/톨부스는 아케이드1층+상층 회의실, 무두질장은 물가 가장자리 합성, 숯가마는 굴뚝 없는 흙무덤형으로 제작했습니다.

## 검토시 유의
24px에서 제화공/재단사 구분을 보완한 전용 아이콘을 포함했습니다. 동일 계열 A/B 변형은 같은 기능을 나타내므로 실루엣 유사성이 남습니다. 줌0.6에서 작은 창빛·상품·벽등만으로 모든 시설의 가동 상태를 즉시 판별할 수 있다고 보장하지 않습니다. 확인 그림은 후보 아트 합성으로, 게임 스크린샷이 아닙니다.
