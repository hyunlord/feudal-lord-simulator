# Wave 4c — 후보 18종

게임에 설치하지 않은 후보입니다. ASSET_PIPELINE_SPEC_v1.md를 우선 적용했습니다. 확인 그림은 납품 PNG를 합성한 오프라인 검사판이며 실제 게임 캡처가 아닙니다.

- `assets/`: 납품 PNG **18장** (허들5·과수4·그루터기2·헛간3·동물4)
- `proofs/`: 확인 그림 **3장**
- `assets.csv`: **18행**, 실제 전체 프롬프트·참조·선택 원본·수정 내용·SHA256
- `asset-contracts.json`: 크기·피벗·소켓·원본→납품 변환
- `sources/`: 생성 원본과 쟁기 팀의 미선택 시도. 납품 18종에 포함하지 않음
- `references/`, `masks/`, `records/`: 제공 자료·구조 마스크·제작 및 검사 기록

## 확인 그림

2. [과수 비교](proofs/02-orchards.png): 줌1과0.6. 첨부된 Wave4b 과수는 c·d·e·f 4종입니다. 게임의 다섯 번째 기존 과수는 원래 게임 그림으로 첨부에서 빠졌습니다(사용자 확인). 사용자 승인에 따라 아홉 번째 비교용 참조 슬롯은 이전 파일럿 사과나무를 ‘이전 파일럿 참조’로 표시했습니다. 신규 납품은18종 그대로입니다.
3. [경작지·헛간·동물](proofs/03-fields-farmsteads.png): 경작지5상태, 헛간3종과 창고, 동물4종.

## 규격 및 차이

헛간3종은 창고와 같은160×136 및 피벗(80,120)입니다. 새 후보의 논리 점유 계약은 의뢰서대로2×1입니다. 현재 제품 창고 메타데이터는2×2이므로 기존 게임 점유와 같다고 주장하지 않습니다. a와 working은 동일 전체 캔버스 등록을 사용합니다.

그루터기2종은 growing의 알파를 픽셀 단위로 그대로 사용하고 X 양끝 RGBA를 맞췄습니다. 기존 growing/fallow의 알파는12,534픽셀이 서로 달라 두 참조 모두와 동시에 일치할 수 없습니다. 기존 fallow는 바꾸지 않았습니다.

과수G/H는 낮고 넓은 계열이지만 줄기·가지·뿌리 형태가 다릅니다. 배I는 가늘고 어린 수형, 자두J는 굵고 비대칭인 고목입니다. I/J와 이전 파일럿은 Wave4b보다 잎 묘사가 조밀합니다. 헛간은 초가 실루엣으로 창고와 구분되지만 줌0.6에서 작은 쟁기·수레 및 수확철 소품 식별은 약합니다. 확인 그림을 기준으로 후보 채택을 판단해 주세요.

## 제작 기록

이미지 도구는 image_gen입니다. 도구가 모델 버전·seed를 노출하지 않아 기록하지 않았습니다. CSV의 generatedAt은 생성 원본을 복사한 파일의 수정 시각입니다. runtimePath 열은 납품 파일 위치이며 게임 설치 경로가 아닙니다.

허들은 독립 생성 원본을 구조 마스크에 등록하고 참조 목재 평균색에 맞췄습니다. 반전·회전으로 코너를 만들지 않았습니다. 납품 해상도로 한 번 샘플링하고 투명 경계 RGB를3픽셀 확장했습니다. 세부 변환 수치는 records에 있습니다.

쟁기 팀은4개 시도 중 regenerate를 선택했습니다. 초기에 뷰어가 투명 영역의 숨은 RGB를 표시해 갈색 번짐처럼 보였으나 실제 배경 합성에서 투명도는 정상이었습니다. 색 제거로 알파를 훼손하지 않았습니다. 미선택 원본과 프롬프트도 보존했습니다.

런타임 설치·충돌·길찾기·DPR·성능 검증은 수행하지 않았습니다. 제품 코드와 public/assets는 변경하지 않았습니다.

## 과수 실루엣 재검토

c·d·e·f와 신규4종을 확인 그림에서 다시 비교했습니다. G는 왼쪽으로 무게가 치우친 비대칭 수관, H는 더 낮고 넓게 벌어진 수관과 굵은 갈라진 줄기, I는 폭이 좁고 성긴 어린 수형, J는 비틀린 굵은 고목 줄기와 분리된 비대칭 수관입니다. 기존 실루엣의 복제·반전은 없으며 저수형 계열의 유사성은 남습니다. 이번 정정에서는 에셋18장 자체를 변경하지 않았습니다.
