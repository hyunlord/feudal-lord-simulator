# 보이는 시뮬레이션 설계서 v1 (가시성 축)

작성 2026-09-25 · 근거: 딥리서치 14 — Claude v0.3(L-, 우리 게임 설계, 첨부 15개 전부 열람), GPT(V-, 사례 해부, 화면 5장 직접 진단). Gemini(Q-, 인지 원리)는 **파일 손상으로 읽지 못함 — 재업로드 필요**. 흐름 설계서 v1과 짝.

## 0. 두 조사가 일치한 결론
1. **새 시스템이 아니라, 이미 도는 시뮬레이션을 화면이 증언하게 한다**(L-1, V-085). 밭 단계·건설 4단계·거부 표시·워커가 **각자 고립된 언어**로 있고 `원인 → 움직임 → 결과`로 묶이지 않는 게 문제다.
2. **모든 명령에 같은 생애**: `가리킴 → 예측 → 확정 → 사람·물건이 움직임 → 장소가 변함 → 완료가 터짐 → 가동 중임이 계속 보임 → 문제면 진단`. 한 고리라도 없으면 숫자 게임으로 돌아간다(V-015, L-2). 이미 좋은 **배치 전 예측(거부 ✓/×)** 언어를 시간축으로 늘리는 것이 가장 재사용 가치가 크다(V-119·120).
3. **건설 결함은 프레임 부족이 아니라 인과 연결 부족**(V-118). 순서: 라벨 기준점·bar를 현장에 → 자재 필요/도착과 현장 더미 연결 → 공사장↔배정 워커 강조 → 단계 전환·완공 보상(V-114~117, L-49).
4. **세계 cue 우선, 아이콘은 예외**: 정상은 연기·사람·재고·활동으로, 행동 필요한 첫 원인만 아이콘, 같은 원인은 줌아웃에서 집계(V-Q4, L-6). 화면 05의 흰 배지 숲을 줄인다.
5. **첫 vertical slice = 밀→빵→집 한 사슬**(V-111): 수확 띠 → 밭에 대표 일꾼 → 볏단·자루 → 밀 실은 수레 → 풍차 날개·화덕 연기 → 빵 바구니 배급 → 집 지붕 연기. 성공하면 목재·석재·시장·세금에 같은 문법 복제.
6. **proxy 허용**: 워커·수레는 실제 이벤트를 대표하는 표현이면 된다. 단 규칙과 거짓말하면 안 된다(V-Q3).
7. **소리의 첫 목표는 음악이 아니라 행동 증명**: 확인·불가 → 망치·수레 → 가동 → 완공 → 경고 → 환경 순. P0 15개(L-11, V-103).
8. **계절은 P0.5**: 옷만 바뀌면 계절 시스템이 달력 숫자로 남는다. 지면 틴트 + 식생 + 지붕 눈 중 2층 + 환경음 1층(V-Q5).
9. **줌 LOD 3단: 0.6 상태 / 1.0 과정 / 1.35 사람**(L-13, V-109). 워커 머리 위 색 사각 마커는 잡음 → 1.35에서만 역할 아이콘(V-110, L-81).

## 1. 첨부가 바로잡은 사실 (Claude L-)
- **집에 굴뚝이 없다**(L0~L2, L3·L4 기본 없음, 개방 화덕) → "굴뚝 연기"가 아니라 **지붕 연기**(용마루·초가 틈). 새 그림 없이 연기 기준점 좌표 22개.
- **방앗간 = 기둥풍차 + 공동 빵 화덕**(물레방아 금지). 가동 표시 = 날개 회전 + 화덕 연기.
- 연료 자원이 없으므로 **연기 = 입주 + 빵 있음**의 관례. 빈집 = 판자 창 + 연기 없음, 빵 결핍 = 연기 약화 + 주민이 문 앞.
- 인구 증가는 외부 유입이 아니라 기존 집에서 → 연출 = **집 문에서 새 주민이 나옴**.
- 건설 워커 시트에 **망치가 이미 그려져 있다** → 망치질은 상체 분리 회전으로 그림 0장 시험.
- 수레는 3장 모두 **빈 수레** → **수레 적재물 레이어**가 P0.
- 공사 라벨 위치 오류 원인 확정: 원점 타일 고정 오프셋(−22, −64), 연결선 없음(`drawConstructionSites.ts:171-190`).

## 4. 워커
수레 적재물(P0 목재·석재, P1 자루·빵·원목·원석) · 짐 부리기·망치질·대기·완공 반응은 코드 · 낫질은 코드 시험 후 불합격 시 수작업 8프레임 · 파종·쟁기·배급·물 긷기·징수는 소품. 워커 툴팁 = 동사 + 무엇을 + 어디로 + 진행("목재를 방앗간 공사장으로 · 12/20"). 이름은 1300–1450 잉글랜드 세례명.

## 5. 시간·계절
