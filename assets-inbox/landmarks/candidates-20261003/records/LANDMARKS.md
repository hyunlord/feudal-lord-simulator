## 범위와 납품 수량

남부·남동부 잉글랜드1300–1450, ART_BIBLE_v2 기준의 검토용 후보다. **교회4 + 나머지6계열×3 =22단계, 각 여름/겨울2계절 =44개 완성 RGBA PNG**가 계약 수량이다. 최종 등록 PNG44개와 CSV44행을 생성했고,22쌍의 외곽 정합·잘림 검사를 통과했다. 이는 역사·투영·눈가림 판정까지 합격했다는 뜻은 아니다. 부품 키트·조각 묶음으로 완성 그림을 대체하지 않는다. 다리 B3도 예배당만의 조각이 아니라 B2 석교와 접근부 예배당이 결합된 완성 그림이다.

게임 소스·설치 manifest·기존 승인 원본은 변경하지 않는다. 런타임 설치·게임플레이 해금 구현·기존 자산 폐기는 범위 밖이다. **등록 계약은 전 단계2048×2048, 공통 피벗(768,1536), world_scale=0.25이며 `assets/manifest.csv`에 기록한다.** 정의 입력은 `records/registration.json`, 처리 도구는 `records/tools/register_assets.py`다. 최종44PNG 전체 완료와 알파·해시·눈가림·줌별 판독·런타임 통과 수치는 검증 결과가 확정될 때 기록한다.

## 통합 전 결정할 공백

1. **저장 상태와 선택 규칙:** 후보 ID와 실제 kind/tier를 연결할 새 명세가 필요하다. 연도만으로 자동 선택하지 말고 건설 완료·권리·재원·선택 프로젝트를 구분한다.
2. **교회:** 청원 수락 때 저장되는 `naveRebuilt`의 시각 연결과 기존 chapel/church 교체 정책이 없다. 비용300·1396년 봄 청원은 현재 특정 이벤트 값이며 모든 C단계 투자비나 공통 날짜가 아니다.
3. **시장과 길드:** 거래 active·길드 설립 존재 상태를 성장 tier로 재해석하지 않는다. 시장권 이전과 길드 설립 각각의 기능을 보존한 별도 등록 설계가 필요하다.
4. **성문과 다리:** 성벽 재료 공사가 끝나기 전에 석문으로 바꾸지 않는다. 교량은 tile deck와 전후 난간으로 나누어 그리므로 완성 후보44PNG가 곧 설치 가능한 렌더 부품44개라는 뜻은 아니다. 통과 중심선·양쪽 둑·가림 레이어를 별도 설계한다.
5. **영주관:** 대상은 `manor_house`이며 keep를 대체하지 않는다. 부유함·공석·가문 이탈은 다른 축이다. 해자와 확장 뜰의 점유·출입을 기존2×2에 억지로 넣지 않는다.
6. **여관:** 독립 영업 기능이 없으므로 새로운 경제 시설로 설치하려면 별도 제품/코드 승인이 필요하다. 현재 L4 주택 변형을 자동 독립 여관으로 바꾸지 않는다.
7. **기하와 검증:** 현행 시설은 crop 바닥 맞춤, 길드홀은 자체 pivot, 성문은 portal 정합, 다리는 affine tile이므로 단일 피벗 규칙으로 덮어쓰지 않는다. 후보의 공통 등록틀과 기존 엔진 등록틀을 구분한다. `assets/manifest.csv` 계약에 따라 원본 알파/접지/계절 정합을 검증하고, 설치가 별도로 승인되면 런타임 검증을 수행한다.

## 문서 우선순위와 상태

최신22단계·44PNG 계약과 ID는 이 문서 및 [PLAN](PLAN.md)이 기준이다. [HISTORY](records/HISTORY.md)의 초기 `B2C`는 최종 B3(선택형)와 같은 뜻이고 초기 영주 저택 `N1–N3`는 최종 L1–L3로 정규화한다. HISTORY의 길드홀 형태안은 검토 초안이며 최종 U2 상층 회의실/U3 뒤동은 이 문서의 확정 제작 방향을 따른다. ENGINE_MAP의 후보 열은 초기 조사 제안이고 실제 구현 열만 현행 상태 근거로 사용한다.

역사 근거·직접 링크는 [SOURCES](SOURCES.md). 제작/QA 결과는 별도 결과 기록으로 확인해야 하며 본 기획 계약만으로 완료를 선언하지 않는다.

## 확정된 등록 계약과 재현 한계

`assets/manifest.csv`의 필드는 `filename,family,stage,season,canvas_width,canvas_height,pivot_x,pivot_y,world_scale,footprint_w,footprint_d,expansion_rule,anchor_kind`다. world_scale는 표시 메타데이터이며2048PNG를 다시0.25배 축소해 저장한다는 뜻이 아니다. 제안 footprint는 **64×32 world 격자의 예약 영역**으로 읽으며 실제 엔진 충돌·경로·필지 점유를 검증한 값이 아니다.

각 여름 원본에서 사람이 정한 `anchor_x,anchor_y`와 `source_scale`를 사용한다. 등록좌표는 `q=source_scale×p+(768,1536)−source_scale×anchor`다. 계절 간에는 겨울 전체 이미지를 여름 실루엣에 균일 배율·평행이동으로 맞춘 뒤, 전체 원본에 affine 등록을 적용한다. 단계 간 anchor와 배율은 수동 설정이며 자동으로 동일 문·탑 위치를 증명하지 않는다. 부품별 추출·재조립·부분 신축으로 증축을 만드는 방식이 아니다. 상세 알고리즘과 실패 조건은 [REGISTRATION_METHOD](records/REGISTRATION_METHOD.md)를 따른다.

생성기는 `image_gen.imagegen`이며 사용 모델의 정확한 이름·버전·seed는 노출되지 않는다. `records/prompts/`의 전체 프롬프트와 원본/참조·변환 기록은 생성 경로를 감사할 수 있게 하지만 같은 모델 결과의 완전한 재생산을 보장하지 않는다. 원본이 확보된 이후의 전체 이미지 등록 과정과 생성 모델 자체의 재현 가능성을 분리한다. QA 지표는 실제 `records/registration-result.json`과 `proofs/VERDICT.md`를 기준으로 판정한다.
