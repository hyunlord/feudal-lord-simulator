# Wave 30 합필 집 후보

18개 변형과 변형별 상태 오버레이 72개, 총 90개 PNG. 게임에 설치하지 않은 후보다. 첨부 6개 원본은 그대로 보존했다.

## 먼저 볼 것

- `proofs/01-city-repetition.jpg`: 첨부 두 화면의 주거지에 후보를 놓은 오프라인 합성. 저장 상태가 없어 원래 건물 ID·합필 여부는 확인하지 못했다. 위치·크기는 화면에서 추정했다.
- `proofs/02-variants-states.jpg`: 18개 변형의 기본·낡음·새것·눈·빈집 판자 합성.
- `generation-records.csv`: 90행. 지붕·형태·벽·피벗·눈 피복률·해시·생성 기록 경로.
- `gallery.html`: 각 PNG 직접 링크와 기본/상태 비교.

**첨부에서 가장 크게 반복되는 붉은 박공 지붕·흰 받침 건물은 곡창이다.** 현재 제품 `barn.png`와 일치하며 렌더러에서 granary가 이 그림을 사용한다. 이번 합필 집 후보가 곡창 반복까지 해결했다고 판단하지 않았다. 확인 그림에서는 곡창을 그대로 두었다. `references/product-barn-identification.png` 참조.

## 수량과 재료

의뢰서 제목은 약 70장이지만 A18 + B72의 명시 항목을 모두 제작했다. 공용 상태로 줄이지 않았다.

|계열|c|d|e|
|---|---|---|---|
|L2 가로|초가|초가|기와|
|L2 세로|초가|기와|기와|
|L3 가로·세로|초가|기와|돌판|
|L4 가로|기와|돌판|기와|
|L4 세로|돌판|기와|돌판|

L2는 가로·세로 합계 초가3/기와3. L3는 각 방향 재료별1. L4는 초가 없음. 사용자 최신 의뢰의 돌판 규칙을 이 묶음에 적용했다. 굴뚝은 만들지 않았다. 텍스트는 검수 그림과 문서에만 있다.

## 캔버스·피벗·발판

`records/source-contract.json`은 첨부 원본 6장과 현재 제품의 SHA256 일치, 기존 렌더러의 crop/pivot을 기록한다. 각 변형과 상태는 해당 원본과 같은 크기의 RGBA PNG다. 새 알파 경계로 다시 잘라 중심을 잡으면 피벗이 달라지므로 기존 crop을 그대로 써야 한다.

생성 후 같은 캔버스에 정합하고, 원본 하부 돌받침 접지 띠를 픽셀 그대로 복원했다. 상태 레이어는 그 띠와 기본 그림의 완전 투명 영역에서 알파0이다. 보존 마스크·복원량·차이는 `records/masks/`와 `records/final-contract-qa.json`에 있다. 이것은 2D 그림 정합 검수이며 엔진 점유·충돌·모든 도로 연결 검증은 아니다.

## 눈 측정

눈을 보고 분모를 맞추지 않았다. 기본 변형의 보이는 지붕면을 먼저 수동 다각형으로 지정하고 마스크로 저장했다. 각 계열 기록에 마스크·픽셀수·추출 기준을 남겼다. CSV의 피복률은 눈으로 분류된 지붕 픽셀/보이는 지붕 픽셀 ×100이다. 반투명 경계 처리 때문에 계열별 추출 조건은 기록을 함께 읽어야 한다.

## 생성 기록·경량판

내장 imagegen으로 각 그림을 생성/편집했다. 원본 참조·실제 프롬프트·출력·후처리·재작업은 계열별 `records/`에 있다. 모델 세부 버전과 seed는 도구가 노출하지 않아 적지 않았다. 임의로 만든 수치는 없다.

경량 ZIP에는 최종 PNG·확인 JPEG·CSV·검수표·원본 참조·측정 마스크·재현 스크립트·해시를 넣는다. 큰 생성 원본은 별도 `astra-raw/wave30-20260929/`에 보관하며 원본 목록/해시로 연결한다. 원본 재생성 없이 이 ZIP만으로 최종 PNG와 측정값을 검증할 수 있다. 생성부터 다시 만드는 데는 별도 원본이 필요하다.
