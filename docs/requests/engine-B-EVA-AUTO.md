# Engine B → 렌더: 활성 사건 증가와 EVA-AUTO 크기 관문

Engine B 작업 가지는 정적 독립 사건 108개를 지원하며, 기존 001–200 그림 중 EVA-AUTO가 93장을 선택한다. 렌더 소스는 수정하지 않았다. 기존 생성기를 실행한 뒤 200장 manifest SHA256은 `f39e824c6a515ca85e4a8776f5c3835ea760a760858886f85a4bb4adad6b108b`로 이전과 같다. 새 그림을 그리거나 원본을 편집하거나 설치 확인 표시를 추가하지 않았다.

## 재현과 관측

- `node --import tsx --test tests/eventArtGeneration.test.ts tests/eventArtCard.test.ts tests/verifyProvenance.test.ts tests/registryStewardSuccessionContext.test.ts`
- Mac 24개 중 23개 통과. 유일한 실패는 `eventArtCard.test.ts:236`의 `built < 0.7 * received && built < 10_000_000` 중 총량 조건이다.
- 수령 원본 19,318,673바이트 → 기존 JPEG_QUALITY=70 파생본 11,897,526바이트(원본의 약 61.6%). 개별 그림은 전부 원본보다 작고, 960×540·결정론·출처 해시 대조를 통과했다.
- 과거 71장 기대값을 새 지원 집합의 93장으로 수정했다. 10MB 관문과 인코딩 품질은 변경하지 않았다.
- 출처 생성기가 r01/r02의 소문자 중첩 `records/assets.csv`를 읽지 못하던 문제는 실제 SHA가 일치하는 기존 자료를 읽도록 보정했다. 추가 보관 프롬프트는 선택된 편집 계보라고 주장하지 않는다.

## 필요한 렌더 인계

93개 활성 사건을 모두 유지하면서 기존 10MB 관문을 만족시키는 그림 배포 방식을 검증하거나, 자동으로 늘어나는 사건 그림 집합에 적용할 정식 용량 계약을 판정해야 한다. Engine B는 렌더 구현·품질·용량 정책의 소유자가 아니며, 시험 제외나 한도 완화로 게시 관문을 통과시키지 않는다.

기존 EVA-AUTO가 선택과 빌드 연결은 처리하지만, 현재 총량 시험은 사건 수 증가에 따라 실패한다. 실제 카드 캡처를 아직 추가하지 않았으므로 새 22장에 `installed_by` 확인 표시를 넣지 않았다. 이 요청은 125년 분포·가드레일의 별도 검증을 대체하지 않는다.


게시 범위: 이 문서는 요청만 전달한다. 언급한 Engine B 구현 ae26ab28과 검증 자료는 별도 작업 가지에 있으며 런타임 게시 관문을 아직 통과하지 않았다. 원본 구현의 그림 총량 실패를 이 문서 게시로 해소했다고 간주하지 않는다.
