# 실제 배급 출구를 기준으로 도로 복구

기준 `ce92845f`, 새 복구 작업트리에서만 수정했다. 기존 5개 seed 검증 작업트리와 실패 산출물은 보존한다.

**원인.** seed 5 최종 상태에서 기존 곡창에는 빵 84개가 있었지만 여섯 집이 비어 있었다. 곡창의 두 도로 접점은 (43,5)와 (43,8)이며 배급자는 실제 큰 도로망의 (43,5)에서만 출발했다. 부족 진단은 이 출구를 사용했지만 도로 복구는 두 접점을 모두 사용해 남쪽 접점의 기존 연결을 보고 `none`을 반환했다. 재고 부족이나 새 곡창 부족이 아니었다.

**수정.** `autoplayFoodRoutes.ts`의 굶는 주택 연결 복구는 실제 `eligibleRoamingExits`를 출발점으로 사용한다. 방앗간 원료 운송은 기존 전체 건물 접점을 유지한다. 경로 계획·성벽 통행·설치 가능 여부·비용·자원은 기존 함수를 그대로 사용한다. 배급자의 출구 선택 규칙이나 경제 수치는 변경하지 않았다.

**검증.** 두 접점이 서로 다른 도로망에 있는 회귀를 먼저 실패 재현했다. 수정 후 기존 설치 함수로 도로를 연결하면 실제 배급 출구에서 집까지 도달하며 재고·건물은 보존된다. seed 5 원시 최종 상태의 메모리 복사본에는 정상 도로 행동 (41,15)→(46,15) 한 번만 적용했다. 이후 조언자·추가 건설·자원 주입 없이 정상 엔진 2,400틱을 실행했다.

이는 원래 1,200,000틱 실패 상태 이후의 **원인 검증용 연속 실행**이며 자연 성장 합격으로 계산하지 않는다. 정식 seed 재검증은 별도다. 식량·배급 출구 집중 회귀 237개와 TypeScript 검사를 통과했다. 새 저장 형식·D24·추가 운송 규칙은 없다.
