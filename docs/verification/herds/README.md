# RB-HERDS 실제 장면 검증

전체 설치는 정적 목축군 PNG **4장**이다. 아래는 최초 양 a 1장의 원본 기록이며 그 해시와 캡처를 보존한다. 이후 양 b·소·돼지 3장의 별도 실제 장면·출처·판정은 [확장 보고서](extension/README.md)에 있다. 아래 b/c 유지 설명은 최초 a 검증 시점의 관찰이다.

기준선은 본선 `8936a469`이다. 실제 게임을 DGX Chrome에서 멈춘 상태로 열고, 여름·겨울 각각 줌 1.0·0.6·3.0에서 같은 저장과 카메라를 비교한다. 동물 개체를 만들거나 위치를 옮기지 않는다. 이 묶음은 양 떼 소품 한 종류의 그림 교체이며 동물 시뮬레이션·보행 애니메이션의 증거가 아니다.

## 저장 출처와 정상 재생

원본은 `docs/verification/install4e/scene/pasture-seed4.json.gz`이다. 원본은 schemaVersion 없는 옛 GameState이며, 현재 `loadSaveFile`은 이를 v0로 읽는다. 마이그레이션 v5ToV6가 구역을 비우므로 원본의 목초지 117셀이 그대로 남는다고 주장할 수 없다. 처음 검사에서 목초지 0개·경작지 12개가 확인되었다.

원본 생성기 `scripts/install4eScenes.ts`와 동일한 기록된 `zone_paint` 붓 획을 현재 `gameReducer`로 재생했다. 결과 목초지 membership이 원본 117셀과 완전히 같은지 assert했다. 그 뒤 `advanceTick`만 호출하여 여름 1500·겨울 3500 저장을 만들었다. tick·날씨·소품·동물 수·배치를 직접 쓰지 않았다. 명령·원본 해시·저장 해시·소품 ID와 좌표는 재현 하니스의 provenance.json에 있다.

준비 실행: `astra-HERDS-prepare-8936a46` — DGX `--light`, 종료 0, 정상 전진과 저장 2개 생성.
기준선 캡처 실행: `astra-HERDS-before-8936a46` — DGX `--light`.
설치 뒤 캡처 실행: `astra-HERDS-after-001a487` — DGX `--light`, 제품 `001a48737b461e315b93c85eaeeb5fa8e4378852`.

판정: 6/6 전후 쌍에서 저장·전체 state·tick·카메라·줌·소품 목록 동일. 양쪽 pageerror 0, network failure 0. 모든 after view에서 새 PNG의 실제 world draw가 관측되고 before에는 없다. 줌 1.0/0.6에서는 mip crop `[32,0,32,24]`·`[0,0,32,24]`, 줌 3.0에서는 원본 crop `[128,0,128,96]`·`[0,0,128,96]`가 기록되었다. SE/NE 방향에 대응한다. 상세는 comparisons.json.

캡처는 `scripts/renderCommitProbe.mjs`의 `openScene`과 공식 sceneInjection 경로를 사용한다. 두 화면의 저장·렌더 주입 뒤 state·tick·카메라·소품 목록 해시를 비교한다. Canvas drawImage를 계측하여 새 PNG의 crop과 화면 그리기가 실제로 발생했는지 별도로 확인한다.

## 판정 범위

현재 실제 목초지에는 `sheep_flock` 2개, `sheep_flock_b` 1개, `sheep_flock_c` 1개가 있다. 새 그림은 기존 `sheep_flock`만 바꾸며 b/c/d는 그대로다. 새 시트의 네 방향을 모두 노출시키려고 소품을 임의 배치하지 않는다. 화면에 나오지 않은 방향은 미판정으로 남긴다.

관련 원칙 A4: 실제 목초지 구역이 만든 기존 소품을 그대로 그린다. A5: 원본 저장과 정상 명령 재생·양쪽 저장 해시를 남긴다. 결과를 과장하지 않음: 그림 변경을 동물 개체나 보행 추가로 설명하지 않는다.

## 화면 판독과 한계

여름·겨울 근접 실제 화면에서 기존 목초지의 양 떼가 네 마리 정적 그림으로 바뀌며, 주변 소·다른 양 무리와 같은 땅 위에 놓인다. 새 중앙 양 네 마리는 기존 그림보다 작고 외곽선이 선명하다. 그대로 남은 b/c 양 무리와 화풍·크기 차이가 보인다(부모의 여름 줌 3.0·겨울 줌 0.6 직접 확인 포함). 공통 `animalScale` 값 `0.20670180722891565`를 사용하여 crop 128×96을 세계 크기 약 26.46×19.84px로 그린 결과이며, 원본 그림을 수정하거나 이 차이를 숨기기 위한 별도 배율을 넣지 않았다. 줌 0.6에서는 무리의 존재는 보이지만 네 마리 수·방향·다리 세부를 판독했다고 주장하지 않는다. 원본 그림 속 보이는 개체 수 변화는 장식 그림 차이이며 엔진 가축 수 변화가 아니다.

기존 두 sheep_flock의 ID는 `farm-prop:zone-000013:616`(40,9, SE), `farm-prop:zone-000013:934`(38,14, NE)다. SW/NW는 이 저장에 선택되지 않아 실제 화면 미판정. 봄용 풀 배제 영역의 실제 화면과 장기 성능은 이 캡처 묶음이 검증하지 않는다. 새 시트는 animation=false로 정적이며 움직임은 추가하지 않았다.

## 구현 검증

제품 커밋 `001a4873`. Mac 집중 시험 99개·타입 검사·변경 파일 린트 통과. 계약은 원본 치수·crop·pivot·정적 선택을 검사하며 잘못된 이미지와 로딩 실패 때 기존 그림과 기존 봄 충돌 범위를 함께 쓴다. 설치 출처·장부는 각각 한 행이다. 최종 게시의 변경 시험과 기하 감사 결과는 전달 ZIP의 관문 기록으로 확인한다.
