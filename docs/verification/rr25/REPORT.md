# RR25 측정판 — 시험이 실제로 읽은 파일로 결과를 다시 쓴다

결정: `docs/decisions/README.md` RR25 (사용자 판정 2026-10-09). 코드: `scripts/checks/testInputs/` (traceReads.mjs, traceHooks.mjs, testInputs.mjs), `scripts/checks/testedChanges.mjs`, `scripts/checks/changedTests.mjs`.

## 왜 측정인가
- 정적 추정(import·경로 글자·폴더 지도)으로 "이 시험이 읽는 파일"을 맞히는 방식은 세 번의 독립 검토가 매번 새 빈틈을 재현했다: 이름 바꾼 파일, import된 JSON, 같은 내용의 새 실패, src 밖 폴더를 훑는 시험(저장 fixture를 바꾼 커밋에서 saveFixtures가 재사용됐고 실제로 실패), 헬퍼를 거쳐 public/을 훑는 시험(verifyProvenance), 경로를 조립해 읽는 fixture(doorSigns), 파일 그림자.
- 그래서 시험이 돌 때 읽은 것을 기록한다. 고르기(어떤 시험이 범위에 걸리나)는 정적 규칙(import, 경로, 폴더 지도)을 안전망으로 두고, 기록이 있는 시험은 기록으로도 고른다.

## 기록하는 것
- 시험 프로세스마다(`NODE_TEST_CONTEXT`): fs로 읽거나 열거나 stat한 파일, `require` 해석 결과, ESM 로더가 해석·로드한 모듈(로더 스레드), 목록을 본 폴더(readdir·opendir·cp·glob), 찾다가 없었던 경로(ENOENT, `existsSync` 거짓 — 해석기가 시도한 후보 경로 포함), 그리고 V8이 컴파일한 스크립트 목록(`NODE_V8_COVERAGE`)을 합친다.
- 측정 불가: 자식 프로세스, TCP·HTTP·fetch, 워커 스레드(esbuild 자체 워커 제외), 저장소 밖 읽기(node_modules·임시 폴더 제외). 이런 시험은 재사용하지 않고 항상 돈다.
- 기록이 없거나 깨진(스키마가 다르거나 목록이 아닌) 시험도 재사용하지 않는다.

## 기록이 빠짐없다는 근거 (V8과 비교)
- doorSigns 한 파일: V8이 컴파일한 저장소 스크립트 343개 — 기록에서 빠진 것 0.
- 실제 시험 25개(25 프로세스, `tests/*.test.ts` 30개마다 하나): V8 스크립트 7,048개 중 기록에 없던 것은 25개, 모두 기록 장치 자신의 갈고리(`traceHooks.mjs`, 프로세스마다 1개). 시험이 불러온 7,023개는 모두 기록됐다. V8 목록은 판정에도 합쳐 쓴다.
- 타입만 가져오는 import(`*.types.ts`)는 esbuild가 지워 실행 중 로드되지 않는다: 정적 범위에는 있고 기록에는 없는 것이 정상이다(doorSigns: 정적 807 / 기록 353).

## 판정
- 같은 트리의 기록이면 그 기록이 정한다(통과 = 인정, 실패 = 막음).
- 다른 트리의 기록은, 그 기록의 트리에서 머리의 트리까지 바뀐 파일이 그 시험의 읽은 파일·없던 경로와 하나도 겹치지 않고, 목록 본 폴더 아래에서도 바뀌지 않았고, `package.json`·`package-lock.json`·`tsconfig.json`이 그대로일 때만 인정한다. 시험마다 같은 입력의 가장 새 기록이 정한다(더 새 실패가 옛 통과를 막는다). 비교할 수 없는 실패(이 체크아웃에 없는 내용)도 막는다.
- "읽은 모듈 옆에 새 모듈" 규칙은 뺐다(사용자 승인): 해석 후보 경로가 "없던 경로"로 기록되어 그림자를 잡는다. 확인 사례: 확장자 생략 상대 경로(.tsx → 옆에 생긴 .ts), index 파일(m/index.ts → 생긴 m.ts), package.json의 exports. `.js`로 적고 `.ts`로 풀리는 import는 진짜 `.js`가 생겨도 tsx가 `.ts`를 그대로 불러온다(실행으로 확인) — 재사용이 맞고, `.ts`를 지우면 다시 돈다.
- 근거는 기록에 남는다(`reused`: 시험, 근거 기록의 트리·커밋·실행 이름·시각, 그 뒤 바뀐 파일 수, 이유).

## 시험
- `tests/testedReuse.test.ts`: 버리는 저장소에서 실제로 기록 장치를 돌려 만든 기록으로 판정한다(가짜 기록 없음). 일부러 겹치게 만든 사례(직접·간접 import, import된 JSON, 경로로 읽는 App.tsx, 조립 경로 fixture, 헬퍼가 훑는 폴더, 시험이 훑는 폴더, 그림자 3형태, 지운 파일·이름 바꾸기, 잠금 파일, 내 편집과 시험 자체 편집, 측정 불가, 더 새 실패, 비교 불가 실패, 내용 없는 기록, 깨진 기록, 측정으로 고르기)와 변이 10개.
- 임시 저장소는 `.tmp/`에, git 자동 유지보수를 끄고 만든다(`tests/helpers/tempRepo.ts`; RR26의 간헐 실패 원인 참고).

## 남는 범위
- 고르기는 여전히 정적 규칙이 바탕이다. 측정 기록이 쌓인 시험은 기록으로도 고르지만, 한 번도 측정되지 않은 시험은 정적 규칙과 폴더 지도만으로 고른다. 본선 클론(3~4시간마다)이 마지막 그물이다.
- 기록의 시각은 각 기계의 시계다(Mac·DGX 시계가 크게 어긋나면 순서가 틀릴 수 있다).
- 환경 변수에 따라 건너뛰는 시험(예: DGX 상태 폴더가 없으면 skip)은 그 기록이 "통과"로 남는다 — 지금의 RR16과 같다.
