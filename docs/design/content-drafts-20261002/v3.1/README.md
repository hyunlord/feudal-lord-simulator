# 사건·청원 v3.1

**60개 전수 검토, 변경49개만 납품.** 승인된 v3는 보존했다. 이 묶음은 콘텐츠 편집본이며 게임에 설치하지 않았다.

적용 순서: **v2/events.json 60개 → 승인된 events-v3.json 15개를 id로 교체 → events-v3.1.json 49개를 id로 교체**. 최종 개수는60개다. v3.1 파일로 전체 목록을 덮어쓰지 않는다. 특히 v3에서 수정한028은 v3.1 변경분에 없으므로 v3 단계를 건너뛰면 안 된다.

- `events-v3.1.json`: 같은 초안 배열 형식의 변경분.
- `events-v3.1.schema.json`: 초안용 JSON Schema. 등록기 정의 스키마와 다르다.
- `REVIEW_ALL_60.md`: 모든 초안의 이전/이후 창과 유지 이유.
- `CHANGES.md`: 범위·효과 조건 변경 및 코드 근거.
- `REMAINING.md`: LM-E9 확인 한계와 통합 담당자의 검증 사항.
- `VALIDATION.md`, `records/REVIEW.md`: 수행한 정적 검증 및 독립 검수.
- `validate.sh`, `SHA256SUMS`: 재검증·파일 무결성.

장려금은 지속 설정이며 즉시 건설·지급이 아니다. 보류는 기한을 멈추거나 새 효과를 발생시키지 않는다. 문자열 조건을 eval하지 말고 기존 데이터에 대한 허용 목록 검사로 구현한다. 코드·커밋·푸시·서버 실행 없음.
