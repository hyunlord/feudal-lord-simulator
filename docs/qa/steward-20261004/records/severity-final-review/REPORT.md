# R08 신규 심각도 심의 — 부모 최종 승인용

**현재 검토 증거에서 확정 중간 이상 신규 추가 권고는 0이다.** 이는 새0를 목표로 고른 결론이 아니다. 미배급 원인과 방앗간 과잉건설 후보를 별도 **HOLD**로 남긴다. 부모 최종 count는 null이며 회차 종료·연속0·목표 완료를 이 문서에서 결정하지 않는다.

판정 단위는 사용자 막힘과 교정 계약이다. 새 seed/새 화면/새 분석만으로 신규를 늘리지 않으며, 기존 파일에 있던 현상이라는 이유만으로 새 독립 피해를 숨기지도 않는다. 기존 미해결 전부 수정·원고 엔진 설치를 회차 신규 판정의 필수조건으로 추가하지 않는다.

## R07에서 승계하는 기준

R07 부모 확정 `SEVERITY_FINAL_R07.json`은 신규중이상0, 이전 R06은7, 당시 연속0 회차1이다. R07의 후보표에는 당시 대기 상태가 남지만 부모 최종판정이 우선이다. R06 의미오류7은 유지하며, 넓은 E02 하나로 지워 버리지 않는다. A01은 구HEAD의 목책 공간 탐색 성능 서명이다. 도시의 성장 정체·건물 수 비율과 같은 서명이 아니다.

## 방앗간 후보를 보류하는 구체적 이유

final raw를 Ruby로 직접 읽은 수량은 fen 방앗간13/농가4, open26/농가6이다. fen arableFields4·띠30·칸86(밀73/보리13), open3·띠34·칸95(밀89/보리6)다. 농가 개수가 모든 농지 칸이나 생산량을 뜻하지 않는다. 작은 띠·칸이 별도 필드에 있으므로 건물 수비만으로 수요를 계산하지 않았다.

종점 방앗간의 밀 재고2미만은 fen1/13, open14/26이다. 이는 그 순간 재고이며 장기간 가동률·굶주림 기전·불필요 건물 판정이 아니다. 보존 mill 영수증은 각각13/26이며 planner는 fen food9+barn_mill4, open food10+barn_mill16이다. 마지막 영수증 tick은497640/441636이다. 모든 건물의 전체 수명·철거 이력까지 재구성했다고 하지 않는다.

Graft 질의 후 실제 `autoplayBarnMill.ts:32–59,64–77`을 읽었다. 예상 연간 밀 수량/방앗간 연간제분량과 도로6칸 내 실제 도달 가능한 방앗간 수를 비교한다. 곡물 적체·주택등급 하락·방앗간 입력부족 조건도 있다. 농가1개당 방앗간1개라는 계약이 아니다. `townAgency.ts:299–318`의 mill/granary 적체 가점은 현재 설계 근거이나 각 착수의 정당성을 증명하지 않는다. 현재 최종 상태를 과거 착수 당시 수확·도로·수요로 덮어쓰지 않았다.

- 식량: 기록된 재구성 입력4개에 원 exported 함수를 적용한 반환은 확인됐다. 공식 내부prefix를 계측한 것은 아니고 장기 미배급 원인은 여전히 HOLD다.

## 승인 경계와 출처

비교 담당 r06_registry_merge의 최종 보고서와13개 manifest를 확인했고 자체 raw 집계와 일치했다. 추가 확정 중 이상 없음·mill 별도 HOLD에 양쪽 판정이 일치한다. 부모가 최종 신규 수를 결정한다. 만약 신규 독립 중간 이상 피해가 들어오면0권고를 철회하고 행별 재심한다. HOLD를 정상으로 바꾸거나 기존 모든 결함을 고칠 의무로 확대하지 않는다.

`FINDINGS.json`에 입력별SHA·size·소스span·행별소유자·다음검증을, `RAW_COUNTS.json`에 실제 두final파일SHA와 직접 집계값을 보존했다. 코드를 바꾸거나 엔진·브라우저·SSH를 실행하지 않았다. 최초 잘못된Graft CLI명령 및 없는year1450별칭 조회는 도구조회 실패로만 남기고 help/final경로로 복구했다. 다른 작업자의 기존 파일은 수정하지 않았다.
