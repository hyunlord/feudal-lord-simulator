# Charter & Kin — 확장성 아키텍처 v1

**확정 2026-10-06**(사용자 승인, 결정 EXT-D1~D3). 기초 설계서 2부의 확장성 정본이다([foundation](foundation.md)). 새로 짜는 코드는 2절 원칙 1~6을 지킨다(헌장 4절).

목표: 지금 게임(1300~1450 잉글랜드)을 **완성하면서도**, 나중에 **다른 시대·다른 나라·다른 배경·판타지·모드**를 "갈아엎지 않고" 얹을 수 있는 구조를 지금부터 갖춘다.

## 1. 지금 코드의 상태 (정직한 진단)

| 부분 | 지금 | 다른 배경으로 갈 때 |
|---|---|---|
| 콘텐츠 분리 | `src/content/`에 설정·문구가 모여 있음(건물·자원·직업·세력·장·역병·전쟁·이름) | 좋은 출발점. 다만 **TS 코드**라 "데이터 팩"이 아님 |
| 종류 목록 | `BuildingKind`, `ResourceType` 등이 **닫힌 TS 유니온** | 새 건물·물자를 더하려면 **코드 수정**이 필요 |
| 엔진 모듈 | `plague.ts`(잉글랜드·역병 관련 단어 175곳), `ale.ts`, `lordship.ts`, `reorganisation.ts` 등 **중세 체계가 엔진에 직접** | 다른 배경은 이 모듈들을 켜고 끌 수 있어야 함 |
| 시간·돈 | 1300~1450 장 구조, 돈은 펜스 정수(좋음) + 화면에서 £·s·d 표기 | 달력·연대·화폐 단위가 **설정값**이어야 함 |
| 문구 | `*.ko.ts`로 분리(좋음), 용어 정본 있음 | 언어 키 체계로 바꾸면 영어·모드 번역 가능 |
| 사건 | **등록기(v4)** — 데이터·스키마·어댑터 | **이미 모드 친화적.** 그대로 확장 |
| 그림 | **그림 계약 장치(ASSET-ARCH-1)** — 데이터·스키마 | **이미 모드 친화적.** 팩별 바이블만 더하면 됨 |
| 저장 | 버전 이행 체계 | 어느 팩·어떤 판인지 저장에 적어야 함 |

**결론**: 사건과 그림은 이미 확장 가능한 구조로 들어갔다. 남은 것은 **"종류 목록이 코드에 닫혀 있음"**과 **"중세 체계가 엔진에 직접 박혀 있음"** 두 가지다. 지금 고치면 작은 일이고, 게임이 커진 뒤 고치면 갈아엎는 일이 된다.

## 2. 목표 구조: 코어 + 규칙 모듈 + 설정 팩

```
[설정 팩 (데이터)]  잉글랜드 1300–1450 · (미래) 조선 1400 · 판타지 변경 · 사용자 모드
   달력·화폐·이름·지형·물자·건물·직업·세력·칭호·권리 종류·장/시대·사건·문장 규칙·문구(언어 키)·그림 계약·바이블
        ↓ 스키마 검증, 팩 id·판을 저장에 기록
[규칙 모듈 (코드 플러그인)]  농사 · 제작 사슬 · 시장·운송 · 질병/역병 · 전쟁·소집 · 법·소송 · 교회/종교 · (미래) 마법·괴물
   각 모듈 = 자기 상태 조각 + 틱 갈고리 + 읽기 모델 + 명령. 팩이 어떤 모듈을 켤지 정함
        ↓
[시뮬레이션 코어 (배경 무관)]  시간·틱·seed 난수 · 사람·가구·혈통 · 물자·조리법 그래프 · 장소·필지·건물(데이터) · 권리·청구·약속·계약 · 세력·관계 · 원장 · 등록기 · 저장
        ↓ 읽기 모델 API
[표현]  세계 그리기(그림 계약) · UI(언어 키·팩 문구)
```

원칙
1. **코어는 배경을 모른다.** "밀"·"교회"·"흑사병"·"파운드"라는 말이 코어 코드에 없다. 코어는 "물자", "조리법", "건물 종류", "질병 사건", "화폐 단위"만 안다.
2. **종류는 데이터, 코드는 열린 id.** 건물·물자·직업·세력·칭호는 팩에 정의되고, 코드는 문자열 id + 로드 때 검증. TS 타입은 팩에서 생성하거나 브랜드 문자열.
3. **특수 체계는 모듈.** 역병·에일·직물·성벽·장 재편 같은 체계는 모듈로 감싸 팩이 켜고 끈다. 판타지 팩은 "역병" 대신 "저주" 모듈을 켤 수 있다.
4. **문구는 키.** 화면·원장·연대기 문구는 팩의 언어 키로. 용어 정본도 팩마다.
5. **그림은 팩의 계약.** 그림 계약에 팩 id, 팩마다 바이블(비율·광원·팔레트·시대 금지 목록).
6. **저장은 팩을 안다.** 저장에 팩 id·판·켠 모듈 목록. 팩이 바뀌면 이행.

## 3. 지금 할 것 / 나중 할 것

**지금(작고 값이 큼) — "이음새"만 넣는다**
- EXT-0 규칙: 이 문서를 기초 설계서에 붙이고, **새로 짜는 코드부터** 원칙 1~6을 지킨다(헌장·AGENTS에 한 줄).
- EXT-1 열린 id: `BuildingKind`·`ResourceType`·직업·세력 종류를 데이터 레지스트리 + 문자열 id로(로드 때 검증). 동작은 그대로, 가드레일 해시 불변이 관문.
- EXT-2 달력·화폐를 설정값으로: 연도 범위·계절·장 구조·화폐 단위와 표기를 팩 설정으로. 동작 불변.
- EXT-3 팩 껍데기: `packs/england-1300/`에 지금 콘텐츠의 위치를 정하고(파일 이동은 점진), 저장에 팩 id·판.

**점진(작업이 그 체계를 만질 때마다)**
- EXT-4 모듈화: 역병·에일·직물·전쟁·재편·성벽 등을 **그 체계를 고칠 때** 모듈 인터페이스로 감싼다(한꺼번에 갈아엎지 않음).
- EXT-5 문구 키: 영어판 작업 때 언어 키 체계로.

**증명(확장성이 말뿐이 되지 않게)**
- EXT-6 **시험용 둘째 팩**: 아주 작은 팩(예: 가상의 다른 왕국 — 다른 이름·화폐 단위·작물 하나·건물 하나·사건 셋·자리 그림)으로 새 게임이 **실제로 뜨고 10년 돌아가는지**를 정기 시험에 넣는다. 둘째 사용처가 있어야 이음새가 썩지 않는다.

**하지 않음(지금은)**
- 모드 불러오기 화면·스크립트 언어·여러 팩 동시 실행·범용 전술 전투. 필요가 생길 때.

## 6. 목표 경험: "완성된 뒤에도 모드 만들기가 쉬운 게임" (확정 2026-10-06)

기준이 되는 느낌: **림월드·크루세이더 킹즈·팩토리오처럼 — 모드 폴더 하나에 데이터·문구·그림을 넣으면 게임 코드를 건드리지 않고 새 시대·새 나라·판타지가 된다.**

### 6.1 본편도 모드다
- 지금 게임(잉글랜드 1300~1450)은 **"core" 팩**으로 들어간다. 모드는 본편과 **같은 형식, 같은 길**로 들어간다. 본편만 쓰는 특별한 통로를 만들지 않는다.

### 6.2 모드 폴더 하나의 모양
```
mods/<mod-id>/
  mod.json          id · 이름 · 판 · 필요한 게임 API 판 · 의존(예: core) · 불러오는 순서 힌트 · 켤 규칙 모듈
  defs/             물자·조리법·건물·직업·세력·칭호·권리 종류·지형·달력·화폐·이름·장/시대 (JSON, 스키마 있음)
  events/           사건·청원(등록기 형식)
  patches/          다른 팩 정의를 바꾸기 — 더하기/덮어쓰기/빼기/값 고치기(id로 가리킴)
  lang/<언어>.json  문구 키 → 문장, 용어 정본
  art/              그림 계약 + 파일, 팩의 바이블
  scenarios/        시작 지도·시나리오·튜토리얼
  modules/ (선택)   새 규칙 모듈 코드(고급 — 정해진 모듈 API만 사용)
```

### 6.3 모드 만들기가 쉬우려면 필요한 것
1. **데이터만으로 되는 범위를 최대로**: 새 물자·건물·직업·사건·문구·그림·시나리오는 코드 없이.
2. **패치 연산**: 본편 정의를 복사하지 않고 "이 건물의 비용만 바꿈", "이 사건 빼기"가 되게(림월드 PatchOperation처럼).
3. **분명한 오류**: 모드를 불러올 때 스키마·참조·충돌을 검사해 **어느 파일 몇째 줄이 왜** 틀렸는지 알려 줌. 게임이 조용히 깨지지 않음.
4. **불러오는 순서와 의존**: mod.json의 의존·순서로 결정론적으로 합침. 같은 id를 두 모드가 바꾸면 경고.
5. **안정된 모드 API 판**: 코어·모듈의 공개 인터페이스에 판 번호. 판이 바뀌면 이행 안내.
6. **저장이 모드 목록을 앎**: 저장에 켠 모드와 판. 모드가 빠지면 불러오기 전에 알림.
7. **만드는 도구**: `npm run mod:validate <폴더>`, 모드 하나로 새 게임 띄우기, 예제 모드와 문서(모드 만들기 안내서).
8. **결정론 유지**: 모드가 있어도 같은 seed·같은 모드 목록이면 같은 결과.

### 6.4 증명 — 시험용 둘째 팩은 "작은 판타지 변경 모드"
- `mods/example-fantasy-march/`: core에 의존, **패치로** 이름·화폐 단위·작물 하나를 바꾸고, 건물 하나·사건 셋·자리 그림을 더하고, 역병 모듈을 끄고 작은 "저주" 모듈(데이터로 정의된 질병 변형)을 켬.
- 정기 시험: 이 모드로 새 게임이 뜨고 10년 돌아감, mod:validate 통과, core만 켠 판의 가드레일 해시 불변.
- 이 예제가 곧 **모드 만들기 안내서의 첫 예제**가 된다.

### 6.5 순서(3절에 더해)
- EXT-0 문서·규칙 → EXT-1 열린 id → EXT-2 달력·화폐 설정 → EXT-3 팩 껍데기(core 팩·mod.json·저장의 모드 목록) → **EXT-3b 불러오기·합치기·패치·오류 보고·mod:validate** → EXT-6 예제 판타지 모드 → 점진 EXT-4 모듈화·EXT-5 문구 키.
