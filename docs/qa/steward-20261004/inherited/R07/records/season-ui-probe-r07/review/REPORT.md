## 저장과 설정의 정확한 범위

초기 fixture SHA `5a3560012282942253fa7699704dc1eb7147405ee3d755598b50dc7088644961`, seed1/tick100000. DGX의 정상 decodeSave+IndexedDB readback은 원본 bytes와 같았다. 수동 저장 SHA `6cf3748893776dab4158fe9228c3c0bb1eaded680d328d1f0b14afc80867c945`, checksum `cyrb53:1f5445eb8b74c3`, tick101156. 저장 후 읽기와 마지막 persisted manual 읽기는 동일하다. 마지막 실제 UI103006과 manual101156의 차이는 저장 시점 차이이며 저장 실패가 아니다.

설정은 `feudal.seasonLedgerAuto`를 web platform preferences/localStorage에 저장한다. 이 실행은 **같은 origin·같은 Chrome 프로세스/profile의 Page.reload**다. 브라우저 프로세스 종료 후 재시작, 다른 profile/기기, 저장 파일 내보내기·가져오기에서 옵션이 이동하는지는 시험하지 않았다. README의 넓은 ‘브라우저 재시작’ 표현을 실행 결과에 그대로 옮기지 않는다.

수동 저장 원시 bytes는 executed 폴더에 별도 파일로 남지 않았고 정상codec 결과의 SHA/checksum/season 상태가 JSON에 남는다. 따라서 리뷰어가 동일 bytes를 다시 codec에 넣어 검증한 것은 아니다. 정상 save click, decode 성공, 실제 reload 후 tick 일치를 함께 증거로 사용한다.

## 첫 플레이 #7 판정

‘자동 보고서가 멈췄을 때 어떻게 계속하며, 끄고 다시 켤 수 있는가’에는 카드의 계속/토글과 일시정지 메뉴라는 실제 경로가 있다. 이번 저장에서 조작·설정 유지·다음 경계 동작을 확인했으므로 그 제한된 질문은 해결됐다. 사용자 발견성, 긴 플레이의 방해 빈도, 다른 모달과 충돌, 모바일/다른 해상도, 브라우저 재시작, 모든 저장 및 실제 신규 플레이 전체의 개선은 미검증이다.

소스·원본 변경 및 엔진/브라우저/원격 실행 없이 증거만 검수했다. 전체1104 source/input/helper 핀과93실행 manifest를 확인했고 실행 후 별도 source-check 로그는 없다. frontend 증거 원칙을 따르며 읽기 전용 계약에 따라 추가 도구 설치·성능 측정·UI 변경은 하지 않았다.
