# 중세영주 UI 상태·HUD 설계안 (조사 15 — 우리 게임 특화 설계)

결론: 상시 HUD는 네 항목(날짜·계절, 인구, 식량 버팀(일), 돈)으로 이루어진 상태 알약 한 줄과 우하단 행동 도크 하나로 줄이고, 건설·자원·구역·inspector는 모두 행동이 불렀을 때만 뜨는 서랍/모드로 바꿔야 합니다. 이렇게 하면 평소 UI 면적은 1280×800에서 4.1%, 1180×820 태블릿에서 5.9%로, UX-3의 "≤ 8%"보다 여유 있게 낮아집니다. 다만 8%라는 숫자 하나로 모든 상태를 재는 규칙은 틀렸으므로 상태별 예산으로 바꿔야 합니다.

## TL;DR
- **상시 정보는 4개(날짜·계절 / 인구 / 식량 버팀 일수 / 돈)만 둡니다.** 개별 자원 7종 이상은 "자원 장부 서랍", 저장소 inspector, 위기 아이콘으로 옮깁니다. Farthest Frontier 공식 가이드(farthestfrontier.com/guide/about/basics)도 상단 우측에 "Logs, Firewood, Planks, Stone, Clay, Bricks and Gold" 7종만 두고, 식량은 "Food stocks"라는 집계 하나로 보여 줍니다. 전체 재고는 하단 "Resources in Storage" 버튼으로 필요할 때 엽니다("opens the resources tab of the Town Center, where you can see a complete summary of all resources stored within your town. Default hotkey: R"). 식품을 종류별로 상단에 늘어놓는 게임이 아니라는 뜻입니다.
- **UX-3 가설은 방향은 맞지만 숫자 규칙이 틀렸습니다.** "평소 ≤ 8%" 하나가 아니라 상태별 예산(평소 PC ≤ 6%·태블릿 ≤ 8%, 배치 ≤ 6/9%, 구역 ≤ 8/12%, 선택 ≤ 18/24%, 일시정지 동반 모달은 예외)으로 바꿔야 합니다. 이번 조사에서 외부 게임 화면 면적을 제가 직접 잰 수치는 **없습니다**(이미지 열람 불가). 그래서 이 예산은 `가설`이며, 우리 빌드에서 재는 관문으로 검증해야 합니다.
- **P0 다섯 가지:** ① 하단 상시 건설바 제거 → 건설 버튼 한 개 + 서랍 ② 상단 자원바 제거 → 상태 알약 ③ 배치 모드에서 발자국 칸별로 초록/빨강 + 패턴 + 이유 문구 표시(Against the Storm식) ④ 층위 전환(직접/구역/방향)을 좌하단에 상시 노출하고 잠김 자물쇠 표시 ⑤ 한 번에 하나만 여는 규칙(상태 기계)을 코드로 강제.

## 1. 핵심 답변 (15줄)

1. S-1 상시 HUD는 **상태 알약 1개(4항목) + 속도 3버튼 + 층위 전환 3버튼 + 행동 도크(건설·장부·청지기)** 뿐이다. 1280×800 기준 4.13%. `유력`
2. S-2 상단 자원바는 **폐지**한다. 자원은 종류가 많고 저장소마다 다르므로, 한 줄 합계는 틀린 정보를 준다(창고에 있어도 공사장에서 멀면 없는 것과 같다). `유력`
3. S-3 식량은 품목별이 아니라 **"식량 버팀 N일" 집계 한 개**로 상시 표시한다. Farthest Frontier 공식 가이드가 상단 좌측에서 "Food stocks"를 사람 상태의 하나로 묶은 것과 같은 방식이다. `유력`
4. S-4 건설 메뉴는 **B키/건설 버튼을 눌렀을 때만** 하단 서랍으로 연다. Farthest Frontier도 "Build (B)"가 "opens the Building menu"로 필요할 때 연다. `확정(외부 사례) / 유력(우리 적용)`
5. S-5 건물을 고르면 서랍은 **즉시 닫히고 배치 모드**로 넘어간다. 배치 모드 UI는 커서 옆 정보 칩과 확인/취소 바뿐이다(4.48%). `유력`
6. S-6 배치 유효성은 **발자국 칸 단위로** 초록/빨강을 칠하되 **빨강 칸에는 사선 패턴 + 이유 아이콘**을 겹친다. 색만으로 전달하지 않는다(Game Accessibility Guidelines 기본 항목). `확정(원칙)`
7. S-7 배치 후 **고스트가 커서에 남아 연속 배치**하고, Esc/우클릭으로 빠져나간다. Against the Storm 공식 튜토리얼 동작과 같다. `확정(외부 사례)`
8. S-8 구역 층위 전환은 **좌하단 상시 버튼**으로 처음부터 보이게 하고, 해금 전에는 **자물쇠 + 해금 조건 툴팁**을 단다. RimWorld Wiki "Zone/Area"는 Area가 "act like an invisible layer on the map. Areas become visible only when using their expand or clear tools"라고 설명하는데, 이렇게 도구를 켤 때만 보이는 층은 발견성이 0에 가깝다. `유력`
9. S-9 구역 모드를 켜면 **칠할 수 있는 땅을 즉시 오버레이**한다(Manor Lords 비옥도 오버레이처럼).\[1\]\[2\] 도구는 붓·다각형·지우기·되돌리기/다시·붓 크기 5종이다. `유력`
10. S-10 **한 번에 하나만** 규칙: 서랍·inspector·모달은 상호 배타이고, 새로 열면 이전 것이 닫힌다. 예외는 위기 아이콘(비모달)뿐이다. `유력`
11. S-11 사건·결정 모달과 계절 결산은 **자동 일시정지**를 동반한다. 그래서 면적 예산에서 예외로 둔다. Xbox Wire 기사("City-Building in Your Hands: Adapting Frostpunk 2's Depth to a Gamepad", 2025-09-18)가 전한 Frostpunk 2 콘솔판의 "Both radial menus pause time automatically… The Extended City View (accessed with X) also freezes time"과 같은 논리다. `유력`
12. S-12 태블릿은 **모든 터치 대상 ≥ 48px**(Apple 권장 44pt보다 여유)로 하고,\[3\]\[4\] 배치는 "탭-드래그-확인 버튼" 3단계로 한다. 호버가 없으니 이유 문구는 칩에 상시 표시한다. `유력`
13. S-13 UX-3의 "평소 ≤ 8%"는 **상태별 예산으로 대체**한다. 외부 면적 실측이 없으므로 숫자는 `가설`이며, 8절의 측정 관문으로 확정한다.
14. S-14 조사 12의 핵심 오류는 "무엇을 어디에"만 물었지 **"언제 보이는가(상태)"를 묻지 않은 것**이다. 그래서 재배치만 했을 뿐 면적은 줄지 않았다. `유력`
15. S-15 결정이 필요한 것은 네 가지: 상시 4항목 확정, 식량 버팀 계산식, 태블릿에서 inspector를 오른쪽 패널로 둘지 하단 시트로 둘지, 구역 해금 시점(10절).

## 3. B — 상태별 와이어프레임

면적 = 요소 bounding box의 합 ÷ 화면 면적(1280×800 = 1,024,000px², 1180×820 = 967,600px²). 월드 위 오버레이(고스트, 유효성 칸, 서비스 범위 원, 구역 오버레이)는 **UI 면적에서 뺍니다**(게임 화면 그 자체이므로). 모달 배경 어둡게도 면적에서 뺍니다.

### 3.1 평소 (S-20)

```
1280×800 ─────────────────────────────────────────────────────────────
[ 봄 3주·1347 | 인구 42 | 식량 38일 | 12£ ]  (360×36)     [⏸ ▶ ▶▶] (132×36)
[ 목표: 곡물창고 짓기 ▸ ] (240×32, 접힘)
                                                   [!식량][!막힘] ← 위기 시만 36×36
                        ( 게 임  화 면 )

[직접|구역|방향] (156×48)                          [건설][장부][청지기] (168×56)
───────────────────────────────────────────────────────────────────────
```

| 요소 | 1280×800 px | 면적 | 1180×820 px | 면적 |
|---|---|---|---|---|
| 상태 알약 | 360×36 | 12,960 | 380×44 | 16,720 |
| 속도 | 132×36 | 4,752 | 160×48 | 7,680 |
| 층위 전환 | 156×48 | 7,488 | 168×56 | 9,408 |
| 행동 도크 | 168×56 | 9,408 | 200×64 | 12,800 |
| 목표 카드(접힘) | 240×32 | 7,680 | 260×40 | 10,400 |
| **합계** | | **42,288 = 4.13%** | | **57,008 = 5.89%** |
| (위기 아이콘 최대 3개) | 36×36×3 | +3,888 = +0.38% | 48×48×3 | +6,912 = +0.71% |

### 3.2 건설 메뉴 열림 (S-21)

```
[ 상태 알약 ]                                   [ 속도 ]

                        ( 게 임  화 면 )
[층위]  ┌──────────── 건설 서랍 640×152 ────────────┐  [도크]
        │ [식량][주거][생산][저장][도로·목책][구역]│
        │ [곡물창고 원목4][빵집 목재6][우물 원석2]…│
        └──────────────────────────────────────────┘
```

외부 근거: Farthest Frontier 공식 가이드(farthestfrontier.com/guide/about/basics)의 상단 HUD는 좌측에 사람 상태(Health, Population and Housing, Happiness, Food stocks), 중앙에 계절, 우측에 "Logs, Firewood, Planks, Stone, Clay, Bricks and Gold" 7종을 둡니다. 전체 재고는 하단의 "Resources in Storage" 버튼(단축키 R)으로 여는데, 가이드 설명은 "opens the resources tab of the Town Center, where you can see a complete summary of all resources stored within your town"입니다. 즉 **성공한 동종 게임도 상시 자원은 "건설 자재 + 금"으로 좁히고, 식량은 집계 한 개로 두며, 전체 재고는 필요할 때 여는 화면(우리 S-26 장부 서랍의 선례)으로 보냅니다.** 우리는 한 걸음 더 나아가 건설 자재도 뺍니다. 이유는 ① 사용자 판정("저장소마다 다르다")과 ② 건설 카드가 비용·부족분을 직접 보여 주기 때문입니다(S-40). 이 선택은 Farthest Frontier보다 공격적이므로 `가설`이며, 플레이테스트에서 "원목이 얼마 있지?"라는 질문이 자주 나오면 **원목·목재 2개를 5·6번째로 추가**하는 후퇴안을 둡니다.
