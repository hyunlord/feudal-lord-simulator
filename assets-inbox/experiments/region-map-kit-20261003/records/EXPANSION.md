# 지역지도 확장 메모

상태: **candidate / 설계 제안 / 게임 미설치**. 현 키트와 정적 조립기의 다음 단계이며, 아래 기능은 이번 결과에 구현·검증되었다고 주장하지 않는다.

## 18개에서 40개 영지로

1600×1000에서 그림 크기를 그대로 두고 영지만 늘리면 중심부 접지·문장·밭·길이 겹친다. 현재 `assembler/geometry.cjs`의 자동 배치는 영지 중심 간145px 이상과 물 거리만 검사하며, 사용자 지정 좌표에도 최소55px 간격을 검사한다. 이 간격 검사는 실제 PNG 점유 다각형 충돌 검사를 대신하지 않는다. `render.cjs`는 대략70~125px의 정착지 그림과 깃발을 얹고 y순으로 그린다. 이는40개 수용 보장이 아니다.

1. 지도 데이터 좌표는 유지하고 화면 카메라에 줌·팬과 LOD를 추가한다. 전체보기는 작은 실루엣+선택 표시, 중간 줌은 장원/시장/수도원 구분, 상세 줌은 정착지 그림·문장·이름·권리를 표시한다. 선택한 영지는 LOD와 무관하게 식별한다. 기존 원본을 확대해서 새로운 고해상도 원본으로 등록하지 않는다.
2. 각 키트 자산에 `canvas`, `anchor`, `alphaBounds`, 지면 점유 다각형, 문장/이름의 화면공간 여백을 둔다. 충돌은 접지점 사이 거리 대신 점유 다각형과 강둑·길 통행 폭을 함께 검사한다. 건물끼리뿐 아니라 밭이 문장이나 옆 장원을 덮는 경우도 판정한다. 배치 실패는 명시적으로 반환하고 영지 수를 몰래 줄이지 않는다.
3. 라벨 후보 위치를8방향으로 만들고 선택 영지→플레이어 영지→분쟁/요청 영지→나머지 순으로 배치한다. 충돌 시 짧은 이름·작은 점 표식·대표 묶음 순으로 축약하고, 호버/포커스에서 전체 정보를 복원한다. Korean/English, 긴 수도원 이름, 1280×800과1920×1080, 전체보기와 확대 상태를 각각 검수한다.
4. 현 생성 길은 최소 연결 트리이며 `connected`는 무방향 도달 여부만 본다.40개 버전은 우회로·시장 접근·통행권을 별도 설계한다. 물리 간선과 법적 사용 가능 간선을 분리하고 소유자, 통행 허가, 통행료, 계절 폐쇄, 다리/여울/나루 운영 상태를 기록한다. 모든 영지의 물리 연결이 모든 인물의 자유 통행을 뜻하지 않게 한다.
5. 40개 고유 houseId/estateId, 데이터 보존, 모든 허용 거점 연결, 금지 수역 침범0, 충돌0 또는 승인된 중첩 목록, 읽을 수 있는 선택 상태를 통과 기준으로 둔다. seed별 검사를 하고 과밀 실패 seed를 숨기지 않는다.

미술 확장은 새40개 고유 건물 그림보다 동일 지역·용도·규모의 A/B 실루엣과 LOD 구분을 우선한다. 좌상 광원과 바닥 접지를 유지하며 flipX로 방향성 채색을 뒤집지 않는다.

## 인접한 지도 두 장

현재 조립기는1600×1000 한 장, 순차 RNG, 한 장 안의 강·길·지면 반복으로 구성된다. 서로 다른 seed로 두 장을 만든 뒤 붙이는 것은 연결된 지역 생성이 아니다.

- `worldSeed`, `generatorVersion`, `chunkId={x,y}`, 세계 좌표 원점·크기를 저장한다. 난수는 `(worldSeed, layerId, globalCellX, globalCellY, objectId)`의 안정적인 해시로 구해 청크 생성 순서나 영지 추가가 주변 숲 전체를 바꾸지 않게 한다. 자산 선택·지형·영지·라벨 난수 흐름을 분리한다.
- 먼저 두 청크를 포함하는 공통 수계 그래프를 만든다. 강의 전역 곡선·폭·흐름·합류점·바다 출구를 공유하고, 경계 포트에는 전역 위치·접선·폭·높이/흐름·강 ID를 둔다. 도로도 공통 포트와 통행권을 가진다. 양쪽이 독립적으로 경계 하천이나 다리를 결정하지 않는다.
- 각 청크에 최대 브러시 반경/스프라이트 돌출/필터 반경보다 큰 halo를 추가해서 렌더하고 중앙 영역만 자른다. 경계에 걸친 숲·언덕·정착지는 하나의 전역 objectId로 소유·중복 제거하며 두 렌더에서 같은 변환을 쓴다. 지면 타일 시작점도 세계 좌표로 고정한다.
- 검증은 데이터 포트 일치만으로 끝내지 않는다. 동일한 세계의 경계 주변을 A와B에서 각각 **같은 전역 구간**으로 렌더해 PNG RGBA 픽셀을 비교한다. 공통 overlap의 모든 픽셀이 같아야 한다. 나란히 있는 마지막 열/첫 열은 서로 다른 세계 위치이므로 그 두 열의 단순 동일성은 올바른 시험이 아니다.
- 통합 큰 캔버스 렌더를 기준으로 청크별 결과를 이어붙인 것과 비교한다. 강둑·길 접선·지면 질감·숲 실루엣·알파 합성 경계를 실물100%와 확대에서 확인한다. JPEG는 블록 압축 차이가 있으므로 이음새 정합 시험은 무손실 PNG로 수행하고 공유 JPEG는 파생본으로 둔다.
- A→B/B→A 생성 순서, 독립 재생성, 캐시를 비운 재생성에서 결과가 같아야 한다. 청크 경계의 다리 폐쇄 후 다른 청크 경유 우회 탐색도 별도 검증한다.

현 소스의 `neighbor-redraw`는 원본 그림의 수로 벡터가 없어 세 도하점에 맞춰 강을 재구성한다. 원본 강 전체를 정확히 추출했다는 뜻이 아니다. 확장 전에 전역 수계 정본을 새 설계 데이터로 승인해야 한다.

## 겨울 변형

겨울은 새 풍경으로 자유 재생성하지 않고 기존 자산의 상태 변형으로 관리한다. 같은 assetId 계열에서 **정확히 같은 캔버스, 피벗, 접지, 점유 마스크, 건물 실루엣**을 유지한다. 지붕·밭·길·강둑·나무의 눈 허용 마스크를 따로 두고, 식생 계절 마스크와 충돌/통행 마스크를 섞지 않는다. 적설의 허용 돌출은 별도 snowBounds에 기록하며 건물 지면 점유를 자동 확장하지 않는다.

- 기본 RGBA + 눈 RGBA overlay를 같은 좌표에 합성한다. 베이스/겨울 자산의 치수·anchor·마스크 해시를 검증하고, 밝은/어두운 바탕과 원본 지도에서 경계·번짐·접지를 확인한다.
- 눈이 참나무를 파란 금속이나 회칠을 흰 플라스틱으로 바꾸지 않도록 중간톤과 좌상광을 유지한다. 겨울 가지형 나무는 같은 위치·크기 계약으로 별도 상태 ID를 둔다.
- 계절 crossfade는 시각 opacity 보간이다. 동일한 레이어 순서와 premultiplied-alpha 합성을 사용하고0/25/50/75/100% 상태에서 이중 윤곽·깃발 유령·바닥 이동을 검수한다. 전역 계절값으로 인접 청크 전환을 동기화한다.
- 강에 얼음이 그려졌다는 사실만으로 보행 가능하게 만들지 않는다. 얼음 통행은 별도 시뮬레이션 상태·두께/안전 조건·하중 제한·개방/폐쇄 사건·경로 재탐색의 계약이다. 겨울 나루 정지, 여울 위험, 다리 사용 가능성도 별도 간선 상태로 결정한다.

현 조립기에는 겨울 overlay·crossfade·얼음 통행 엔진이 없다. 현 결정론도 같은 입력·같은 키트 바이트·같은 sharp/libvips 버전 범위의 정적 출력 결정론이며 서로 다른 렌더러 간 동일성은 미검증이다.
