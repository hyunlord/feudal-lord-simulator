# S6-F5 공사 취소 화물 귀환

1. 현재 본선에서 R1 `s6-cancel-full-store`를 재현했다. 취소 뒤 창고 200, 귀환 화물 8, 3,000틱 후에도 동일 운반꾼이 남아 두 번째 공사는 목재 1에서 멈췄다.
2. 취소된 공사 배송 화물은 경로가 있는 가장 가까운 호환 창고를 고른다. 도로/벽 운반의 기존 귀환 경로를 재사용하고 도로 비용 1·벽 운반 비용 2의 총비용 동률은 건물 ID 순이다. 원래 창고만 고집하지 않으며 가득 찬 창고도 귀환 화물을 받는다.
3. 정상 배송과 생산 입고의 공유 저장 한도는 유지한다. 취소 귀환에만 한도 초과 하역을 허용하여 운반꾼이 사라지고 원래 공급원은 다시 공사 배송에 참여한다. 이미 한도가 넘친 동안 신규 입고는 기존 여유 공간 0 판정에 의해 막히며, 출고와 소비는 계속된다.
4. `넘침 N · 귀환 화물을 임시 보관 중`은 현재 실물 재고 합계−공유 한도의 파생값이다. 입고 예약은 넘침에 포함하지 않는다. 소비로 한도 이하가 되면 즉시 사라진다. 원인 등록표·지도 원인·선택 상세의 기존 체계를 사용한다. 저장 필드·버전 변경 없음.
5. 취소 현장에 이미 내려진 자재의 60% 환급 규칙 및 국고 목재 반환은 바꾸지 않는다. 생산용 일반 fetch 운반의 예약 소유권도 그대로다.

검증: R-T10 실제 기본 게임 공사/배송/취소/귀환/다음 공사 흐름, R-T11 파생 표시 해제, 가까운 가득 찬 다른 창고 선택·가까워도 경로 없는 창고 제외, 기존 운반 예약 소유권·취소 회귀. `tests/constructionCargoRecovery.test.ts`, `tests/deliveryReturnCapacityOwnership.test.ts`, `tests/constructionCancellation.test.ts`.

R-T17: 지시서의 A⁵-1 seed2 석벽 16구간 원시 상태는 전달된 증빙에서 찾지 못해 자연 상태라고 주장하지 않는다. 별도 준비 상태 16구간에서 첫 구간 `no_route`를 남겨도 나머지 15개 작업 완결을 고정했다(`stoneConstructionFlow.test.ts`). 자연 상태의 실제 12구간 벽 운반은 R-T9에서 별도 검증한다.
