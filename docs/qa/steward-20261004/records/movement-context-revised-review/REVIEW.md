원본 PROPOSAL과 대조하여 이 3개 headline만 바뀌었고, 나머지 10문구·조건·필드 계약·스키마·fixture는 그대로임을 확인했다. 원본의 자동 칙허 목재 주문 경로 확인, 수령처와 실제 사용처 구별, 제안 조건과 거절 동기 구별, 사건 시점 캡처 및 FIX-12 이름 읽기 계약을 유지한다. “현재 도시 기록”은 사건 발생 당시의 people 범위를 뜻하며 읽는 시점의 현재 인물 목록으로 과거 사건을 재구성해서는 안 된다.

## 독립 재실행

작성자 `validate.rb`의 출력 경로만 검수 폴더로 바꾸어 같은 검사 논리를 실행했다. 원고 폴더에 스크립트를 실행하여 결과를 덮어쓰지 않았다.

- 선택 fixture **104/104**.
- 스키마 음성 **75/75**.
- 추가 필드 gate **26/26**.
- envelope **15/15**.
- 읽을 때 이름 계약 모형 **4/4**. 실제 인명 formatter 실행 결과는 아니다.
- 소스 **11파일·22인용 범위**의 SHA와 줄 내용을 실제 저장소와 대조했다. 교정과 직접 관련된 lordship의 가문 소멸·교체·빵 배분 분기를 읽고 판정했다.
- 원본 및 수정 원고 전체 파일 해시가 검사 전후 동일하다. 정본 650 SHA `7314050459321e78ea19257fd4376ff80ab803586b0adfdaf2dd8ee159666dbf`도 보존했다.

첫 검수 래퍼 실행은 작성자 스크립트와 로컬 변수 이름이 겹쳐 검사 후 보존 확인 단계에서 중단되었다. 검수 폴더의 래퍼 변수만 교정한 뒤 전체 검사를 재실행해 통과했다. 후보·엔진 결함으로 분류하지 않는다.

`RESULT.json`이 최종 독립 판정이다. `VALIDATION.json`은 작성자 검사 논리를 재실행한 결과이므로 안의 “독립 검수 대기” 문구는 원 작성자 상태 문자열이며 이 보고서의 판정을 대체하지 않는다.

사건 시점 어댑터 구현, 실제 저장/복원, UI·엔진 실행은 이번 재검수 범위 밖이다. 조건부 승인은 실제 선택된 producer 경로와 사건별 record 결합을 확인한 문맥만 사용하고 불명확하면 fallback한다는 초안 계약을 유지한다.
