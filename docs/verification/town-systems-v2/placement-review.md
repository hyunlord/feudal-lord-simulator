# 성벽·공사장 배치 독립 검토

판정: PASS (2026-09-20, 코드 읽기 + 독립 엔진 재현).

## 결함과 수정

기존 `engine/palisade.ts`는 완성 건물만 성벽 이격 검사에 넣어, 주택 공사를 먼저 시작하고 그 자리를 지나는 성벽을 확정할 수 있었다. 새 `engine/palisadeFootprints.ts`는 완성 건물의 실제 점유와 건물 공사장의 전체 점유를 함께 반환한다. `palisade.ts` 확정, `autoplayActions.ts` 자동 제안, `eraConsoleModel.ts`를 통한 UI 제안·드래그가 같은 함수에 연결된다. 중복된 세 점유 계산을 하나로 합쳤다.

## 독립 재현

24×24 잔디 맵, 기존 선포 가능 마을, 목재1000, 성벽 경로 (5,5)→(15,5)→(15,15)→(5,15)→(5,5). 실제 tile.buildingId까지 주택 공사장에 할당한 상태로 reducer를 호출했다.

| 주택 공사장 | 기대 | 실제 |
|---|---|---|
| (3,9), 벽 바깥 1칸 간격 | 승인·공사장 보존 | 통과 |
| (4,9), 벽과 모서리 접촉 | 원본 상태 그대로 거부 | 통과 |
| (5,9), 벽과 모서리 접촉 | 원본 상태 그대로 거부 | 통과 |
| (6,9), 벽 안쪽 1칸 간격 | 승인·공사장 보존 | 통과 |

원래 발견한 (5,9) 사례는 수정 전 accepted:true에서 수정 후 accepted:false로 바뀌었다. 승인된 결과에 실제 목책 공사장들이 있어도 공유 함수는 이를 건물로 세지 않는다. 석벽 공사장도 추가해 제외됨을 확인했다. `isBuildingConstructionSite`가 두 성벽 종류를 명시적으로 제외한다.

## 범위와 한계

이 검토는 실제 reducer/기하의 점유·이격 보장이다. 지붕 위 도로 덧그림이나 성벽 깊이 순서의 시각 검증을 대신하지 않는다. PNG를 새로 생성하지 않았고 실행 화면 평가는 별도 렌더 검토·브라우저 캡처가 담당한다. 기존 저장 데이터 자체에 이미 잘못 배치된 구조물이 있을 경우 이 수정이 자동으로 이동시키지는 않는다.
