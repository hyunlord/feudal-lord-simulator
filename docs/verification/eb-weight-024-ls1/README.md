DGX 실행 `engineB-weight024-LS1-ae3f01a`, 도구 `ae3f01ac79d7c1b477bddeb8cfaf7974deebf36c`, clean 공식 실험 슬롯 2, **종료 0·valid=true·오류 0**. 준비 4.8초, 대기 2.0초, 명령 263.9초. 정상 UI 10배속 경로를 브라우저 시계로 통제한 1,370회 관측이며 벽시계 성능 수치가 아니다. 305059→307251 동안 봇 답변·실질 결정 건너뛰기·직접 엔진 tick 호출이 없었다.

자동 표시 판정은 **이미 있던 연간 칩의 2→3 갱신**이다. 카드가 자동으로 열린 것은 아니며(`automaticCardOpen=false`), 카드 확인은 수동 행동으로 따로 기록했다. 1280×800 [자동 칩](evidence/automatic-chip.jpg)과 [수동 카드](evidence/manual-card.jpg)를 두 검토자가 독립적으로 펼쳐 보았고, 해당 문구의 잘림·가림 없이 읽힘을 확인했다. 27d 전체가 이 선택으로 추가된 수입이라는 주장은 아니며, 다른 해상도나 다른 선택지까지 확대하지 않는다.

[원자료](evidence/live024.json.gz)에 최초 상태·행별 변화·정확한 원인·실제 입력·모든 화면과 상태 SHA를 보존했다. JSON은 원문 바이트 그대로 gzip, JPEG는 DGX 원본 그대로이며 상태 파일 세 개와 원본 여섯 화면을 모두 저장소 안에 뒀다. `SHA256SUMS`로 복원 및 보존 파일을 검사한다. Mac은 문법·해시·압축 검증만, 게임·브라우저는 DGX에서 실행했다.

제품 기준은 `0eddc146c7d57b4cae091bff62295a1fc16e1f97`(v55)이다. [정지 상태의 현재 칩·카드 확인](../eb-weight-ls1/README.md)과 역사 실행 `engineB-live-024-f57723c`(제품 c5d2b35, 수동 왕복 성공·자동 표시 실패)는 별개로 보존한다. v56 통합 결과나 전체 56사건 가시성 판정으로 사용하지 않는다.

진행 계약:

1. 원본 `engineB-weight125-kept-clean-2485af4` seed 1의 manifest SHA `e4615d5a01c18d7b6adba9f3eec12c570f0ab14041266e947305674c04e2b93d`, 024/lower 답 저장 SHA `84c61a1e778654cf9812fe10dbcb6e461f26b184947e58387b6ee93dc1c8fd40`를 고정한다. 답은 `h-019919`, 시작은 305059이다. 현재 공식 codec을 거친 표시 상태가 원본과 일치해야 한다.
2. DGX 공식 실험 슬롯에서 B 실행 하나만 돌린다. 정상 UI 10배속 경로를 브라우저 시계로 통제해 최대 3000틱을 관측한다. 실제 벽시계·성능 측정은 아니다. 봇 답변·직접 엔진 tick 호출·원인이나 상태 추가는 금지한다. 정보성 철 결산 Continue만 상태와 시간 불변을 검증해 누르며 실질 결정이 필요하면 중단한다.
3. 시작 뒤 새로 발생한 결과의 정확한 `because.decisionId=h-019919`와 현재 `yearResults`의 답 멤버십을 대조한다. 같은 관측 시점의 가려지지 않은 실제 `results:<year>` 칩을 확인한다. 결과 전에 있던 칩만으로 통과시키지 않는다. 화면 기본 지연을 유지한다.
4. 자동 포착 이후 일시정지하고 실제 결과 카드에서 해당 답의 문구를 대조한다. 수동 열기와 자동 노출은 구분하고, 탐색 중 상태 SHA는 같아야 한다. 실패도 실행 종료 코드·원자료·화면과 함께 보존하고 렌더 영역은 고치지 않는다.

원칙: P-C3의 정확한 원인 연결, A5의 원본·실패 보존, A4의 실제 화면 노출. Mac은 도구 문법과 압축/해시 확인만 담당하며 게임 및 브라우저는 DGX에서 실행한다.

실행 로그는 원래 공백까지 보존하는 `run.txt.gz`로 묶었다. `log-archives.json`에 원문 크기·SHA와 압축 SHA를 함께 기록했다.
