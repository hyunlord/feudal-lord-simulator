# Engine B → 엔진: EB-FREQ 조건 사실의 정상 영주 경로

기준 소스 `a5776a8e0f18dc5d1f989cdf0a3f037460b40825`. 기존 역사40의 조건34를 정본·바인딩·맥락·실제 사실 생산 경로로 대조하는 후속 요청이다. 정본 조건을 넓히거나 준비 상태를 자연 발생으로 세지 않는다. 이 요청을 기대 결과표·측정 도구 게시의 선행 조건으로 삼지 않는다.

## 048: 정상 영주 경로의 실제 목초지

- **필요한 사실:** 홈 영지의 기한 안 `common_pasture` 청원이 열려 있고, 실제 `pasture` 구역에 유효하고 정렬된 지도 셀 membership이 있어야 한다. 공동체·상인 당사자도 실제 세력이어야 한다. `src/engine/registryPasturePetitionContext.ts:8–27`은 그 구역을 읽어 분쟁 위치를 고정하며 관습상 권리를 만들어내지 않는다.
- **관측:** 렌더 자료 `docs/verification/variants/results.json`의 14개 이름 붙은 자연 실행에서 048 변형 노출은 0이다. 영주가 홈 청원을 맡는 `*-keeps` 실행 합계는 원청원 17건·048 변형 0건, 기본 위임 실행은 원청원 0건이다. 준비 `home-048`은 목초지가 없으면 가장 작은 밭을 목초지로 바꿨다고 명시한다. 따라서 준비 화면 성공은 정상 경로의 목초지 생산 증거가 아니다. 실행별 seed·종료 연도는 원자료대로이며 모든 실행을 20년 완료 표본으로 합치지 않는다.
- **범위:** 엔진 전체에 목초지 생산 코드가 없다는 뜻은 아니다. `src/engine/autoplayCloth.ts:63–88`은 천 생산 봇의 목초지 `paint_zone`을 만들며 `src/engine/autoplayActions.ts:66–67`은 구역 명령으로 옮긴다. 이것은 영주 모드 마을의 자율적 생산 경로 증거가 아니다. 사용자 관측인 “마을이 목초지를 두지 않음”과 구분 없이 샌드박스 경로로 충족 처리하지 않는다.
- **원하는 동작:** 정상 영주 플레이에서 마을의 필요·토지 이용 결정이 실제 목초지 구역을 만들고, 그 상태가 홈 공동 목초 청원과 함께 읽혀야 한다. 영주에게 직접 구역 칠하기를 요구하거나 048 조건에서 목초지를 빼지 않는다. 엔진이 소유한 정상 사실 생산 경로와 그 원인·소유권을 제공해 달라.
- **검증 기대:** 준비 상태 변경 없이 정상 영주 실행의 구역 생성 전후 기록, 구역 ID/membership, 열린 홈 청원 ID/기한, 그 청원에서 선택된 048 변형 ID를 같은 실행 ID·소스 해시로 확인한다. 생성 확률·시점을 B가 임의로 정하지 않는다.

## 078: 019 원사건과 봇 정책의 경로 구분

078은 독립 사건 생산자가 아니라 019 제안의 문구 변형이다(`src/content/registry/registryVariantConfig.ts:8–12`, `src/engine/registryVariants.ts:27–51`). 같은 14개 자연 실행에서 019 원제안과 078 변형 노출은 모두 0이다. 반면 준비 `registry-078`은 세 이웃 영지를 직접 감독하고 첫 영지에 현 청지기와 두 후보를 놓았다.

019는 직접 감독·주의력 과부하와 현직을 제외한 상인/농민 두 후보를 요구한다. `src/engine/stewardship.ts:85–105`에는 성향별 실제 후보 생산자가 있다. `src/engine/lordBot.ts:158–165`는 예외 규칙을 정규화하고 직접 감독 영지를 청지기에게 위임하므로, 기본 봇의 무노출을 엔진의 후보 생산 부재로 분류하지 않는다.

**원하는 확인:** 정상 플레이에서 직접 감독을 유지하는 정책 아래 실제 후보·현직·주의력 상태가 정본 조건을 만족하고 019 제안→078 변형으로 이어지는 경로를 보존한다. 기본 봇을 078 노출률에 맞춰 조작하거나 후보 조건을 넓히는 요청이 아니다. 해당 경로가 엔진 정책상 금지되어 있다면 그 정책과 정본의 충돌을 명시해 달라. 원인별 조건34 표의 정책 제한과 실제 생산 누락을 구분한다.

## TRACE-LINK 및 슬롯 순서

답변의 대상·결과 종류·조건·표시 기한·원인 연결 기대는 `docs/design/engine-B-outcomes.json`으로 별도 전달한다. TRACE-LINK는 사용자 지시대로 GROW-BLOCK 두 단계 뒤·MONEY-SINK 앞이다. MOD-SLOT은 MONEY-SINK 뒤 엔진 검토하며, 본선 채택 뒤 B 구현 순서는 135 → 묶음7 → 묶음9다.

원칙: P-M1 실제 사실만 읽기, P-D5 층위 유지, P-C3 실제 원인 연결, A1 영주가 조건을 만드는 플레이 유지. 이 요청서는 엔진·저장·화면 구현 완료나 새로운 자연 발생 관측을 주장하지 않는다.
