# Wave 22 재작업: 오프라인 분산 배치 계약

상태: candidate. 게임 코드를 수정하거나 설치하지 않았다. 이 문서는 확인 그림용 재현 가능한 배치 방식이며 런타임 구현 완료를 의미하지 않는다.

## 원본과 파생값

- 원본: 타입별 여름·가을·겨울 fill a/b 각 256×128, 특징 데칼 a/b/c 각 64×48·96×64·128×96.
- 데칼 피벗: `(width/2, height-8)`. 실제 투명 여백을 제외한 사각형에 4px 간격을 더해 중복을 제한한다.
- 월드 좌표 128 단위 = 논리 타일 1칸. 확인 그림 UV 반복은 256×256 월드 정사각형 = 2×2칸이다. 256×128 원본은 해당 정사각형에 맵핑한 뒤 2:1 투영한다.
- 지면 fill 4×4 비교는 신작과 기존 grass 모두 표시 UV 256×128을 사용한다. 기존 grass 256×256 전체를 세로로 압축하며 자르지 않는다. 동일 반복 밀도 비교이지 실제 엔진의 UV 일치 검증은 아니다.

## 안정적 키와 해시

- seed: `wave22-rework-20260927-preview-158`.
- 확인 그림 seed는 5유형 장면 각각 a/b/c 세 크기를 모두 보여 주도록 고른 고정 예시다. 일반 seed의 모든 작은 영역에 세 변형이 반드시 존재한다는 뜻은 아니다.
- 알고리즘 버전: `scatter-v1`.
- UTF-8 문자열 `seed|version|family|cellX|cellY|tag`에 32비트 FNV-1a 뒤에 Murmur3 fmix32 최종 혼합을 적용한다. 곱셈은 `Math.imul`, 결과는 unsigned 32-bit다.
- fill 선택: 256단위 청크 좌표와 `fill` 태그의 해시 홀짝으로 a/b를 선택한다.
- 데칼 후보: 160단위 월드 격자의 중앙, 각 축에 `jx/jy` 해시로 -48…+48 지터를 더한다.
- `density` 해시의 100 나머지가 82 미만이면 후보가 활성화된다. `variant`의 3 나머지로 a/b/c를 고른다.
- 후보 배열 순서, 생성 호출 순서, 카메라 위치, 프레임 시간, 전역 난수 상태를 사용하지 않는다.

## 겹침과 국소 갱신

- 각 후보의 화면 투영 사각형이 이웃 ±2 셀 후보와 겹치면 `priority` 해시가 더 작은 후보를 우선한다. 동점은 `(cellY, cellX)` 사전순이다.
- 이웃의 최종 선택 결과에 의존하지 않고 원래 활성 후보에만 의존하므로 연쇄 재평가가 생기지 않는다. 보수적인 빈 공간이 남을 수 있다.
- 청크 밖 이웃도 조회해 청크 생성 순서에 따라 경계 배치가 달라지지 않게 한다. 시야 밖은 그리지 않되 선택 판정에서는 생략하지 않는다.
- 확인 그림에는 고정 나무 `(620,660)` 반경 110 월드 단위의 제외 영역이 있다. 게임에서는 실제 배치·통행·기능 충돌 마스크를 입력받아야 하며, 원래 논리 판정을 바꾸지 않아야 한다.
- fill과 데칼은 표현 계층이다. 타입, 구역, 통행 또는 건축 가능 여부를 새로 결정하지 않는다.
- 저장 권고: seed, 알고리즘 버전, 유형 지도 및 사용자가 직접 고정한 예외만 원본으로 저장한다. 파생 데칼 배열은 캐시로 다룬다. 실제 저장 스키마 변경은 별도 코드 작업 범위다.

## 검증

`proofs.cjs`는 같은 셀 목록의 정순·역순 결과 일치, 인접 셀 삽입 후 기존 셀 결과 불변, 선택된 데칼의 투명 여백을 제외한 사각형 비중복을 검사한다. 실행 결과 및 실제 장면 좌표는 `proofs-placement.json`에 기록한다. 실제 게임 렌더·DPR·가림·성능·청크 교체 순간의 이음은 검증하지 않았다.

확인 그림의 지면 다각형 밖은 클리핑한다. 배치 선택 수는 일부 경계 클리핑된 데칼도 포함하며, 전체 형태는 범례에서 별도로 표시한다.
