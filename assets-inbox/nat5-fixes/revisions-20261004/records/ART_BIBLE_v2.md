## 3. 광원·그림자

- 월드 오브젝트의 낮 기본 주광은 **화면 왼쪽 위**, 그늘은 오른쪽 아래. 좌상 면이 더 밝다는 형태 단서가 같은 재료 안에서 유지되어야 한다.

- 사건 삽화는 실내 창·촛불·난로·저녁이라는 서사 광원을 허용한다. 장면 안 인물과 물체의 광원이 일치해야 하며 월드 스프라이트와 같은 좌상광을 기계적으로 강제하지 않는다.
- 초상은 세트 안 얼굴의 부드러운 좌상 주광·명암비를 맞춘다. UI는 평면 기호·가죽/목재 표면 표현을 사용하되 월드의 투사 그림자 규칙과 분리한다.

## 5. 외곽선과 질감

월드 본체는 별도 검정 외곽 스트로크를 사용하지 않는다. 경계는 재료의 어두운 면과 약한 AO로 분리한다. 목표는 줌1에서 연속한 불투명 검은선이1화면px를 넘지 않고, 줌1.4에서 선 두께만 과장되지 않는 것이다. 이음·문틀·목골 구조선과 카툰 외곽선을 구별한다. 어두운 목재 자체를 일괄 밝게 만들지 않는다.

초상·사건은 회화형 가장자리, UI 기호·문장은 작은 화면에서 판독 가능한 선을 허용한다. UI용 선명도를 월드 나무나 흙에 이식하지 않는다. 낮은 줌에서 점무늬로 뭉치는 잎·기와·돌을 픽셀마다 묘사하지 않고 중간 크기의 덩어리로 설계한다. 과도한 샤프닝·흰 테두리·JPEG 링잉·반복 업스케일을 금지한다. 기존 작은 PNG를 검수판에서 크게 띄운 것만으로 '업스케일 결함'이라고 판정하지 않는다.

원본에서 최종 런타임 크기로 **한 번 축소**한다. 필요한 미프는 런타임 파생본으로 따로 만든다. alpha=0 영역 RGB가 화면에 번지지 않는지 짙은 배경·밝은 배경에서 모두 확인한다. 투명 오버레이는 원본 베이스 위에 합성한 상태까지 검수한다. 상태 오버레이의 캔버스·피벗·발 접지·실루엣은 원본과 일치해야 한다.

## 6. 시대·지역 제한

**프로젝트 규약 위반과 역사적 불가능을 별도로 기록한다.** 아래 금지는 기본형의 통일 규칙이다. 가능성이 있다는 역사 출처 하나로 기존 승인을 바꾸지 않는다.

- 1300 일반 주택·오두막 기본형: 외부 굴뚝·벽돌 굴뚝·굴뚝 통(chimney pot)·푸른 반사 유리·쇼윈도·새시창 금지. 무유리 작은 개구부와 나무 덧창. 후기 L3/L4의 수수한 석조 굴뚝1개(굴뚝 통 없음)·작은 납틀창은 기존 AB상 검토 가능한 예외이며 ID·시기·승인 근거가 없으면 적용하지 않는다.
- 초가 또는 작은 불규칙 테라코타 **평기와**. 청회 슬레이트·팬타일·S기와·검정 들보와 순백 패널의 과장된 튜더 장식·일반 주택 벽돌 전면 금지. 교회 납지붕 등 기능성 예외는 별도 명세.
- 곡물 mill은 목조 post mill: buck·중앙 기둥·십자받침·네 날개·꼬리대. 탑풍차·스목풍차·곡물 수차·산업 굴뚝 금지. 물을 쓰는 축융 시설과 곡물 mill을 혼동하지 않는다.
- 작업장에 현대 기계·고무 타이어·공장 굴뚝·금속 표준 컨테이너·규격 사각 건초·전기 조명 금지. 발자국도 현대 운동화 밑창의 규칙적 트레드를 피한다.
- 1300 기본 장면은 무홉 에일. 홉 원료·홉 덩굴을 양조 표식으로 사용하지 않는다. 통·컵만으로 홉 사용을 단정하지 않는다.
- 육각 관 실루엣, 문 위 역병 표식, 근세 능보·대포 총안, 현대 헤어·칼라·달력 표기, 담비의 검정 꼬리무늬는 프로젝트 금지. 기존 승인 초상에 남아 있는 규약 충돌은 예외 목록으로 관리하며 자동 재작업하지 않는다. **L6 백작 가문은 담비 허용 예외**다.
- 옷은 큰 면적의 형광·순 RGB 원색을 피한다. 빨강·파랑이 있다는 사실만으로 시대 오류라 하지 않는다. 문장은 식별 가능한 tincture 색과 금속 대비를 유지한다. 피부색·체형을 신분·도덕성과 연결하지 않는다.

| 지면 fill/strip/decal/module | 논리64×32와 제작128×64 계약을 자산별 명시; 구역형은 지정3×3/5×5 단일 배치 의미 유지 | 경계·반복·알파·시즌; 구역 한 장을 타일 반복으로 재해석 금지 |
| 초상 | 원본 보존; 현재 빌드의256px/96px JPEG 파생본 사용 | 256표정·복식, 실제96식별·노화·밝기; 원본만 보고 통과 금지 |
| 사건 삽화 | 960×540, 글자 없음; 프로젝트 승인 삽화의 회화 질감 | 장소·행동·시점 구별, 카드 크기 판독, 시대 메타데이터 |
| UI 틀·버튼 | 기존9-slice 모서리·inset·상태 ID 보존; 작은 아이콘은 실제CSS크기로 | 주/보조 명도·재질 구분, hover<selected, disabled판독, 확장 시모서리 |

주 버튼의 짙은 oak 바탕, 보조 버튼의 밝은 parchment 바탕을 분명히 나눈다. 탭 hover는 선택 탭보다 덜 밝아야 한다. 비활성은 흐리기만 해서 상태 정보가 사라지지 않도록 테두리·대비를 함께 확인한다. 이 기준을 적었다고 미설치 Wave38 후보가 게임에 적용된 것은 아니다.

PNG/JPEG에 가짜 투명 체크보드·문자·워터마크를 굽지 않는다. 원본/생성 기록은 보존하고 배포 파생본의 불필요한 메타데이터는 기존 빌더 규약으로 처리한다. 확장자·색공간·알파·크기·해시를 검증한다. 전 자산에 한 해상도를 강제하거나 예전 작은 런타임 파일을 단순 확대해 새 원본으로 등록하지 않는다.

## 8. 승인과 다음 검수의 고정 절차

1. 설치 기준 HEAD, ledger SHA, ID·경로·상태(runtime/retired/candidate), 실제 빌드 URL과 파생 관계를 고정한다.
2. 같은 종류·같은 조명/계절의 기존 승인 원본과 나란히 놓는다. 후보를 승인 기준으로 자동 승격하지 않는다.
3. H비율·재료 패치·외곽선·광원·시대 예외를 기록하고 각 파일을 읽을 수 있는 크기로 검토한다. 의심 자산은 원본과 실제 런타임 크기를 함께 본다.
4. 동일 실제 게임 장면을0.5/1.0/1.4로 캡처한다. 상태·중심·DPR을 고정하고 카메라만 바꾼다. 비/눈/실내/초상 UI 등 필요한 별도 상태도 실화면에서 확인한다.
5. 예외는 `assetId / SHA / 용도 / 연대 / 지역 / 예외 내용 / 출처 / 승인 근거`를 남긴다. 승인된 Pool3와 다른 기존 승인물을 일괄 폐기하지 않는다.
6. 다시 그림·코드 보정·참조 없는 옛 파일의 폐기를 분리한다. 폐기는 참조가 없음을 확인한 뒤 별도 변경으로 수행한다. 감사만으로 설치·삭제하지 않는다.

이 기준의 숫자 목표는 이후 실제 가독성 검수로 조정할 수 있지만 변경 이유와 비교 증거를 남긴다. 원본 해상도·파일 개수 검사만 통과한 결과를 게임 일관성 통과로 보고하지 않는다.
