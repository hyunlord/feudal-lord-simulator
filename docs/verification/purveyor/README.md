# 왕실 구매 뒤 창고의 장부 담당자

관문: 진행 중 — 제품 `f012955c`, 원본 5장. 최종 기하·변경 시험·게시 영수증은 전달 ZIP에 기록한다.

I0340 몸체와 I0321–I0324 장부 네 방향을 공용 `walker-body` / `walker-held-prop` 계약에 넣었다. 실제 금전 원장에 Crown의 양수 `cash/purveyance`가 있고 해당 창고가 남아 있을 때, 영수증 뒤 250 saved ticks 동안 가까운 연결 도로에 담당자 한 명을 그린다. 이는 화면 연출의 수명이며 역사적 체류 시간이나 새 엔진 인물이 아니다. 일반 상인 풀·재고·경제·저장 형식은 바꾸지 않았다.

같은 건물은 최신 영수증 하나만 표시한다. 미래·만료·음수·다른 계정·왕실 출처 없음·창고 철거·도로 없음은 표시하지 않는다. `buildingRoadAccessTiles`와 벽을 고려한 `shortestExistingRoadPath`, 기존 도로 정렬 및 보행자 깊이 정렬을 사용한다. 건물·공사 발판, 물, 광장 고정점, 기존 인물과 겹치는 후보는 제외한다. 이미지가 아직 준비되지 않았으면 몸체만 대체 표시하지 않는다.

원본 8프레임의 발과 장부 손 좌표를 유지했다. 일반 P1 상인의 손 좌표는 원본과 달라 재사용하지 않았다. 새 선택 정보가 있는 프레임만 몸체→장부→원본 손3×3 순서로 그린다. 등록 높이68px를 성인17.6world px로 표시한다. 자연 장면은 정지 자세(gait0)이며, 4방향·두 자세 그림은 합성기 진단이다. 자연 이동이나 여덟 방향의 자연 발생을 주장하지 않는다.

## 실제 화면과 실행

- 자연 원본: `docs/qa/round02/repro/saves/chapter2-war1340.json.gz`, 1340년 봄, tick160183. 원본 `ledger-002062`는 tick160000의 양수2, 창고 `construction-site-000024` (48,42). 새 거래를 만들지 않았다.

- 정상 봄 기준: `astra-PURVEYOR-baseline-codec-db41ab9`, 수정 전 HEAD db41ab97. 최초 구현 관찰: `astra-PURVEYOR-after-first-e66d130`, dirty 제품. e66d1303만으로 구현을 재현할 수 있다는 뜻이 아니다. 최종 제품 커밋 장면을 별도로 남긴다.

## 검증과 한계

Mac 집중 회귀50개·크기 가드·캐시 회귀·typecheck·바뀐 렌더 lint를 통과했다. 큰 마당의 소품 예약을 사람 발판에 그대로 적용하지 않았다. 서로 다른 저장에서 같은 위치가 항상 보이거나 장식 전부와 무조건 겹치지 않는다는 주장은 하지 않는다. 점유한 도로 후보는 제외하므로 인물이 움직이면 후보가 달라질 수 있다.

장부 기존5행의 `installed_by`만 헤더로 찾아 제자리 갱신했다. CSV 전체 재직렬화를 하지 않았고 CRLF·행수·순서와 다른 셀의 원래 바이트를 보존했다. 자체 및 root의 독립 바이트 감사 JSON을 함께 둔다.

원칙: A4는 실제 구매 사실을 세계의 짧은 흔적으로 연결했다. A5는 영수증 id를 연출 id로 사용했다. A7은 확정 원본과 그 손 연결 자료를 보존했다. P-X1은 같은 저장에서 같은 영수증·도로 후보·프레임을 고르는 회귀로 확인했다. 코어 팩 계약으로 설치하고 엔진·화면 문구·저장 형식을 건드리지 않았다.

최종 여섯 쌍은 저장·읽기 상태·tick·타일·줌·시계·카메라가 모두 같고 오류0이다. 여름·겨울도 줌1의 새 인물 영역10×18px, 줌.6의6×11px 밖에는 PNG 차이가 없었다(`pairs.json`). 저장 원본의24명은 그대로이며 기존 주민 표현층이 여름15명·겨울18명을 추가해 읽기 상태 SHA가 정본 저장 SHA와 다르다. 전후 각 쌍의 읽기 상태는 완전히 같다.

저장소 JPG는 같은1280×800 크기에서 quality65로 재압축한 열람본이다. 원본 PNG/JPEG와 전체 상태·하네스는 전달 ZIP에 보존한다. `image-derivatives.json`의 양쪽 해시로 구분한다. 최종 장면은 `f012955c`의 제품 tree가 clean임을 실행 안에서 확인했다. 앞선 dirty 관찰을 제품 HEAD 단독 증거로 쓰지 않았다.
