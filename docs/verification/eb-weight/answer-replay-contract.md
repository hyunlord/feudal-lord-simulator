# 실제 답변 무게 재현 계약

`scripts/engineBAnswerEvidence.ts`는 실제 reducer 호출 직전/직후 상태에서 답변 기록과 분류 입력을 복제한다. 합쳐진 기존 root의 무게를 뒤의 답변에 빌려 쓰지 않는다. 영지 청원은 실제 답변 뒤 escalation을, 장 청원은 실제 직전 상태를 보존한다. 가상 명령을 실행하는 장 청원 무게 판정은 모든 상태 동등성 검증이 끝난 뒤 오프라인으로 한다. 중복 ordinal·history ID와 누락 동적 입력은 미해결로 남긴다.

`scripts/engineBAnswerReplay.ts`의 대상은 새 표본이 아니라 원본2485af4 seed1/2/3의 동일 궤적이다. DGX Linux·Node24.21.0·정확한 원본 HEAD·lock SHA·원본 JSON·저장 manifest·등록 답변 목록의 해시를 확인한다. 원본 체크포인트의 최초 적격 관측 조건, 명령 묶음 순서, no-op 포함 관측 주기를 유지한다. 각 저장의 전체 상태 SHA와 최종500000 상태, 기존 수집기8필드, 후보 수집기, 변경 명령 수, 실제 등록 답변 목록이 같아야 통과한다. 같은 영수증이 여러 결정 쌍에 연결돼도 entry/phase/history 복합 키로 구분한다.

seed1은 실제 청지기 사건058·034·144·163의 계절 닫힘 직전 저장도 남긴다. 모든 원본 동등성 검증을 통과한 뒤에만 화면 사용 가능으로 바꾼다. 이 저장에서 계절 화면을 확인할 때는 저장 당시 명령 묶음을 반복하지 않고 정상 advanceTick부터 진행한다.

## 검증 상태

- 수집기7·재현기9 제한 시험, 기존 답변/보고서11시험 합계27 통과. 타입 검사와 변경4파일 lint 통과.
- 독립 소스 검토에서 차단 결함 없음. 원본 관측 단계·공유 영수증·경계12000·중복 답변·변조·누락 목록을 제한 시험으로 점검했다.
- 셸 실행 계획은 성공 validity 형식과 정리 시 원래 종료 코드 보존을 수정했고, 원본3개의 등록 답변 sidecar45/75/78 및 해시를 재계산했다. 재현 엔진 트리에 복사하는 도구는 두 TS 파일뿐이다.
- **실제 DGX 재현은 아직 실행 전이다.** 기존 가드레일 실험 종료 후 한 실험에서 seed1→2→3으로만 진행한다. 원본과 같은 경로라는 주장은 실제 결과 전까지 하지 않는다.

`valid=true`는 정해진 원본 동등성/분류 검증을 뜻한다. 기존 trace 분류 밖의 history 명령은 `unclassified`로 보존하며, 이를 가벼운 답변이나 전체 history 분류 완료로 세지 않는다. 보고서는 제외·미해결·분류 밖 수와 경계를 명시해야 한다. 소식 전환, 전체 화면 완료, P-T1 통과를 자동으로 뜻하지 않는다.

코어 틱·저장·GameState·렌더·공용 관문·정본 조건은 변경하지 않았다. 공식 변경시험은 기존 체크포인트 시험의 source-scan 분류 문제로 실패 상태이며 REMOTE 검토 요청을 유지한다.

## 검증된 결과의 오프라인 집계

`scripts/engineBAnswerReplayReport.mjs`는 seed1/2/3의 실제 manifest/validity 바이트를 받아 SHA와 검증 선언을 대조한 뒤125년씩375 seed-years를 합친다. 명령 답변 자신의 tick을 사용하며 전체·등록기·이전B11을 분리한다. 중복·미해결·미검증 입력은 거부하고, 분류 밖 명령과 제외 사유는 별도 수로 보존한다. CLI는 기존 출력이나 원본을 덮어쓰지 않는다.

8개 제한 시험과 lint, 독립 검토가 통과했다. 검토에서 발견한 final 체크포인트 위치 오류를 실제 재현기의 `manifest.final` 형식에 맞춰 수정했다. 이 집계기는 기록된 재현 검증을 읽는 도구이며 상태를 재실행하거나 맥락을 다시 분류하지 않는다. 실제3seed재현 결과는 아직 없으므로 새 실측 수치를 생성하지 않았다.
