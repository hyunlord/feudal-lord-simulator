# 절단·접합 기록

## 원본과 변환

`records/assemble.py`가 픽셀 제작의 전부다. 외부 이미지, 생성 모델, 새 돌·말뚝을 그리는 브러시를 사용하지 않았다.

1. `stone_face_rubble_a-v2.png` 또는 `palisade_face_a-v2.png`의 512×128 띠를 읽는다.
2. `stone_top_a-v1.png` 또는 `palisade_top-v1.png`의 512×48 띠를 별도로 읽는다.
3. 게임과 같은 X/Y 32/16 투영, 벽면 높이 20, 윗면 높이 27.5→20, 두께 석벽 0.30·목책 0.16타일을 쓴다.
4. 두 팔의 안·바깥 윤곽을 마이터로 맞춘다. 텍스처는 직선 띠의 아핀 변환을 유지한 채 윤곽에서 자른다. 모서리에 맞춘다고 돌과 흉벽을 삼각형으로 늘이지 않는다.
5. 한 타일당 원본 U 205px. 석벽 접합 U=224로 32px 흉벽 주기의 틈에서 접합하고, 목책은 U=205를 쓴다. 석벽 범위는 19→224→429, 목책은 0→205→410이다. 실제 마이터 폭만큼 샘플 범위가 양옆으로 조금 확장된다.
6. Y축 면에는 원래 렌더러와 같은 22% 잉크색 `(42,33,24)` 음영을 준다. 팔레트 재색칠은 하지 않는다.
7. 동·서 접합의 윗면 공통 높이는 23.75. 그 아래의 작은 삼각 틈에는 같은 벽면 띠를 반복해서 받친다. 넓은 단색 기둥이나 새 캡은 만들지 않는다.
8. 목책에는 같은 목재 벽면 띠를 높이 23.75의 뒤쪽 면으로도 잘라 넣는다. 원본 상단의 두 번째 줄 아래로 지면이 훤히 비던 틈을 받치며, 새 단색 면은 그리지 않는다. 앞면보다 먼저 그려 앞 말뚝과 가로대를 보존한다.
9. 바깥 끝 24~36.8 월드 픽셀 구간을 알파로 점감한다. 본체와 흉벽은 동일 원본 픽셀이다.

## 겨울

`dry_stone_wall_winter.png`의 사각형 `(0,25,512,36)`에서 밝고 중성인 눈 픽셀만 선택한다(B>130, B>0.90R). 83px마다 13px 구간만 남겨 짧고 불규칙한 적설 조각으로 쓴다. 원본 윗면 알파 안에만 붙인다. 석벽 y=23, 목책 y=12. 새 눈을 그리거나 벽면·가로대를 바꾸지 않는다. 긴 흰 선 때문에 코너만 드러났던 초기안은 폐기했다.

## 캔버스와 좌표

1024×768 RGBA, 피벗 `(512,544)`, 월드 그리기 크기 128×96, 배율 1/8. 줌 1.4 캡처에서 약 179.2×134.4 화면 픽셀이다. 피벗은 타일 모서리의 `tileToScreen` 위치에서 y−16 한 벽체 지면점이다. 화면에 놓을 때 x−64, y−68 월드 좌표에서 그린다. 512px 중간본의 이중 축소가 질감을 흐리게 했으므로 최종본은 8배 제작 해상도를 사용한다.

## 재현

제작 환경은 Python 3, Pillow, numpy, 프로젝트의 Node/tsx/Vite와 설치된 Playwright·Chrome이다. 추가 프로젝트 의존성은 넣지 않았다. `assemble.py` 실행은 후보 및 기본 manifest를 다시 만들므로 검수 뒤에는 비교용 폴더에서 실행한다. `capture-runtime.mjs`와 `capture-native-runtime.mjs`는 자기 클론에서 Vite 4319를 띄운 뒤 실행한다. Playwright 위치는 해당 Mac의 절대 경로로 기록되어 있다.

캡처 스크립트는 저장소 안 `scripts/renderCommitProbe.mjs`와 save codec을 사용하므로 ZIP만 단독으로 실행되는 게임은 아니다. 메모리 응답 변경은 target node 교체, 0.65타일 띠 비우기, 해당 연결 체인의 기존 body 단면 생략뿐이다. 파일에 적용하는 패치나 설치 스크립트는 제공하지 않는다.
