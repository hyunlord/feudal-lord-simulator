## 경계와 요청

새 효과 구현은 엔진 B의 몫이다. 저장 형식 이행·코어 틱은 엔진 세션의 몫이다. 공식 버전 있는 모듈 저장 슬롯과 필요한 사실 생산/전이 갈고리가 정해지면 B가 모듈 상태·명령·읽기·시험을 구현한다. 선택 명령이 이미 있어도 전제 사실을 지어내거나 일반 소송을 다른 분쟁으로 가장하지 않는다. RegistryOccurrence는 400개 제시 기록이므로 영속 계약 저장소로 쓰지 않는다.

## 변주와 편집 차단

`docs/design/registry.md:72`의 `registryVariantFor`를 이번 작업 가지에 구현했다. 067→031/059, 078→019의 원래 기한·선택·효과·저장된 대상은 유지하고 제목과 본문만 반환한다. 6개 경계 시험을 통과했으며 새 발생 수로 세지 않는다. 렌더 소비 경로는 인계 사항이다. 001·023·026·044·048·054·056의 전제 사실은 API만 생겨도 자동 충족되지 않는다.

- 070·089·096: `history_window` 사료/집필 창 불일치.
- 181·182·183·185·187: `later_practice`, 1215 규범을 후대 실제 관행으로 적용하는 검토.
- 166: 급류 사실과 함께 사료 시기 적용도 미확인.
- 195: `source_date` 편년/사건 맥락 검토. 묶음 7 요청에 포함.

위 편집 차단은 모듈 구현으로 자동 해제하지 않고 Astra 콘텐츠 확인 대상으로 남긴다.
